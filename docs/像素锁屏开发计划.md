# 像素锁屏开发计划

## 目标与边界

像素锁屏通过独立 LSPosed APK 注入 `com.android.systemui`，使用现有 Pixel Engine 绘制视觉层。
系统 Keyguard 继续负责 PIN、密码、图案、指纹、人脸、SIM PIN、工作资料、紧急呼叫和设备管理
策略。项目不替换认证结果、不读取或保存锁屏凭据，也不通过 Hook 绕过 Strong Auth。

任何不支持的 ROM、SystemUI 结构或 LSPosed API 都必须保持原生锁屏，不允许尝试模糊注入。

## 模块结构

- `:app`：现有 Launcher APK，不承载 LSPosed 入口。
- `:pixel-engine`：Launcher、Showcase 和锁屏共同使用的通用像素渲染引擎。
- `:lockscreen-module`：独立安装和禁用的轻量锁屏 APK，只允许作用于 SystemUI。
- `:pixel-design`：后续新增的产品视觉库，承载共享主题、字体、图标和视觉规范。

`pixel-design` 不能并入通用引擎；它应由 Launcher 和锁屏共同依赖。提取视觉库属于独立重构，
不与 SystemUI Hook 或锁屏功能混合提交。

## 开发阶段

### M0：目标设备侦察

1. 记录 Android API、完整 Build Fingerprint、厂商、ROM 与 SystemUI APK 路径。
2. 确认 LSPosed 发行分支、版本和支持的 Xposed API。
3. 拉取目标 SystemUI APK 及相关 split，分析 Keyguard 使用传统 View 还是 Scene/Compose。
4. 确认 Keyguard 根视图、Bouncer 显隐接口、通知隐私过滤器和 AOD/Doze 路径。
5. 形成以完整 Fingerprint 为键的兼容性记录；没有记录时 Hook 必须关闭。

退出条件：确定唯一注入边界、模块 API 和设备恢复路径后，才能注册第一个 LSPosed Hook。

### M1：安全模块脚手架

1. 创建无 Activity、无服务、无 Hook 入口的独立 APK。
2. 只依赖 `pixel-engine`，不引入 Launcher 业务依赖。
3. 默认关闭 Hook，并用单元测试锁定唯一允许的 `com.android.systemui` 作用域。
4. 验证 Debug/Release APK 均能独立构建。

退出条件：模块构建、测试和 Lint 通过，安装后不会改变任何系统行为。

### M2：共享视觉层

1. 新建 `pixel-design` Android Library。
2. 从 Launcher 提取主题目录、字体包加载、共享图标和必要排版规则。
3. Launcher 行为和视觉保持不变，API 与资源归属测试通过。
4. 在 Showcase 增加锁屏静态预览，先离线验收布局。

退出条件：Launcher 和锁屏预览消费同一份主题、字体与图标，不存在复制色值或字体资产。

### M3：锁屏静态 Host

1. 新建轻量 `LockscreenRootHost`，直接持有 `PixelHostView`。
2. 首版只显示时钟、日期、电量、充电状态和解锁提示。
3. 不创建输入法桥，不接管系统通知、媒体、快捷入口或认证输入。
4. 静止状态只在分钟、电量和配置变化时重绘，不运行连续特效。

退出条件：Showcase/测试宿主中的布局、Insets、横竖屏和字体降级策略通过验收。

### M4：单设备 SystemUI 注入试点

1. 只支持 M0 确认的一个 Build Fingerprint。
2. 使用对应的 Legacy View 或 Scene 适配器挂载 Pixel Host。
3. 原生 Keyguard 视觉层保留在下方；首帧或生命周期异常时立即移除像素层。
4. Bouncer、指纹动画、紧急呼叫和通知区域保持原生。
5. 提供模块开关、启动失败自动关闭和 ADB/Magisk 恢复说明。

退出条件：反复亮灭屏、重启、首次解锁、指纹失败、密码回退与 SystemUI 重启均不会黑屏。

### M5：解锁转场与状态同步

1. 上滑或点击解锁只调用目标 SystemUI 的现有 Bouncer/Scene 转场。
2. Bouncer 显示时隐藏 Pixel Host，认证完成后随 Keyguard 一起退出。
3. 支持指纹、人脸、受信任状态、强认证超时和用户切换。
4. 为快速亮灭屏、旋转、配置变化和 SystemUI 进程重建补充状态机测试。

### M6：媒体与通知

1. 先接入 SystemUI 已解析的媒体状态，不自行扫描其他应用。
2. 通知必须复用 SystemUI 的可见性、用户、工作资料、私密内容和 OTP 脱敏判断。
3. 点击通知和媒体操作仍走 SystemUI 原有 PendingIntent 与解锁流程。
4. 任一隐私策略无法可靠解析时，回退到原生通知区域。

### M7：AOD 与扩展适配

1. AOD/Doze 单独建模，默认使用静态低亮像素并限制刷新频率。
2. 验证 OLED 烧屏规避、功耗、口袋模式、抬腕唤醒和息屏指纹。
3. 每增加一个 ROM 或 OTA，只新增独立适配器和 Fingerprint 记录。

## 安全与恢复门禁

- Hook 回调不得向 SystemUI 抛出异常。
- 不修改 Keyguard 安全判定、凭据校验、加密密钥或认证成功结果。
- 原生锁屏必须始终可恢复，未知环境默认不注入。
- 模块必须只声明 `com.android.systemui` 静态作用域。
- 发布前记录关闭模块、Magisk 安全模式和 ADB 恢复步骤。
- SystemUI 连续启动失败时必须自动停用视觉层，不能无限崩溃重启。

## 验证职责

Agent 负责静态审查、单元测试、模块构建、Lint、API 门禁和恢复逻辑检查。用户负责安装模块、
启用 LSPosed 作用域以及真机亮灭屏、认证、AOD、通知隐私和视觉验收。
