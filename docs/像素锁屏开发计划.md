# 像素锁屏开发计划

## 当前阶段结论

像素锁屏的设备无关阶段 M1–M3 已完成。当前仓库已经具备共享产品主题、静态锁屏 UI、透明
Android 宿主和 Showcase 离线预览，但不会向系统锁屏注入任何内容，也不会读取系统时间、电量或
充电状态。

本阶段不依赖任何目标设备信息。之前采集的 Android 12 / MIUI 结构、类名和行为结论全部作废；
后续只能以实际连接的 Android 15 原生系统目标设备重新采集的数据为准。

## 已完成范围

### M1：安全模块脚手架

- `:lockscreen-module` 是可独立构建的 Android Application。
- Manifest 不声明 Activity、Service、Receiver、Provider、Xposed 入口或 LSPosed 静态作用域。
- 模块默认不启用 Hook，安装后不会产生系统行为。
- Debug/Release 构建、单元测试和 Lint 已纳入自动验证。

### M2：共享产品主题

- `:pixel-design` 是 Launcher 与锁屏共同依赖的中立 Android Library。
- 公共主题类型为 `ProductThemeFamily`、`ProductThemeMode`、`ProductThemeBrightness`、
  `ProductPalette` 和 `ProductThemeCatalog`。
- 主题目录包含 MIDNIGHT、CRT、AMBER、GAMEBOY、PAPER、BUBBLEGUM、CITRUS 和 ARCADE
  八个家族，每个家族都有 DAY/NIGHT 变体和稳定 ID。
- 弱化文字、轮廓和警示色统一经过背景对比度修正。
- Launcher 保留原有业务类型、设置值和持久化语义，现有主题结果由共享色板生成。
- 完整产品字体包仍只属于 Launcher；锁屏首版使用 Pixel Engine 内置 5×7 字体和整数倍率，避免
  锁屏 APK 无条件包含约 18 MiB 字体资产。

### M3：静态锁屏宿主

- `:lockscreen-ui` 同时被 `:lockscreen-module` 和 `:showcase` 依赖，锁屏 Widget 树只有一份实现。
- 公共展示状态固定为：

  ```kotlin
  LockscreenUiState(
      timeText,
      dateText,
      batteryPercent,
      isCharging,
      unlockHint,
  )
  ```

- `batteryPercent` 只接受 `0..100`；时间、日期和提示均由外部格式化。
- `LockscreenRootHost` 直接持有唯一 `PixelHostView`，只公开状态更新和资源释放能力。
- 宿主背景、边框底色和熄灭像素均透明，不抢焦点、不消费触摸、不访问系统服务、不创建定时器。
- 完全相同的状态、主题和方向不会重复提交 Widget 树。
- 纵屏时间使用 4 倍像素字体，横屏使用 3 倍；日期和辅助信息使用 1–2 倍字体。
- 主要文字使用四向单逻辑像素反差描边，不增加遮挡壁纸的整块面板。
- 电量图形需要按百分比动态填充，而现有公共系统图标目录没有电池图标，因此当前实现保留在
  `:lockscreen-ui` 内部，没有为锁屏专用状态扩大 Pixel Engine 公共 API。

## Showcase 离线预览

Showcase 首页提供 `LOCKSCREEN` 入口。预览页直接使用真实 `LockscreenRootHost`，不会复制锁屏
Widget 树，也不会启动生命周期定时器。

预览输入和控制范围如下：

- 固定时间 `09:41` 和固定日期，保证重复截图结果稳定。
- 八个共享主题家族。
- DAY 与 NIGHT；当前不提供 AUTO，因为离线页没有系统明暗状态需要解析。
- 10%、50%、92% 三档电量，以及普通/充电状态。
- PORTRAIT 与 LANDSCAPE 两种预览框比例，不要求旋转设备。
- LIGHT、DARK、GRAY 和 CONTRAST 四种背景，用于检查透明度与描边可读性。

## 模块依赖

```text
:app -> :pixel-design -> :pixel-engine
:lockscreen-module -> :lockscreen-ui -> :pixel-design -> :pixel-engine
:showcase -> :lockscreen-ui -> :pixel-design -> :pixel-engine
:showcase -> :pixel-engine
```

`pixel-design` 和 `lockscreen-ui` 是产品内部共享库，不改变 Pixel Engine 仅发布一个 Maven 坐标的
现有策略。

## 自动验证范围

Agent 负责以下设备无关验证：

- 八个主题家族、日夜变体、稳定 ID 唯一性和文字对比度。
- Launcher 主题映射、设置值和持久化值保持不变。
- 0%、1%、50%、100% 以及充电/非充电静态渲染。
- 12/24 小时文本、长日期、横竖屏、最小安全区和固定整数字体倍率不裁切。
- 透明画布四角、文字前景和四向描边均存在。
- 状态去重、无交互语义、触摸透传以及无系统服务/定时器依赖。
- 相关单元测试、Lint、Debug/Release 构建、架构门禁和 Pixel Engine API 门禁。

## 用户视觉验收

当前阶段不需要连接目标设备。用户只需运行 Showcase 并完成以下检查：

1. 从首页进入 `LOCKSCREEN`。
2. 循环八个主题，分别查看 DAY 和 NIGHT，确认时间、日期、电量和底部提示清晰。
3. 依次选择 LIGHT、DARK、GRAY 和 CONTRAST 背景，确认四角仍显示背景，文字边缘存在反差描边。
4. 切换 10%、50%、92% 和 CHARGING，确认电池填充与文字一致。
5. 切换 PORTRAIT/LANDSCAPE，确认大时钟倍率变化且日期、电量和底部提示均不裁切。

Agent 不主动安装应用或操作设备；用户发现视觉问题后反馈具体主题、模式、背景和方向组合即可。

## 已延后工作

以下内容继续暂停，不得在缺少目标设备数据时凭猜测实现：

- Android 15 SystemUI 架构侦察和完整 Build Fingerprint 兼容记录。
- LSPosed/Xposed API、模块入口、静态作用域和任何 SystemUI 类名。
- 系统时间、电量、充电、配置变化和系统明暗的数据适配器。
- 原生锁屏挂载、首帧回退、崩溃保护、恢复路径和进程重建。
- Launcher 与锁屏的跨进程主题同步。
- 完整字体包共享、通知、媒体、认证转场、AOD 和多 ROM 支持。

## 设备阶段恢复条件

只有在 Android 15 原生系统目标设备连接后才恢复设备相关阶段。恢复时首先重新采集 API、完整
Build Fingerprint、SystemUI APK/split、LSPosed 版本和可用 API，再决定挂载方案；未知环境必须
保持原生锁屏，不允许使用旧 Android 12 / MIUI 结论作为兼容依据。
