# 像素 Keyguard 完整替代开发计划

## 最终目标与安全边界

本项目的最终交付不是在原生锁屏上叠加一层时钟，而是在已适配的 Android 15 SystemUI
中完整替代 Keyguard 的可见 UI 和用户交互：

- 普通锁屏的时钟、日期、状态、通知、媒体和快捷操作使用像素 UI。
- 图案、PIN、密码、生物识别状态、失败提示和锁定倒计时使用像素 UI。
- SIM PIN/PUK/ME、MTK AntiTheft 和紧急呼叫使用像素 UI；管理员二次锁屏继续承载 DPC
  提供的外部 Surface，因为模块无法安全推断第三方认证协议或重绘其私有内容。
- 密码存储、凭据校验、Gatekeeper、Weaver、StrongAuth、生物识别采集和设备策略继续由
  Android 系统处理，模块不重新实现、绕过或降级任何安全决策。

因此工程上的准确名称是“完整替代 Keyguard UI”，而不是“替换 Android 安全后端”。

## 已确认的目标设备合同

第一个且当前唯一支持目标是 Unihertz Titan 2 EEA：

| 合同项 | 要求 |
| --- | --- |
| Android API | 35 |
| Build Fingerprint | `Unihertz/Titan_2_EEA/Titan_2:15/AP3A.240905.015.A2/V01.00.10:user/release-keys` |
| SystemUI 包 | `com.android.systemui` |
| SystemUI APK | `/system_ext/priv-app/MtkSystemUI/MtkSystemUI.apk` |
| SystemUI 版本 | versionCode 35 / versionName 15 |
| SystemUI 架构 | 传统 View Keyguard；Scene/Compose 锁屏运行时关闭 |
| 启动挂载点 | `com.android.systemui.keyguard.KeyguardViewConfigurator.start()` |
| 安全模式 | None、Pattern、PIN、Password、SIM PIN/PUK/ME1-4、MTK AntiTheft |

指纹、SDK、包名、进程名或必需类签名任一不匹配时，模块必须保持原生 Keyguard。后续新增
ROM 必须通过新的显式适配器加入，不得放宽为模糊的 Android 版本判断。

## 总体架构

```text
:lockscreen-ui
├── PixelKeyguardScene        普通锁屏和认证场景的唯一 Widget 树
├── PixelCredentialInput      只保留当次输入的 PIN/密码/图案视图状态
└── PixelKeyguardUiState      不包含原始凭据的可渲染状态

:lockscreen-module  （注入 com.android.systemui）
├── PixelLockscreenModule     Modern Xposed API 入口和唯一静态作用域
├── TargetCompatibilityGate  Build Fingerprint 与 SystemUI 签名门禁
├── Titan2SystemUiAdapter     目标 ROM 的 View 定位、挂载、隐藏和恢复
├── KeyguardStateAdapter      时间、电量、主题、通知、媒体和 Insets
├── SystemCredentialBridge   临时 LockscreenCredential 与系统校验调用
├── KeyguardDismissBridge     校验成功后返回原生 dismiss/finish 链路
└── NativeFallbackController  任何错误下原子恢复原生 UI
```

`SystemCredentialBridge` 只在 SystemUI 进程内创建临时 `LockscreenCredential`。凭据不得进入
`LockscreenUiState`、ViewModel、Bundle、SavedState、日志、分析、截图或持久化存储；校验完成、取消
或生命周期结束时必须立即清零。

## 实施里程碑

### M1–M3：设备无关基础（已完成）

- 已创建独立 `:lockscreen-module`、共享 `:pixel-design` 和 `:lockscreen-ui`。
- 已完成八个主题家族、日夜色板、透明静态宿主和 Showcase 离线预览。
- 静态宿主不读取系统状态、不拦截触摸、不包含认证逻辑。

### M4：注入、兼容门禁与回退骨架（已完成）

- 使用 Modern Xposed API 102，静态作用域只允许 `com.android.systemui`。
- 模块加载后首先执行纯读兼容判定，未命中 Titan 2 完整合同时不安装任何 Hook。
- Hook `KeyguardViewConfigurator.start()` 时先执行原方法，再校验必需视图与回调签名。
- 兼容门禁通过后才安装普通页和已适配凭据页 Hook；不支持的构建完全不修改 SystemUI。
- 所有 Hook 使用保护异常模式，模块代码失败不得影响 SystemUI 原逻辑。

### M5：普通 Keyguard 整屏替代（候选包已启用，待真机验收）

- 像素宿主挂到 `KeyguardRootView` 第一子层，自动继承锁屏可见性；原生 Bouncer 保留在窗口更高层级。
- 已接入系统时间、日期、电量、充电和主题明暗，仅使用系统广播驱动，不创建计时线程。
- 像素宿主首次完成 Android 绘制前保留原生 UI；下一帧才通过可恢复事务隐藏普通节点。
- 锁屏不可见、根节点重建、状态更新失败或宿主脱离时恢复原生节点并注销所有广播。
- 当前替代时钟、状态栏、底部区域、设备入口图标和锁屏通知容器；宿主作为原生
  KeyguardRootView 子节点继承系统点亮、熄屏、解锁和旋转转场。

### M6：图案、PIN 和密码认证 UI（候选包已启用，待真机验收）

- 已完成设备无关的凭据安全基础：可覆写字符/图案缓冲、提交即清空的单次 lease、
  Android 15 隐藏 API 精确合同检查、`LockPatternChecker` 结果映射及单任务取消仲裁。
- PIN/密码通过自定义 `CharSequence` 交给系统同步复制，不创建无法主动清零的业务 `String`；
  图案只在固定九格数组与系统 `Cell` 工厂调用期间存在。
- 已按 Titan 2 实际 `KeyguardSecurityContainerController` 签名建立原生结果桥：异步结果到达时
  会再次核对当前用户与安全模式，成功复用 `reportUnlockAttempt` 和 `dismiss`，失败复用系统
  失败次数与擦除策略，限流截止时间由 `LockPatternUtils` 写入；图案与 PIN 会话均已接入该桥。
- 已在 `:lockscreen-ui` 完成设备无关的像素 Pattern 交互宿主：可见内容全部由 Pixel Engine
  绘制，透明 Android 容器只负责二维触摸映射；支持连续拖动、快速采样、跨格补点、去重和
  横竖屏布局，抬起或取消后立即覆写视图路径。
- Showcase 的 `LOCKSCREEN` 离线页已直接接入同一个 Pattern 宿主，可切换 CLOCK/PATTERN、
  四种系统反馈、八套主题、日夜、横竖屏和测试背景；预览监听器会丢弃格子，不执行校验。
- Pattern 宿主已补充像素紧急入口和独立透明无障碍节点；可见按钮仍由 Pixel Engine 绘制，
  点击事件只通过监听器转发，运行时必须绑定 SystemUI 原生紧急流程后才允许隐藏原生页面。
- Titan 2 紧急操作桥只复用当前 `EmergencyButtonController` 已安装的原生点击链，并在挂载、
  启用、可见、监听器和对象身份任一变化时拒绝操作；运行时会把拒绝视为恢复原生页面的条件。
- 图案运行时会话已串联首帧门禁、原生图案根可逆隐藏、普通像素页暂停、系统校验、
  原生结果上报、系统截止时间倒计时和生命周期清零；Titan 2 精确 Hook 已仅对 Pattern 开启。
- PIN 已完成真实像素键盘、只暴露输入长度的状态、系统自动确认长度对齐、可清零协调器、
  Titan 2 控制器绑定、紧急操作、系统校验、首帧门禁、限流倒计时、生命周期 Hook 与原生回退。
- PIN 生命周期 Hook 位于图案已用安全容器 Hook 与 PIN/密码共享父类方法上；共享父类回调按
  最终控制器类型过滤，避免模式串线。图案、PIN 和密码接管开关均已启用。
- Password 保留原生 EditText 作为不可见输入连接，像素层只镜像输入长度、焦点、IME 切换入口
  和系统反馈；不会复制或持久化密码正文。
- 输入 UI 只收集临时凭据，通过系统 `LockPatternChecker`/`LockPatternUtils` 校验。
- 失败次数、超时、锁定截止时间和 StrongAuth 完全使用系统结果，UI 不自行推断。
- 成功后通过 `KeyguardSecurityCallback` 与 `KeyguardViewMediator` 原生链路完成解锁。

### M7：生物识别和安全状态（代码完成，待真机验收）

- 保留 SystemUI 现有指纹/人脸认证与取消流程，不获取原始生物数据。
- 使用像素 UI 表达等待、采集、成功、失败、暂停和必须强凭据解锁状态。
- 验证信任代理、延长解锁、Lockdown、重启后首次解锁和用户切换。
- StrongAuth 在状态组合和渲染两层都高于信任提示，任何矛盾状态都优先要求强凭据。

### M8：特殊安全模式（候选包已启用，待真机验收）

- 为 SIM PIN、SIM PUK、SIM ME1-4 和 MTK AntiTheft 建立独立适配器，不误用设备凭据校验通道。
- SIM/PUK/ME 和 AntiTheft 只转发原生数字、删除、确认和紧急点击，不读取或保存明文。
- 管理员二次锁屏是 DPC 通过 `IKeyguardClient` 提供的外部 SurfaceView，必须原样保留；工作资料
  和多用户继续由当前 SystemUI 安全上下文决定，不由像素层推断。
- 每一种模式只有在成功、失败、超时、取消和进程重建均验证后才禁用对应原生页面。

### M9：通知、媒体、快捷操作与 AOD（代码完成，待真机验收）

- 只读镜像 SystemUI 当前锁屏通知顺序和 `mShowingPublic` 隐私结果，最多显示三条摘要；点击通过
  同帧原生通知行执行，分组、清理和复杂展开继续由通知进入后的系统界面负责。
- 镜像当前媒体标题、艺术家和播放状态，播放/暂停通过 MediaViewHolder 原生按钮执行。
- 镜像 `start_button` / `end_button` 当前无障碍名称，快捷操作完全复用原生 View 点击链，不
  自行启动相机、手电筒或其他 Intent。
- 使用公开 `PowerManager.isInteractive` 切换 AOD；AOD 只显示时间、日期和电量，并由系统分钟
  广播产生有界防烧屏位移，不创建模块定时器或唤醒设备。
- 普通页和凭据页均挂在原生转场父容器内，继承点亮、熄屏、旋转和认证转场；首帧前始终保留
  原生 UI，任何运行时错误均恢复原生属性。

### M10：目标设备验收与稳定候选（进行中）

- 对目标 Fingerprint 执行完整的模式矩阵、冷启动、崩溃恢复、锁定和重启测试。
- 所有已适配可达安全模式的候选开关已启用；只有像素首帧和精确运行时合同有效时才隐藏对应
  原生 Keyguard/Bouncer，管理员外部安全页始终例外。
- 紧急回退仍保留：未匹配构建、必需签名变化或模块内部失败时，不做任何 UI 接管。

## 安全不变式

1. 先证明像素 UI 可用，后隐藏原生 UI；禁止反过来执行。
2. 原生视图只改变可恢复属性，不从 SystemUI 树中永久删除。
3. 任何反射、Hook、渲染、认证或状态适配异常都先恢复原生 UI，再记录不含凭据的诊断。
4. 不提供跳过凭据、伪造生物识别成功、重置失败次数或绕过管理策略的开关。
5. 一次只接受一个凭据校验任务；新输入、锁屏隐藏、用户切换和进程重建均取消旧任务并清零数据。
6. 安全时间、失败次数、当前用户、认证模式和 dismiss 条件以 SystemUI/系统服务为唯一真值源。

## Titan 2 候选包验收矩阵

用户在最终候选安装后按以下顺序一次性验收；任一页面出现空白、无法操作或 SystemUI 重启时，
先停用模块并记录发生前的模式，不重复输入真实凭据到日志或截图：

1. 重启后确认普通锁屏、透明壁纸、时间、日期、电量、通知隐私、媒体和左右快捷操作均为像素 UI。
2. 分别验证日间、夜间、横竖屏、充电、亮屏、熄屏和 AOD；AOD 不应显示通知、快捷操作或解锁提示。
3. 验证通知点击、媒体播放/暂停和两个系统快捷槽位仍走原生操作结果，空白区域上滑仍可进入认证页。
4. 验证指纹/人脸等待、成功、失败、锁定，以及重启后、Lockdown 后必须使用强凭据的提示。
5. 对当前设备实际可用的 Pattern、PIN、Password 分别验证正确、错误、连续失败限流、取消、紧急入口、
   旋转和页面重建；密码额外验证软键盘、硬键盘和输入法切换。
6. 在具备测试条件时验证 SIM PIN/PUK/ME 与 MTK AntiTheft；这些页面必须执行运营商或厂商原生结果，
   不能进入设备凭据校验链。
7. 若设备策略触发管理员二级锁屏，应看到 DPC 原生 Surface；停用模块并重启后必须完整恢复原生锁屏。

## 验证分工

Agent 负责：

- 单元测试、组件测试、Lint、Debug/Release 构建和 APK 内容门禁。
- 反射签名、兼容性矩阵、凭据清零、并发取消、失败限流和回退恢复的自动验证。
- 每个里程碑提供不含凭据的最小日志检查点和清晰的真机验收步骤。

用户负责：

- 安装或更新模块、在 LSPosed/Vector 中启用静态 SystemUI 作用域并重启 SystemUI/设备。
- 真机视觉、触摸、锁定/解锁、指纹/人脸、SIM 与紧急流程验收，并反馈实际日志与现象。

在 M10 完成前，任何单一预览页、单一解锁模式或单次成功解锁都不能作为“完整替代”的
完成证据。
