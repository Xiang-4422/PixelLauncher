# PixelLauncher 设计文档

本文记录 PixelLauncher 的产品与 app 侧设计细节。完整项目事实入口见 [项目总览](项目总览.md)，UI 实现细则见 [PixelLauncher UI 规范](PixelLauncher%20UI规范.md)；pixel-engine 的内部设计与 SDK 用法不在本文展开，分别见 [架构与技术实现](../pixel-engine/docs/架构与技术实现.md) 和 [使用说明与 API 手册](../pixel-engine/docs/使用说明与API手册.md)。

## 1. 产品定位

PixelLauncher 是面向 Android 手机的像素风桌面启动器。它不是传统图标桌面，目标是用统一、克制的像素 UI 呈现必要状态，减少用户为了确认信息而频繁打开 App。

核心原则：

- 信息减法优先于功能堆叠
- Home 负责必须看的状态
- Drawer 负责快速检索并启动 App
- Idle 负责低信息密度待机展示
- Settings 是单页完整设置系统
- 不做图标墙、推荐流、复杂通知中心或系统锁屏替代

当前优先范围：

- Android 手机
- 竖屏
- 优先适配 `1:1` 比例设备
- 中英文基础文本

## 2. 当前实现架构

当前项目不是 Compose，也不是多 Activity / 多 Fragment 架构。主干是：

- 单 `Activity`
- 单一 `LauncherState`
- `LauncherViewModel` 持有唯一状态源
- `LauncherUiState` 作为渲染投影
- `LauncherRootHost` 统一装配 pixel-engine widget 树
- `PixelHostView` 作为唯一像素 UI 宿主

主链路：

1. `MainActivity` 初始化系统仓库、设置、`LauncherViewModel` 和 `LauncherRootHost`
2. `data` 层读取系统服务、权限能力、网络或持久化数据
3. `LauncherStateTransitions` 把输入和数据快照收敛为新的 `LauncherState`
4. `LauncherViewModel` 保存状态，并在渲染时通过 `toLauncherUiState()` 投影 UI 字段
5. `LauncherRootHost.update(...)` 同步主题、字体、屏幕档位、控制器状态和页面模式
6. `LauncherRootHost` 构建页面 widget 树
7. pixel-engine retained runtime 通过 `PixelHostView` 绘制到 Android `Canvas`

主界面渲染入口是 `LauncherRootHost` 与 `PixelHostView`；新页面应沿 pixel-engine widget 链路扩展。

## 3. 模块边界

当前 Gradle 模块：

```text
:app        -> :pixel-engine
:pixel-demo -> :pixel-engine
```

- `:app`：PixelLauncher 主程序，负责产品状态、系统能力接线和页面装配
- `:pixel-engine`：像素 UI SDK，包含 pixelcore、pixelui 和模块 marker
- `:pixel-demo`：SDK 验收宿主，覆盖组件、布局、滚动、输入、动画、导航和压力场景

app 侧代码分层：

- `app`：运行时编排入口，代表文件 `MainActivity.kt`、`SmsController.kt`
- `viewmodel`：保存 `LauncherState`，投影 `LauncherUiState`
- `launcher`：产品状态机、页面模式、列表模型、设置模型和 `LauncherRootHost`
- `ui/screen`：Home、Drawer、Settings、SMS、Diagnostics、Idle 的 widget 页面
- `ui/widget`：状态栏、电池分隔线、设置控件等 Launcher 复用组件
- `ui/theme` / `ui/text`：Launcher 侧主题和字体栅格器适配
- `render`：仅保留屏幕档位、字体度量和轻量动画节拍等原语
- `data`：系统服务、权限、持久化、网络数据源接线
- `system`：启动 App、窗口模式、重力映射等系统行为封装
- `util`：时间文本、标签格式化、节流等轻量工具

### UI 组件边界

`pixel-engine` 只提供可跨应用复用的像素 UI 能力，`:app` 负责把这些能力组合成 PixelLauncher 的产品界面。判断一个 UI 组件归属时，以“是否携带 PixelLauncher 产品语义”为第一标准。

应留在 `:app` 的定制 UI：

- 页面：`HomeScreen`、`DrawerScreen`、`SettingsScreen`、`IdleScreen`、`Sms*Screen`、`DiagnosticsScreen`
- Launcher 复用组件：`LauncherHeader`、`LauncherSearchHeader`、`BatteryDividerWidget`、`SettingsControls`
- 产品主题与文字适配：`LauncherTheme`、`LauncherThemes`、`LauncherTextRasterizers`
- 与产品状态绑定的展示模型：Home 上下文卡、抽屉搜索、短信流程、待机状态、诊断行、权限/数据状态入口

可以进入 `pixel-engine` 的通用能力：

- 基础布局：`Row`、`Column`、`Stack`、`Padding`、`Container`、`SafeArea`、`AspectRatio`
- 基础内容：`Text`、`RichText`、`Image`、`CustomPaint`、图形/路径/形状
- 通用交互：`GestureDetector`、`OutlinedButton`、`Slider`、`TextField`、选择控件、焦点、表单
- 通用容器：`ListView`、`GridView`、`PageView`、`CustomScrollView`、sliver、导航、动画
- 宿主与调试能力：`PixelHostView`、controller、frame stats、inspector、advanced render object 扩展点

禁止进入 `pixel-engine` 的内容：

- `com.purride.pixellauncherv2` 包引用
- Home / Drawer / Settings / Idle / SMS / Diagnostics 等页面语义
- 通话、短信、闹钟、Usage Access、定位、天气、App 启动等系统服务读取
- PixelLauncher 专属颜色 token、文案、设置项、状态机和业务模型

如果一个组件只是“当前 app 用得多”，但名字、参数或默认样式仍然绑定 PixelLauncher，就应继续留在 `:app`。只有当它能用中性命名表达、通过参数配置样式和行为、并能在 `pixel-demo` 作为通用能力演示时，才考虑提升到 `pixel-engine`。

## 4. 页面设计

### Home

定位：必须看信息页，不是启动器大厅。

当前已落地：

- 日期
- 下一次闹钟
- 动态信息行：`CALL / SMS / RAIN`
- 屏幕使用时间和打开次数
- 终端状态文案
- 基础上下文卡片

目标内容：

- 时间、日期、下一次闹钟
- 未接电话、未读短信、未来降雨提醒
- 屏幕使用时间和打开次数
- 上下文堆叠区：格言、媒体、通知摘要、TODO

非目标：

- 最近使用 App
- 快捷启动入口
- 完整通知列表
- 全天气卡片
- 自由拼装小组件

### Drawer

定位：检索工具。

当前已落地：

- 顶部对齐纯文本应用列表
- 状态栏搜索入口
- ASCII 搜索输入代理
- 中文名称、拼音全拼、拼音首字母、英文名称和别名检索
- 字母序加轻量 recent 修正
- 右侧隐藏快速定位区
- 点击应用名直接启动

目标行为：

- 搜索入口处于主路径
- 结果区是纯文本应用列表
- 不显示图标、分类、收藏、最近使用或推荐
- 未输入时保留快速定位能力
- 排序以匹配质量优先，使用频率只做轻量修正

### Idle

定位：待机页，不是第二个 Home，也不是系统锁屏替代。

当前已落地：

- 独立 `LauncherMode.IDLE`
- 空闲超时进入与退出
- 简化待机时钟页

目标状态优先级：

1. 通知态
2. 充电态
3. 媒体态
4. 默认态

默认态显示时间、日期、电量；同一时刻只突出一个主题，避免信息堆叠。

### Settings

定位：单页设置系统。

当前已落地：

- 可滚动单页设置
- 点击直接生效
- 无可见选中高亮
- 外观、抽屉行为、Idle 开关和 Advanced 入口

目标分组：

1. Display
2. Home
3. Drawer
4. Idle
5. Notifications & Data
6. Behavior
7. Advanced

设置改动尽量即时生效；权限、数据源、实验功能和 Diagnostics 不应污染主流程。

### SMS

定位：Launcher 内的全屏短信子流程。

当前已落地：

- SMS 角色申请
- 线程列表
- 会话详情
- 未读收件箱
- 草稿输入与发送

SMS 编排由 `SmsController` 负责，页面由 `ui/screen/Sms*.kt` 提供。

### Diagnostics

定位：Advanced 下的高级信息页，不承担主产品路径。

Diagnostics 可以保留调试信息和工程诊断，但不应重新膨胀成主页面或启动自检体验。

## 5. 数据与权限

当前关键数据源：

- 应用列表：`PackageManagerAppRepository`
- 电池与充电状态：`DeviceStatusRepository`
- 下一次闹钟：`NextAlarmRepository`
- 屏幕使用时间与打开次数：`ScreenUsageRepository`
- 未接来电与未读短信：`CommunicationStatusRepository`
- 定位与降雨提醒：`DeviceLocationRepository`、`RainForecastRepository`
- 外观与交互偏好持久化：`FontSettingsRepository`

优先接入能力：

- 闹钟
- 电话
- 短信
- 通知
- 媒体
- 电池
- 屏幕使用情况
- 定位与降雨提醒
- 格言源

TODO 数据源可先占位。

每个数据能力都必须有：

- 权限缺失态
- 空数据态
- 失败回退态
- Settings 中的状态入口

关键权限：

- `INTERNET`
- `ACCESS_COARSE_LOCATION`
- `ACCESS_FINE_LOCATION`
- `READ_CALL_LOG`
- `READ_SMS`
- `PACKAGE_USAGE_STATS`

Usage Access 不是普通运行时权限，必须跳到系统设置页开启。

## 6. 当前主要差距

- Home 上下文堆叠区、媒体卡、TODO 卡和通知横幅还未完整落地
- Drawer 仍使用系统输入法代理，正式像素输入层未完成
- Idle 还不是完整状态驱动系统，缺充电态、媒体态、通知态
- Settings 还缺完整分组、权限入口和模块级细项设置
- TODO 正式数据源未定

## 7. 开发约束

- 不把主界面改写成 Compose
- 主界面页面只通过 pixel-engine widget 链路实现
- 不把 Android 原生控件树混进像素主界面
- 不绕过 `LauncherState` 直接在 UI 层塞临时状态
- 不把系统服务读取塞进 `ui/screen`
- 新数据能力优先进入 `data`
- 新系统行为优先进入 `system`
- 新状态字段和状态迁移优先进入 `launcher` / `viewmodel`
- 新页面结构优先进入 `ui/screen`
- 可复用 Launcher 组件放进 `ui/widget`
- SDK 级能力先在 `pixel-engine` 实现，并通过 `pixel-demo` 验证后再进入 `:app`
