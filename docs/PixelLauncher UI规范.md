# PixelLauncher UI 规范

日期：2026-06-20

本文用于约束 PixelLauncher 后续 UI 实现和验收。目标不是增加视觉复杂度，而是避免重复出现固定尺寸、文字裁切、列宽压缩、padding 不一致和状态栏处理错误。

设计参考：[Designing for Playdate](https://help.play.date/developer/designing-for-playdate/)。本文只吸收其可转化为 PixelLauncher 的设计规则，不镜像原文，不照搬掌机交互。

## 1. 总原则

- UI 以像素文本为核心，信息密度低但可读性高。
- 低分辨率不等于小；优先保证可读性，而不是把更多内容缩进一屏。
- 不使用传统图标墙、卡片堆叠或复杂装饰。
- 少组件、高一致性；优先打磨 TextButton、ListRow、Switch、Input、Dialog、TwoColumn 等基础组件。
- 不用固定宽高硬凑布局，优先依赖组件自身测量、父级约束和 `Expanded`。
- 新页面必须先保证文本完整显示，再考虑视觉效果。
- 每个新增或重构页面都要真机截图自查。
- selected / pressed / loading 状态不能改变布局尺寸。
- UI 动画和重绘要克制，避免没有意义的持续重建和动画泛滥。
- 主页面横向顺序固定为左侧 `SETTINGS`、中间 `HOME`、右侧 `DRAWER`，默认停留在中间 Home。
- 分页吸附动画允许被新手势接管；动画结束前再次同向滑动必须能继续进入下一页，接管时画面不能跳变。

Playdate 可借鉴但不能照搬的边界：

- 借鉴少色、反色、稳定行高、轻量菜单和真实设备优先的原则。
- 不照搬 1-bit 视觉限制，PixelLauncher 可以保留主题能力。
- 不照搬 crank、掌机按钮或游戏 Launcher card 交互。
- 不使用 Playdate 字体解决中文问题；中文字体、baseline 和 fallback 要独立设计。
- Pixel 风格可以有个性，但不能牺牲 Home、SMS、Drawer、Settings 这些工具流程的效率。

## 2. 文本

文本必须满足：

- 不被边框、父容器或相邻元素裁切。
- 单行文本超长时明确使用省略、换行或滚动，不允许自然溢出。
- 中文、英文、数字混排时必须检查最长真实文案。
- 文本垂直居中不能依赖字体 top bearing 的偶然视觉效果。
- 不用负 letter spacing。

建议：

- 重要信息用短文本，不用长句说明。
- 列表标题只显示标题，摘要只在空间足够的二级区域显示。
- 按钮文字优先使用短词，例如 `SMS`、`BACK`、`SAVE`。
- 文本可读性按真实字体指标判断，包括 `capHeight`、笔画厚度、baseline、ink bounds 和混排效果。
- 所有组件先通过最长中文文案验收，再检查英文和数字。

## 3. 字体尺寸

字体大小和字体风格由 UI 决定，不作为用户设置项暴露。页面通过受控 enum 选择字体尺寸，而不是通过任意数字或用户设置决定。

原则：

- Settings 不能提供 font size 选择。
- Settings 不能提供 `MONO` / `PROP` 这种 fontStyle 选择。
- 页面不能随意指定任意数字字号。
- UI 只能从受控字体尺寸 enum 中选择。
- 字体尺寸 enum 必须由项目统一维护，不能在页面里散落 magic number。

建议字体尺寸：

```kotlin
enum class PixelFontSize(val px: Int) {
    PX_8(8),
    PX_10(10),
    PX_12(12),
}
```

使用建议：

- `PX_8`：短标签、角标、极短状态值。
- `PX_10`：Home、Drawer、Settings 默认正文。
- `PX_12`：菜单、列表重点项、SMS 正文。

后续如果引入 16px 字形包，可以增加 `PX_16(16)`，用于 Idle 大字、页面标题或少量强调信息。生产代码不能暴露没有对应 glyphpack 的尺寸。

验收规则：

- 同一字体尺寸必须有稳定 `cellHeight`、`baseline`、`inkTop`、`inkBottom`。
- 中英文混排按中文最大字形验收。
- UI 组件只依赖字体 metrics，不手写某个字体的高度。

## 4. Padding 与边框

边框内文字必须保留稳定 padding：

- `OutlinedButton` 的文字与边框之间最小 padding 使用 `EdgeInsets.all(2)`。
- `TextButton` 默认 padding 为零，需要扩大点击区域时由调用方显式配置。
- Home、Drawer、Settings 的普通内容统一使用 `LauncherSpacing.CONTENT_HORIZONTAL` 作为页面左右边距。
- 普通无边框行使用自然尺寸，不在页面边距之外重复增加行内 padding。
- 三个主页面的普通行间距统一使用 `LauncherSpacing.ROW_SPACING`。
- 边框不能贴字，不能只在顶部看起来有 1px 空隙。
- 需要紧凑布局时，优先减少外部间距，不减少文字与边框的内部 padding。

Launcher 页面空间常量集中在 `LauncherSpacing`：

| 常量 | 当前值 | 使用场景 |
|---|---:|---|
| `CONTENT_HORIZONTAL` | 2 | 状态栏文字、搜索框以及 Home、Drawer、Settings 正文左右边距 |
| `CONTENT_VERTICAL` | 2 | Home、Drawer、Settings 正文顶部和底部边距 |
| `ROW_SPACING` | 2 | 三个主页面普通同级行之间的间距 |
| `EDGE_ACTION` | 1 | Home 底部 `CALL` / `SMS` 距左右及底部屏幕边缘 |
| `BORDERED_CONTROL_INSET` | 2 | Settings Switch 等自定义有边框控件的文字内距 |

禁止：

- 用 `EdgeInsets.all(1)` 做有边框文字按钮的默认内边距。
- 为了对齐视觉手动计算文字高度。
- 让字体光栅本身的留白承担 padding 职责。

## 5. 尺寸与约束

默认不写固定宽高。

允许固定尺寸的情况：

- 明确的像素图标。
- 明确的分隔线。
- 明确的最小触控区域。
- 经过真机截图验证的特定像素装饰。

其它场景应使用：

- `Row` / `Column` 的自然测量。
- `Expanded` / `Flexible` 分配剩余空间。
- 内容列按 child intrinsic size 占用。
- 可滚动区域承接溢出。

禁止：

- 为文字按钮写死高度。
- 为两栏布局写死左栏宽度。
- 用屏幕宽度比例猜测文本需要空间。
- 用全局 padding 包住整个 App 来处理状态栏或圆角。
- 用桌面预览或模拟器结果替代真机截图判断。

## 6. 两栏与分栏布局

两栏布局规则：

- 左栏按内容自然宽度占用。
- 右栏使用 `Expanded` 吃掉剩余空间。
- 左栏文字必须完整显示，不能被压到只剩边框或半个字。
- 右栏列表项也使用可伸缩宽度，文字居中或按页面语义对齐。
- 两栏之间只保留必要间距，不做装饰性空白。

适用场景：

- Demo 首页分类 + 子项。
- Settings 分组 + 选项。
- App 管理列表 + 编辑区。

## 7. 按钮

文本按钮规则：

- 无特殊需要时不要加边框。
- 有边框时必须保证内部 padding 和垂直居中。
- 首页底部 `CALL` / `SMS` 使用无边框 TextButton，按钮内部零 padding，屏幕边缘间距由 Home 布局负责。
- 按钮状态不能改变布局尺寸。

Settings 的 Display 控件：

- `PIXEL` 使用 pixel-engine `SegmentedControl` 展示类似 Switch 的多值选项，只能从 `ScreenProfileFactory` 提供的离散尺寸中选择；窄屏时每行最多 3 项。
- `GAP` 使用二元 Switch，只显示 `ON / OFF`，状态模型只保存 Boolean。
- `PIXEL` 和 `GAP` 都不使用 Slider，也不保留比例预览状态。

按钮内容：

- 只显示命令本身，不写解释说明。
- 避免长文本放进按钮。
- 不因为 selected / pressed 状态改变文字宽度。

## 8. 列表行

列表行规则：

- 左侧标题必须完整显示或明确省略。
- 只在空间允许时显示摘要。
- 行高由内容和 padding 自然决定，不写死到贴字。
- selected 状态只改变颜色、反色或边框，不改变尺寸。
- loading / disabled 状态不能改变行高或文字位置。
- 长按菜单用于 App 别名和重命名等局部操作。

Drawer 列表：

- 只展示 App。
- 搜索结果优先显示重命名后的标题。
- 别名只影响搜索，不让列表变复杂。
- 非空搜索条件下只剩一个 App 时，直接启动该 App；空搜索不触发自动启动。

SMS 滚动：

- SMS 首页使用固定两页：左页 `UNREAD` 显示所有未读短信，右页 `ALL` 显示全部会话。
- 页签 Tab 固定在底部，和横向 PageView 必须同步，默认进入左侧未读页。
- 底部两个 Tab 必须等宽、文字居中，并使用同一个外边框；选中 Tab 使用纯色填充。
- SMS 首页顶部右上角使用无边框 `READ` 按钮，将当前所有未读短信标记为已读。
- 进入会话详情或切换会话时，消息完成布局后定位到末尾。
- 普通重绘和状态栏动画不得修改未读列表、会话列表或消息详情的滚动位置。
- 新消息到达时仅在用户原本位于末尾时继续跟随；用户正在查看历史消息时保持当前位置。
- 用户开始拖动后，尚未执行的自动定位必须立即取消。

## 9. 状态栏与系统栏

状态栏 padding 只在宿主顶部处理：

- 只给真正的顶部安全区添加 padding。
- 不把状态栏 padding 递归加到整个 UI。
- 页面内部不重复处理状态栏高度。
- 不为了屏幕圆角引入额外全局 padding。

Launcher 替代原生状态栏显示时：

- 状态栏高度应来自 Android 真实 status bar inset。
- 顶部自绘状态栏只占用这段真实高度。
- 内容区从状态栏下方开始布局。
- 左侧时间、右侧页面标识、临时消息和搜索框距离屏幕左右边缘各 2 个 pixel-engine 逻辑像素。
- 状态栏同时作为全局临时消息出口，用于承载页面级临时提示。
- 临时消息出现时，只替换时间、页面标题或搜索框所在的文字行。
- 临时消息独占文字行并单行居中显示，过长时省略；新消息替换前一条消息并重置消失计时。
- 临时消息显示期间，底部电量线和充电动画继续显示。
- 消息出现和消失不得改变状态栏高度或推动页面内容。
- 电量线只填充当前剩余电量对应的水平长度：`51%–100%` 使用绿色，`21%–50%` 使用黄色，`0%–20%` 使用红色。
- 充电时电量段使用对应电量颜色的半透明版本；同色实心像素从最左侧移动到当前电量段末端并循环，不沿屏幕边缘转向。

## 10. 系统菜单与浮层菜单

菜单效果参考 Playdate 的系统菜单：轻量浮层、反色选中、行高稳定、边界清楚、少装饰。

适用场景：

- Drawer 长按 App：重命名、编辑别名。
- Settings 选择项：字体、主题、Idle 超时。
- SMS 消息长按：复制、验证码复制（有验证码时）、重发（发送失败时）、删除。
- Home 状态项点击后的轻量操作。

结构规则：

- 菜单是浮层，不是新页面。
- 菜单项只显示动作标题，不放长说明。
- 当前选中项使用整行反色或高对比填充。
- 菜单边界可以是 1px 线或轻量背景差，不使用厚边框和复杂阴影。
- 菜单行高由文字和 padding 自然决定，不能贴字。
- 行内状态可以放在右侧，例如音量条、当前值、开关状态。
- 行内状态使用像素块、阶梯条或短值，不使用长说明文字。
- 菜单底部可以显示时间、电量等系统信息，但只在菜单语义需要时使用。

交互规则：

- 点击外部关闭。
- Back 关闭菜单。
- 选中菜单项后立即执行或进入下一级轻量菜单。
- selected / pressed 状态不能改变菜单尺寸。
- 菜单宽度按内容和父级约束决定，不能压缩到裁切文字。

视觉规则：

- 少色，优先黑白/反色表达状态。
- 不做闪烁纹理。
- 不做大面积装饰图案、密集抖动或噪声背景。
- 如果有进度条或音量条，使用像素阶梯或块状条，不用平滑渐变。
- 有趣味性的像素元素只能作为状态表达的一部分，不能干扰阅读和操作。

## 11. Settings UI

Settings 要承载：

- 外观设置。
- 数据健康。
- App 别名和重命名。
- Idle 自动进入配置。
- Diagnostics / Advanced。

规则：

- 不提供字体大小选择。
- 不提供 `MONO` / `PROP` 字体风格选择。
- 分组清晰，但不要做多层复杂导航。
- 每个设置项只显示标题和当前值。
- 说明性长文放到详情页或诊断页，不塞进列表行。
- 二元选项使用 switch。
- 多选项优先使用系统菜单；需要并列比较时再用 segmented 控件。

## 12. Idle UI

Idle 是 Launcher 内部待机页，不是系统锁屏替代。

规则：

- 支持充电自动进入。
- 支持无操作 30s 自动进入。
- 自动进入配置放在 Settings。
- 暂时不做防烧屏。
- 文本少、对比清晰、状态明确。
- Idle 可以采用更强的 Playdate 式大字、低信息、少动画风格，但仍然按 Android 触控和状态栏规则实现。

## 13. Home UI

Home 是手机亮屏后的第一印象，只展示当前最重要的信息。

规则：

- 不展示所有功能入口。
- 重要信息优先于装饰。
- 顶部信息顺序固定为日期、常显天气、动态优先级状态。
- 天气不参与动态状态行竞争；无数据和无定位权限时仍保留占位及刷新入口。
- 左下角 `CALL` 和右下角 `SMS` 距离左右及底部屏幕边缘各 1 个 pixel-engine 逻辑像素。
- 状态文本短而明确。
- 底部主要操作保持稳定位置。
- 动态状态更新不能导致整屏跳动。

## 14. 性能与重绘

PixelLauncher 应保持低功耗、低重绘、快速响应。

规则：

- Home、Drawer 搜索、SMS 输入和 Idle 不做无意义的持续动画。
- 只在状态变化时重建必要区域。
- 搜索输入、列表滚动和菜单弹出必须优先保证响应。
- 像素纹理、抖动、进度动画必须有明确功能含义。
- 性能问题以真机表现为准，不只看模拟器。

## 15. 验收清单

新增或修改 UI 后必须检查：

- 真机截图中没有文字裁切。
- 左右栏没有异常压缩。
- 按钮文字和边框之间有稳定 padding。
- selected / pressed / loading 状态不会改变布局尺寸。
- 菜单浮层不会裁切标题或当前值。
- 长中文、长英文、数字混排都能处理。
- 状态栏 padding 只出现一次。
- 横竖屏或不同分辨率下不出现重叠。
- 搜索、滚动、输入、菜单弹出没有明显卡顿。
- 没有无意义的闪烁、噪声背景或高频动画。

## 16. 截图要求

每次涉及 UI 布局修改，至少截图检查：

- Home。
- Drawer。
- Settings。
- SMS 列表和详情。
- Idle。
- 本次新增或修改页面。

如果当前连接真机，应优先用真机截图；没有真机时，再用可运行的本地预览或测试截图替代。
