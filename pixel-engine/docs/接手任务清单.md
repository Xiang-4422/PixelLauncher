## 1. 当前结论

`pixel-engine` 已经过了“能不能跑”的阶段，当前重点是产品化：API 可信、文档准确、性能有门禁、demo 能当 release gate。

当前已具备：

- 单模块 `:pixel-engine`，内部保留 `pixelcore` / `pixelui` / `pixelengine` 包边界。
- Flutter 风格 `Widget -> Element -> RenderObject` 三层模型。
- `PixelHostView` 继承 `android.view.View`，不是 `SurfaceView`。
- `explicitApi = Strict` 已启用。
- `pixel-demo` 已覆盖大量公开 widget 和高级扩展场景。
- `ListViewBuilder(itemExtent != null)` 已有固定高度 lazy 路径；`itemExtent == null` 仍是 eager 兼容路径。
- `PerfBaselineTest` 默认只打印样本，不写 tracked baseline；只有 `REGEN_PERF_BASELINE=1` 时写盘。

当前固定验收命令：

```bash
./gradlew :pixel-engine:testDebugUnitTest :pixel-engine:assembleDebug :pixel-demo:assembleDebug --no-daemon
```

如果改到 lint / public API，再加：

```bash
./gradlew :pixel-engine:lintDebug --no-daemon
```

### 任务 #2：`ListViewSeparatedBuilder` 固定高度 lazy 版本

#### 动机

`ListViewSeparated` 当前是 eager：会一次性构造全部 item 和 separator。长列表使用它会有首屏构建成本风险。

`ListViewBuilder` 已有固定高度 lazy 路径，但只支持同一高度的 item。`ListViewSeparatedBuilder` 应该补齐“item 固定高度 + separator 固定高度”的 lazy 场景。

#### API 草案

```kotlin
public fun ListViewSeparatedBuilder(
    itemCount: Int,
    itemBuilder: (Int) -> Widget,
    separatorBuilder: (Int) -> Widget,
    state: PixelListState,
    controller: PixelListController,
    itemExtent: Int,
    separatorExtent: Int,
    cacheExtent: Int = 1,
    key: Any? = null,
): Widget
```

#### 设计要求

- 保留现有 `ListViewSeparated` eager API，不做破坏性修改。
- `itemExtent` 和 `separatorExtent` 都是必填，避免把变高虚拟化伪装成已完成。
- 内部需要正确计算交错虚拟行：
  - virtual index 偶数：item，真实 index = virtual / 2，高度 = `itemExtent`
  - virtual index 奇数：separator，真实 index = virtual / 2，高度 = `separatorExtent`
- 不能直接复用现有 `RenderLazyListViewport` 的 `itemExtent + spacing` 模型，除非先把它抽象成“按 virtual index 取 extent”的通用模型；否则 item/separator 不同高度会算错 offset。
- `state.itemTopOffsetsPx` 和 `state.itemHeightsPx` 仍应按真实 item 维度同步，保证 `scrollItemIntoView(state, itemIndex)` 定位真实 item，而不是 separator。

#### 文件

- `pixel-engine/src/main/kotlin/com/purride/pixelui/widgets/PixelWidgets.kt`
- `pixel-engine/src/main/kotlin/com/purride/pixelui/internal/widgets/scroll/ListWidgets.kt`
- `pixel-engine/src/main/kotlin/com/purride/pixelui/internal/render/pipeline/renderobjects/viewport/RenderScrollViewport.kt`
- `pixel-engine/src/test/kotlin/com/purride/pixelui/internal/render/pipeline/PipelineElementTreeRendererTest.kt`
- `pixel-engine/docs/组件目录.md`
- `pixel-demo/src/main/kotlin/com/purride/pixeldemo/app/DemoScenes.kt` 的 `PALETTE_GRID` 场景

#### 验收

- 1000 item 初始 render 只调用可见窗口 + cache 范围内的 `itemBuilder` / `separatorBuilder`。
- 点击 target 和 list target 仍被 viewport 裁剪。
- `scrollItemIntoView` 对真实 item index 生效。
- `ListViewSeparated` eager API 行为不变。
- demo `PALETTE_GRID` 改用新 builder。

验证：

```bash
./gradlew :pixel-engine:testDebugUnitTest :pixel-demo:assembleDebug --no-daemon
```

### 任务 #3：性能回归阈值门禁

#### 当前事实

`PerfBaselineTest` 现在只负责采样和打印。默认不写盘，`REGEN_PERF_BASELINE=1` 才覆盖 baseline。这部分已经修正，不要再按旧文档恢复默认写盘。

#### 要做

新增 `PerfRegressionTest`，读取 `src/test/resources/perf-baseline.json`，对关键指标做宽松阈值断言。

#### 设计要求

- 与 `PerfBaselineTest` 共享测量 helper，避免两套测量逻辑漂移。
- 默认永不写盘。
- baseline 文件不存在时 skip，并打印如何生成 baseline。
- JVM 不支持线程分配统计时 skip allocation 相关断言，不要 fail。
- 每项指标建议多轮采样取中位数，降低本机波动。
- 阈值先保守，避免 CI 噪声：
  - allocation：baseline * 1.5
  - render time：baseline * 2.0
  - blit：baseline * 2.0
  - rich text：baseline * 2.0

#### 验收

- 当前 baseline 下通过。
- 故意制造明显回归时失败信息要显示 baseline/current/threshold。
- 不修改 `perf-baseline.json`。

验证：

```bash
./gradlew :pixel-engine:testDebugUnitTest --no-daemon
```

## 4. P1：需要先设计再做

P1 不建议直接开工。每个任务先写 1 页设计文档，说明目标、非目标、API、数据结构、兼容策略、测试计划。

### 任务 #4：变高 item 列表虚拟化

当前 `ListViewBuilder(itemExtent != null)` 是固定高度 lazy；`itemExtent == null` 仍是 eager。变高列表虚拟化仍未完成。

建议方向：

- 新增 `estimatedItemExtent` 作为显式 opt-in，不改变 `itemExtent == null` 的兼容 eager 行为。
- 增加 item 高度测量缓存。
- 对未测 item 使用估算高度。
- `scrollItemIntoView` 支持变高列表定位。
- demo 增加 `VARIABLE_HEIGHT_LIST`。
- perf 增加 1000/5000 item 场景。

不要把该任务和 `ListViewSeparatedBuilder` 混在一个提交里。

### 任务 #5：文本系统 v2

当前文本系统已能支持基础 `Text` / `RichText` / 多行 / ellipsis，但还不是完整 paragraph model。

建议拆阶段：

1. internal paragraph model：统一 `RenderText` / `RenderRichText` 测量、断行、ellipsis。
2. `PixelTextStyle` 扩展：`letterSpacing`、`lineHeight`、受限的整数倍 `fontScale`。
3. TextField selection 可视化与光标节拍。
4. IME composition 显示与提交语义。

每阶段都需要 golden 或 snapshot 回归。

---

### 任务 #6：滚动 / 手势 v2

当前已有基本 fling、bounce 参数、Pager/List 嵌套仲裁，但还不是产品级复杂手势系统。

建议拆阶段：

1. `PixelScrollPhysics` 明确 snap / overscroll / edge handoff 语义。
2. 新增 `NestedScrollSession`，把一次手势的归属状态显式建模。
3. demo 增加 gesture stress 场景：`PageView + ListView + TextField`。

该任务会触碰 `PixelHostView` 手势分发，必须配真机手测。

## 7. 历史决策与注意事项

- 保留 `com.purride.pixelui` 扁平包作为主要用户入口。
- `DefaultTextRasterizer` 通过 inherited widget 注入，宿主切换字体只需 invalidate。
- `PixelListController` / `PixelPagerController` 已显式处理 NaN / Infinity 速度。
- `PerfBaselineTest` 默认不写盘，避免污染 tracked baseline。
- `ListViewBuilder` lazy 必须传 `itemExtent`；不传就是 eager。
- `PixelHostView` 是 Android `View`，不是 `SurfaceView`。
- [接手任务清单](接手任务清单.md) 是维护参考，不是强制执行计划。执行前必须先按当前代码复核。

## 8. 工作建议

1. 每个任务先确认当前代码事实，再改。
2. 每个 P0 任务独立提交。
3. P1 先写设计文档，不要直接开大改。
4. 改公开 API 必须同步 `README` 和 `docs/` 中对应文档。
5. 新增 widget 或公开 API 必须补 demo 和测试。
6. 不要在 `paint()` / hot path 中新增对象分配。
7. 不要从业务 app 反向污染 `pixel-engine`，engine 不应知道 Launcher 业务语义。
