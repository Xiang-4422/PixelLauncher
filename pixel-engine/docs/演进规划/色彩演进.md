# 色彩演进

> 状态：历史决策记录。当前代码已经收敛为单一 ARGB `PixelBuffer` 路径，不再区分 Mono / Color mode。

最后更新：2026-05-25

---

## 当前事实

当前 `pixel-engine` 的颜色模型：

- `PixelColor` 是公开颜色值类型，ARGB 32-bit。
- `PixelBuffer` 内部是 `IntArray`，每个逻辑像素存一个 ARGB 值，`0` 表示透明。
- `PixelHostView.backgroundColor` 控制 Android View 背景 / bezel 色。
- `PixelHostView.pixelGridColor` 控制未绘制逻辑像素的格栅 / panel 色。
- `PixelHostSetupConfig` 不再包含 `palette`、`themeData`、`colorMode`。
- 公开 widget 直接接受颜色参数：`Text(color)`、`Container(fillColor, borderColor)`、`OutlinedButton(fillColor, borderColor)`、`TextFieldStyle`、`Line(color)`、`Circle(color)`。
- `PixelColorTween` 负责 ARGB 补间。

这条路径比早期“双模式”方案更简单：没有 `PixelTone` 到 `PixelColor` 的映射，也没有 Mono / Color buffer 之间的运行时分支。

---

## 已放弃的早期方案

早期设计曾考虑：

- 保留 `PixelTone.OFF / ON / ACCENT` 三色语义。
- `PixelPalette` 把三色 tone 映射到 RGB。
- `PixelColorMode.Mono` / `PixelColorMode.Color` 在 host 构造时切换。
- `MonoPixelBuffer(ByteArray)` 与 `ColorPixelBuffer(IntArray)` 双类型并存。
- `PixelThemeTokens` 同时持有 `xxxTone` 和 `xxxColor` 字段。

代码演进后没有保留这套公开模型。原因：

- 双模式会让 widget API、paint context、buffer pool、测试矩阵全部翻倍。
- Mono 模式下传 color、Color 模式下传 tone 的兼容策略容易产生隐式视觉漂移。
- Launcher 和 demo 的真实需求已经以直接 ARGB 颜色为主。
- 单一 ARGB buffer 更容易和 `Image(PixelBitmap)`、图形原语、动画补间、Android Bitmap blit 对齐。

---

## 当前边界

已支持：

- 任意 ARGB 颜色。
- 透明像素。
- `PixelBitmap` / `Image` 1:1 blit。
- `Line` / `Circle` 图形原语。
- 文本、容器、按钮、输入框的直接颜色样式。
- 颜色补间动画。

仍未支持：

- 线性 / 径向渐变。
- 渐变、blend mode 和更完整的 alpha 策略。当前 buffer 已提供 straight alpha `srcOver` 写入语义，`alpha = 255` 保留 opaque fast path。
- 子树级色彩空间切换。
- palette schema 或主题 token 体系。
- 自动把 Android/Compose/Material 主题映射到 pixel-engine。

这些能力如有真实需求，应作为独立任务设计，而不是恢复早期 Mono / Color 双模式。
