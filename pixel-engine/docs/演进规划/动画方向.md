# pixel-engine 动画方向

> 本文档不是已有功能说明，而是 **未来动画系统的设计方向**。
> 目的：在动手实现前，先把"像素引擎应该做哪种动画、不做哪种动画"写清楚，避免照搬 Flutter 导致风格漂移或过度工程。

最后更新：2026-05-20

---

## 1. 背景

当前 `pixel-engine` 完全没有动画系统。仅有的"动态"基础设施是：

- `PixelFrameScheduler`（Choreographer 帧驱动）
- `ValueNotifier` / `ChangeNotifier` / `ValueListenableBuilder`（值变 → 局部重建）
- `StatefulWidget.setState` + `DirtyElementScheduler`（局部 rebuild）
- `PixelScrollPhysics`（滚动惯性 fling，已内置弹性边界）

这些足以做"状态切换 → 立即重绘"，但不足以做"在 N 帧内平滑过渡到新状态"。

由于像素艺术有自己的视觉语言，**不能简单把 Flutter 的动画体系搬过来**。本文档先定方向。

---

## 2. 像素动画的取向

像素引擎的动画哲学与 Flutter / Compose 主流方向有几个本质区别：

### 2.1 离散优先，不追求"丝滑"

- 像素美学的核心是**离散感**：明确的像素格、明确的色阶切换。
- 60/120 FPS 的连续插值在像素 UI 上会糊掉锯齿、消解风格。
- **推荐**：动画应能配置为 15 / 30 FPS，并且默认走"分段跳变"曲线（step curve），而不是 ease curve。

### 2.2 整数像素，不允许亚像素

- 所有位移 / 尺寸 / padding 类 Tween 的输出必须是 `Int`，由曲线 round 到整数像素。
- 不存在"半个像素的位移"——半像素会被绘制层裁掉，结果是抖动。
- 这导致：很短的位移动画（< 4 像素）很多时候不如直接瞬切。

### 2.3 三色板没有真正的颜色插值

- pixel-engine 调色板是 `OFF / ON / ACCENT` 三档（外加 `PixelTone.toAlpha()` 之类的便利映射）。
- 颜色"渐变"在三色板里退化为**按时间阈值切换色阶**（0.0..0.5 → ON，0.5..1.0 → ACCENT 等）。
- 不要做 ARGB 线性插值——结果会落到调色板外的颜色，破坏视觉一致。

### 2.4 动画首要是反馈，不是装饰

- 像素界面更接近"复古设备 UI"——按键反馈、列表加载、模式切换是动画的主要场景。
- 弹性 / 重力 / 多段交错这些"叙事性动画"在像素 UI 里大多不必要。
- 默认时长应短（150-300ms），少用大于 500ms 的动画。

### 2.5 不需要的能力，明确不做

| Flutter 能力 | pixel-engine 决策 | 理由 |
|---|---|---|
| Hero 共享元素 | ❌ 不做 | 没有 Navigator，且像素 UI 较少需要跨页元素衔接 |
| SpringSimulation 弹簧物理 | ❌ 不做 | `PixelScrollPhysics` 已覆盖滚动；其他场景的弹性反馈瞬切 + 短动画更像素风 |
| Lottie | ❌ 不做 | 矢量动画与像素风冲突 |
| Rive | ❌ 不做 | 同上 |
| ARGB 颜色插值 | ❌ 不做 | 三色板不允许中间色 |
| 自定义路由转场 | ⏸ 暂缓 | 等 `Navigator` 出来再说 |

## 3. 复用现有基础设施

实施动画系统时，**优先复用**：

- `PixelFrameScheduler` 作为 vsync 源——不要新建 Choreographer 包装。
- `ChangeNotifier` 作为 Animation 状态变更广播器——`AnimationController` 应继承它。
- `ValueListenableBuilder` 作为"动画值 → 局部重建"的桥——避免新发明监听机制。
- `StatefulWidget` 持有 controller 生命周期——`initState` 创建、`dispose` 释放，与 Flutter 一致。

不要复用：

- `PixelScrollPhysics` 的 fling 实现——它只服务滚动，不要硬塞做通用动画引擎。

---

## 4. 分层路线图

按依赖顺序分四层。**每一层都可以独立落地、独立验证**，不必一次性做完。

### Layer 1 — 动画核心（P1）

最小可用集合，不依赖任何 widget 层改动：

- `PixelTicker` / `PixelTickerProvider`：基于 `PixelFrameScheduler` 派发 `(elapsedNanos) -> Unit`，可暂停 / 恢复 / dispose。
- `PixelAnimationController(duration, vsync)`：0→1 进度状态机，继承 `ChangeNotifier`。支持 `forward / reverse / repeat / stop / reset`，可读 `value: Float` 和 `status`。
- `Tween<T>`：抽象基类。具体实现至少包含：
  - `IntTween`（像素坐标 / 尺寸）
  - `EdgeInsetsTween`
  - `OffsetTween`（整数坐标 pair）
  - `PixelToneTween`（按阈值切色阶，**不是颜色插值**）
- `Curves`：
  - 平滑曲线：`linear` / `easeIn` / `easeOut` / `easeInOut`（输出连续 Float，由 Tween 自行 round）
  - **像素专属**：`step(n)` —— 把 0..1 分 n 段离散跳变（强烈推荐作为像素动画默认曲线）
  - `Interval(begin, end, child)`：用于交错动画
- `CurvedAnimation`：组合 controller + curve。

**验收**：单测覆盖 controller 状态机、Tween/Curve 数学正确性，不需要 widget 集成。

### Layer 2 — 隐式动画 widget（P1，依赖 Layer 1）

最常用、API 最易学的一层。**只做属性能落到整数像素或调色板的组件**：

- `AnimatedContainer`：动 width / height / padding / margin / borderTone（按阈值切色阶）
- `AnimatedOpacity`：用 `PixelTone.toAlpha()` 体系实现（注意：透明度在像素风里也应是离散的，例如 0% / 50% / 100% 三档）
- `AnimatedAlign`：动 alignment 到整数像素位置
- `AnimatedPadding`：动 EdgeInsets
- `AnimatedPositioned`：Stack 内整数位移
- `AnimatedSwitcher`：两 widget 离散切换 + 简单淡入淡出（淡入淡出走"按阈值切显隐"，不是真透明度）
- `TweenAnimationBuilder<T>`：兜底 API，用户自己提供 Tween

**不做**：`AnimatedDefaultTextStyle`（文本样式插值意义不大）、`AnimatedCrossFade`（用 AnimatedSwitcher 即可）。

### Layer 3 — 显式动画工具（P2）

- `AnimatedBuilder`：性能取向，只重建 child。
- `PixelFps`：让单个 controller 限制在 N FPS（包装 Ticker，drop 中间帧）。这是像素风专属能力。

### Layer 4 — 列表 / 路由动画（P3，需要前置条件）

依赖项：

- `Navigator` / `PixelRoute` 体系（目前不存在）。
- 列表 widget 暴露 item 增删事件（目前 `ListViewBuilder` 是 itemCount + itemBuilder，没有 diff）。

具体内容：

- `PixelAnimatedList`：item 插入 / 删除时的离散滑入 / 滑出。
- `PixelPageRoute` + `transitionsBuilder`：路由切换。但首先要有路由系统。

**建议**：Layer 4 不是动画系统的优先级，而是 Navigator 系统的优先级——动画只是顺手做掉。

## 5. 建议落地顺序

仅作排序参考，每步都可独立 commit：

1. Layer 1.1：`PixelTicker` + `PixelTickerProvider`。
2. Layer 1.2：`PixelAnimationController` + status / 状态机。
3. Layer 1.3：`Tween` 抽象 + `IntTween` / `EdgeInsetsTween` / `OffsetTween` / `PixelToneTween`。
4. Layer 1.4：`Curves`（含 `step(n)`）+ `Interval` + `CurvedAnimation`。
5. Layer 1.5：单测 + 一个 demo scene `ANIMATION_CORE`（直接展示 controller + Tween + Curve）。
6. Layer 2.1：`TweenAnimationBuilder`（最通用，最先做）。
7. Layer 2.2：`AnimatedContainer` / `AnimatedPadding` / `AnimatedAlign` / `AnimatedPositioned`。
8. Layer 2.3：`AnimatedOpacity`（按色阶档位）+ `AnimatedSwitcher`。
9. Layer 2.4：demo scene `IMPLICIT_ANIMATIONS`，做主题切换 / 按钮按下反馈 / 列表项展开收起。
10. Layer 3 / Layer 4：按需求触发再做，不强制排期。

**强制约束**：每加一个公开 widget 都必须：

- 出现在 [组件目录](../使用说明/组件目录.md)
- 至少出现在一个 demo scene
- 至少有一个单测覆盖
- 通过 `PublicApiCoverageTest`

## 6. 开放问题（已收敛，2026-05-20）

以下问题已在 Layer 1 + Layer 2 落地过程中完成决策：

### Q1：默认曲线 ✅ 已收敛

**决定**：`PixelAnimationController` 底层不附加曲线（等价于 `Linear`）；所有隐式动画 widget（`AnimatedContainer` / `AnimatedOpacity` 等）的 `curve` 参数默认为 `Curves.Step(8)`，可显式覆盖。

### Q2：透明度走真 alpha 还是色阶档位 ✅ 已收敛

**决定**：`AnimatedOpacity` 默认三档量化（`< 0.25 → 0f`，`0.25..0.75 → 0.5f`，`> 0.75 → 1f`），不引入真 alpha。用户若需要真 alpha 需自行在 `TweenAnimationBuilder` 中实现并写入自定义 rasterizer。

### Q3：Ticker 共享策略 ✅ 已收敛

**决定**：表面 API 独立（每个 controller 持有自己的 `PixelTicker`），底层 `PixelTickerProvider` 仅当有活动 ticker 时才向 `PixelFrameScheduler` 注册，实现同帧合并（同一个 provider 内的多个 ticker 共享一次 `scheduleFrame`）。

### Q4：动画期间降帧 ✅ 已收敛

**决定**：不做全局降帧，等真碰到性能问题再通过 `PerfRegressionTest` 检测并补。

### Q5：隐式动画 setState 模式 ✅ 已收敛

**决定**：Layer 2 所有 widget 均实现此模式——用户只需在父 state 调 `setState { property = newValue }`，widget 内部通过 `didUpdateWidget` 检测变化并自动起 controller。`AnimatedContainer` / `AnimatedPadding` / `AnimatedPositioned` / `AnimatedOpacity` 均已实现。
