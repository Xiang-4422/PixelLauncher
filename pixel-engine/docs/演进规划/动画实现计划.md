## 3. 已定的设计取舍（不要再讨论）

实现期不允许偏离以下决定。如有强烈异议，先在 issue 里讨论再改 `动画方向.md`。

### 3.1 默认曲线

- Layer 1 核心：`Curves.Linear` 是默认（可预测、最小惊讶）。
- Layer 2 隐式动画：默认 `Curves.Step(8)`——离散感强，保留像素美学。所有 `AnimatedXxx` widget 的 `curve` 参数默认值用 `Curves.Step(8)`。

### 3.2 透明度走档位，不走真 alpha

- `AnimatedOpacity` 把 0..1 离散为 **3 档**：`0`（OFF）/ `0.5`（半透明 ON，用现有 `PixelTone.toAlpha()` 中间档）/ `1`（完全 ON）。
- 阈值：`< 0.25 → 0`、`0.25..0.75 → 0.5`、`> 0.75 → 1`。
- 不允许在 Layer 1/2 阶段引入真 alpha——那是彩色模式的事。

### 3.3 Ticker 共享底层 vsync

- 表面 API 每个 `AnimationController` 像独占自己的 ticker。
- 底层只有一个 `PixelTickerProvider` 单例（每个 `PixelHostView` 一个），从 `PixelFrameScheduler` 拉一帧、广播给所有活动 controller。
- 没有活动 controller 时不调度帧，避免空跑 vsync。

### 3.4 不做全局降帧

- 不做"动画期间 widget 树全局降到 30FPS"——等真碰到性能问题再说。
- 单 controller 可以通过曲线 `Step(n)` 间接降视觉帧。

### 3.5 隐式动画必须支持 setState 自动触发

- Layer 2 所有 `AnimatedXxx` widget 内部都自己持有 controller。
- 用户改 widget 参数（如 `AnimatedContainer(width = newWidth)`）后，组件检测到属性变化、自动起 controller 过渡到新值。这是隐式动画的核心承诺。

### 3.6 `Tween<T>` 必须为彩色扩展留位

- `Tween<T>` 抽象基类不允许硬编码 `T = PixelTone`。
- 当前实现 4 个具体 `Tween`：`IntTween` / `EdgeInsetsTween` / `OffsetTween` / `PixelToneTween`。
- 未来彩色模式落地时只需新增 `PixelColorTween`，不得修改基类。

### 4.2 PixelTicker

```kotlin
public class PixelTicker(
    private val onTick: (elapsedNanos: Long) -> Unit,
) {
    public fun start()
    public fun stop()
    public val isActive: Boolean
    public fun dispose()
}
```

实现要点：

- 内部不持有 `PixelFrameScheduler`，由 `PixelTickerProvider` 注入帧脉冲。
- `start()` 把自身注册进 provider 的 active 列表；`stop()` 摘除。
- `onTick` 收到的 `elapsedNanos` 是 **从首次 tick 起的累计时间**（不是绝对时间），避免实现端再做减法。

**测试必须覆盖**：

- start → 第一次 onTick 触发；多次 tick 累计正确。
- stop 后不再触发 onTick；再次 start 重置 elapsedNanos = 0。
- dispose 后任何调用 no-op，不抛异常。

### 4.3 PixelTickerProvider

```kotlin
public class PixelTickerProvider internal constructor(
    private val frameScheduler: PixelFrameScheduler,
) {
    public fun createTicker(onTick: (Long) -> Unit): PixelTicker
    internal fun activate(ticker: PixelTicker)
    internal fun deactivate(ticker: PixelTicker)
}
```

实现要点：

- 持有 `activeTickers: MutableList<PixelTicker>`。
- 仅在 `activeTickers.isNotEmpty()` 时向 `frameScheduler.scheduleFrame` 注册下一帧。
- 收到帧后：记录 `lastFrameNanos`；遍历 `activeTickers` 派发 `onTick(now - tickerStartNanos)`；如果还有活动 ticker 继续注册下一帧。
- **同一帧只调一次 frameScheduler**——不允许每个 ticker 各自注册帧。

**测试必须覆盖**：

- 0 active ticker → 不调用 `frameScheduler.scheduleFrame`。
- N active tickers 同一帧只调一次 `frameScheduler.scheduleFrame`。
- ticker stop → 重新注册逻辑正确。

**测试基建**：用 `ManualFrameScheduler`（已存在于 `pixel-engine/src/test/...`，从测试基础设施借）作为 `frameScheduler` 注入，手动 step 帧。

### 4.4 PixelAnimationStatus

```kotlin
public enum class PixelAnimationStatus {
    Dismissed,    // value = 0，未运行
    Forward,      // 正向运行中
    Completed,    // value = 1，运行完成
    Reverse,      // 反向运行中
}
```

### 4.5 PixelAnimationController

```kotlin
public class PixelAnimationController(
    public val duration: Duration,
    private val vsync: PixelTickerProvider,
    initialValue: Float = 0f,
) : ChangeNotifier() {
    public var value: Float
        get() = ...
        public set(value) { ... }   // 直接 set 会停止动画

    public val status: PixelAnimationStatus
    public val isAnimating: Boolean

    public fun forward(from: Float? = null)
    public fun reverse(from: Float? = null)
    public fun repeat(reverse: Boolean = false)  // 循环播放
    public fun stop()
    public fun reset()                            // value = 0, status = Dismissed

    override fun dispose()
}
```

实现要点：

- 继承 `ChangeNotifier`，`value` 变化时 `notifyListeners()`。
- 内部持有一个 `PixelTicker`（通过 `vsync.createTicker`）。
- `forward()`：start ticker，按 `elapsedNanos / duration.inWholeNanoseconds` 计算 value，达到 1.0 时 status = Completed 并 stop ticker。
- `reverse()`：类似，方向相反。
- `repeat(reverse = false)`：达到 1 后立即 reset 到 0 继续 forward。
- `repeat(reverse = true)`：达到 1 后切 reverse，达到 0 后切 forward，循环。
- `dispose()` 必须 stop ticker 并 dispose 它，否则会泄漏帧回调。

**测试必须覆盖**（用 `ManualFrameScheduler` 手动驱动）：

- 默认 status = Dismissed，value = 0。
- forward 后 status = Forward；推进时间到 duration → status = Completed，value = 1。
- reverse 后 status = Reverse；推进到 0 → status = Dismissed。
- repeat(reverse=false)：到 1 后回到 0 继续。
- repeat(reverse=true)：到 1 后转向反向。
- stop 后 status 不变但 ticker 停。
- 直接赋值 value 立即停止动画。
- listeners 在每次 value 变化时被通知。
- dispose 后 ticker 也 dispose。

### 4.6 Tween 抽象 + 4 个具体实现

```kotlin
public abstract class Tween<T>(
    public val begin: T,
    public val end: T,
) {
    public abstract fun lerp(t: Float): T   // t 经过曲线后的值，0..1
    public fun evaluate(animation: Animation<Float>): T = lerp(animation.value)
}

public class IntTween(begin: Int, end: Int) : Tween<Int>(begin, end) {
    override fun lerp(t: Float): Int = (begin + (end - begin) * t).roundToInt()
}

public class EdgeInsetsTween(begin: EdgeInsets, end: EdgeInsets) : Tween<EdgeInsets>(begin, end) {
    override fun lerp(t: Float): EdgeInsets = EdgeInsets(
        left = lerpInt(begin.left, end.left, t),
        top = lerpInt(begin.top, end.top, t),
        right = lerpInt(begin.right, end.right, t),
        bottom = lerpInt(begin.bottom, end.bottom, t),
    )
}

public class OffsetTween(begin: IntOffset, end: IntOffset) : Tween<IntOffset>(begin, end) { ... }

public class PixelToneTween(begin: PixelTone, end: PixelTone) : Tween<PixelTone>(begin, end) {
    override fun lerp(t: Float): PixelTone = when {
        t < 0.5f -> begin
        else -> end
    }
    // 严格阈值切换；不在三色间做线性插值
}
```

**`Animation<T>` 接口**（用现有 `ChangeNotifier` 的 read-only 视图，必要时新增最薄抽象）：

```kotlin
public interface Animation<T> : Listenable {
    public val value: T
    public val status: PixelAnimationStatus
}
```

`PixelAnimationController` 应实现 `Animation<Float>`。

**测试必须覆盖**：

- IntTween：begin=0, end=10, t=0/0.5/1 → 0/5/10。t=0.49 → round 到 0（验证 round 不是 floor）。
- EdgeInsetsTween：四边各自 round。
- OffsetTween：两轴各自 round。
- PixelToneTween：t<0.5 → begin，t>=0.5 → end。**不允许出现第三种 tone**。

### 4.7 Curves

```kotlin
public fun interface Curve {
    public fun transform(t: Float): Float
}

public object Curves {
    public val Linear: Curve = Curve { it }
    public val EaseIn: Curve = Curve { it * it }
    public val EaseOut: Curve = Curve { 1f - (1f - it) * (1f - it) }
    public val EaseInOut: Curve = Curve { ... }
    public fun Step(n: Int): Curve = Curve { t -> floor(t * n) / n }   // 像素专属
}

public class Interval(
    public val begin: Float,
    public val end: Float,
    public val child: Curve = Curves.Linear,
) : Curve {
    override fun transform(t: Float): Float = when {
        t < begin -> 0f
        t > end -> 1f
        else -> child.transform((t - begin) / (end - begin))
    }
}
```

**测试必须覆盖**：

- Linear：t = 0/0.5/1 → 0/0.5/1。
- EaseIn / EaseOut / EaseInOut：边界 t=0 和 t=1 严格等于 0/1。
- Step(8)：t=0/0.124/0.125/0.249/0.25 → 0/0/0.125/0.125/0.25。
- Step(1)：t=0/0.99 → 0；t=1 → 1（瞬切）。
- Interval(0.2, 0.8)：t<0.2 → 0；t>0.8 → 1；t=0.5 → 0.5（中点）。

### 4.8 CurvedAnimation

```kotlin
public class CurvedAnimation(
    private val parent: Animation<Float>,
    public val curve: Curve,
    public val reverseCurve: Curve? = null,
) : Animation<Float>, Listenable {
    override val value: Float
        get() = activeCurve.transform(parent.value)
    override val status: PixelAnimationStatus get() = parent.status
    // listener 透传 parent
}
```

`activeCurve`：status = Reverse 时用 `reverseCurve ?: curve`，其他用 `curve`。

**测试必须覆盖**：

- Linear parent + EaseIn curve → value 是 parent.value 平方。
- Reverse 状态下走 reverseCurve。
- listener 透传：parent.notifyListeners() → CurvedAnimation 也广播。

## 9. 已知坑点 / 容易做错的地方

### 9.1 Ticker 不能各自注册帧

如果每个 `PixelAnimationController` 都向 `PixelFrameScheduler.scheduleFrame` 注册回调，N 个 controller 同帧会引发 N 次 frame 调度。**只有 `PixelTickerProvider` 注册帧，所有 ticker 共享这一次脉冲。**

### 9.2 dispose 顺序

`PixelAnimationController.dispose` 必须：

1. stop ticker
2. dispose ticker（解除 provider 引用）
3. 调用 `super.dispose()`（清空 listeners）

漏掉第 2 步会导致 provider 持有死引用，无法 GC。

### 9.3 隐式动画 widget 的 didUpdateWidget

属性变化检测必须**逐属性比较**，不能依赖 `widget != oldWidget`（因为 Widget 不可变、每次都是新对象）。否则会每帧都触发动画。

### 9.4 PixelToneTween 严禁三色插值

不要在 `OFF` 和 `ACCENT` 之间"过渡"出 `ON`。这是常见错误。tone tween 只能阈值切。

### 9.5 AnimatedOpacity 量化要在最终绘制时做

不要在 controller value 上量化——量化要在**读取 alpha 给 paint 用之前**做。否则后续如果加 curve，曲线会被量化提前截断。

### 9.6 测试时手动驱动帧

不要用 `Thread.sleep`。所有动画测试都用 `ManualFrameScheduler` 手动 `step(deltaNanos)`，保证确定性。

### 9.7 不要急着写 Layer 3

`AnimatedBuilder` 和 `PixelFps` 在 Layer 1+2 完成、用户实际用了一段时间反馈后再做。提早实现没有验证场景。

---

## 10. 不在本计划范围内

- Layer 3（AnimatedBuilder / PixelFps）—— 另外提单
- Layer 4（AnimatedList / 路由动画）—— 等 Navigator
- 物理动画（Spring 等）—— 不做
- 颜色 / alpha 真插值 —— 等彩色模式
- 动画系统的可视化调试工具（如 timeline overlay）—— 另外提单
- 与第三方动画格式互转（Lottie/Rive）—— 不做
