# pixel-engine 1.0.0 主题 Token 与组件状态迁移指南

## 影响范围

M5-1 把原先以少量具体颜色和组件默认参数为主的 `PixelThemeData`，扩展为完整且可继承的
`PixelThemeTokens`。旧 `PixelThemeData` 数据模型、`PixelTheme(data = ...)` 构造器和既有组件 facade
仍保留真实 JVM descriptor；新代码应优先使用语义 token 和带 `PixelControlStateSet` 的重载。

完整主题图包含：

- `PixelColorScheme`：22 个语义颜色角色；
- `PixelTypographyTokens`：body、label、title、caption、button、input；
- `PixelSpacingTokens`、`PixelSizeTokens`、`PixelRadiusTokens`、`PixelBorderTokens`；
- `PixelElevationTokens` 与既有 `PixelMotionThemeData`；
- `PixelComponentTokens`：21 个标准组件族；
- `PixelLabelTokens`：标准组件与状态的可替换默认文案。

`PixelThemeTokens` 根节点的公开属性依次为 `brightness`、`contrast`、`colors`、`typography`、
`spacing`、`sizes`、`radii`、`borders`、`elevations`、`motion`、`components` 和 `labels`。
`PixelTheme(tokens = ..., child = ...)` 会同时提供完整 token 图和投影后的旧 `PixelThemeData`；
`PixelTheme(data = ..., child = ...)` 则通过 `PixelThemeTokens.fromLegacy(data)` 补齐完整图。读取时：

- `PixelTheme.tokensOf(context)` / `maybeTokensOf(context)` 返回完整 token 图；无 provider 时前者回退到
  `PixelThemeTokens.Default`，后者返回 `null`；
- `PixelTheme.of(context)` / `maybeOf(context)` 保留旧主题读取行为；无 provider 时前者回退到
  `PixelThemeData.Default`，后者返回 `null`；
- 最近的显式 `PixelMotionTheme` 优先于 `PixelThemeTokens.motion`，因此可只在局部覆盖动画策略。

内置主题为 `Dark`、`Light`、`HighContrastDark` 和 `HighContrastLight`。`Default` 等同于 `Dark`，
因此未迁移业务不会在升级后突然切换基础明暗模式。

## 1. 提供完整主题

```kotlin
/** Wraps an application subtree in a consumer-defined pixel theme. */
fun applicationTheme(child: Widget): Widget {
    /** Brand scheme expressed through semantic roles instead of component-local colors. */
    val colors = PixelColorScheme.Dark.copy(
        primary = PixelColor.fromRgb(24, 184, 112),
        onPrimary = PixelColor.Black,
        focus = PixelColor.fromRgb(0, 224, 255),
        danger = PixelColor.fromRgb(232, 72, 80),
    )
    /** Complete immutable token graph inherited by every descendant component. */
    val tokens = PixelThemeTokens.Dark.copy(
        colors = colors,
        spacing = PixelSpacingTokens.Default.copy(small = 3),
        radii = PixelRadiusTokens.Default.copy(small = 2),
        borders = PixelBorderTokens.Default.copy(thin = 2),
        labels = PixelLabelTokens.Default.copy(
            confirm = "确定",
            cancel = "取消",
            loading = "加载中",
        ),
    )
    return PixelTheme(tokens = tokens, child = child)
}
```

组件 token 保存的是 `PixelColorRole`，而不是主题创建时的一份颜色副本。因此只复制
`PixelThemeTokens.colors` 就能让所有引用该角色的标准组件同步变化。间距、尺寸、圆角和边框也通过
共享 foundation scale 解析；例如组件中的标准 `2px` padding 编码会读取当前 `spacing.small`。
标准 spacing、size、radius、border 编码会映射到当前 foundation；不属于标准编码的非负整数仍作为
字面逻辑像素保留。`PixelFocusIndicatorTokens.width = 1` 是读取 `borders.focus` 的标准编码，其他正整数
保持为字面宽度，`inset` 必须为非负整数。

消费者仍可复制单个组件族：

```kotlin
/** Creates one theme with a denser, square Button family. */
fun denseButtonTheme(): PixelThemeTokens {
    /** Existing semantic state map retained while only geometry is customized. */
    val button = PixelComponentTokens.Default.button.copy(
        padding = EdgeInsets.all(1),
        cornerRadius = 0,
        elevationRole = PixelElevationRole.None,
    )
    return PixelThemeTokens.Dark.copy(
        components = PixelComponentTokens.Default.copy(button = button),
    )
}
```

所有尺寸使用非负整数逻辑像素。标准组件只绘制阶梯圆角、整数边框和无模糊硬阴影，不会因为主题
切换引入亚像素或抗锯齿边缘。

## 2. 统一状态模型

`PixelControlStateSet.Normal` 是空 bit set；其余状态可以组合。`PixelStateMap` 使用全局固定优先级：

```text
Disabled > Loading > Error > Pressed > Focused > Hovered > Selected > Normal
```

这个顺序只决定同一视觉属性的单值解析，而且按属性逐项回退：`PixelStateMap` 会从高到低寻找
“当前激活且该属性显式配置了 override”的第一个状态；找不到时才返回 `normal`。例如 Disabled +
Selected 的 `containerColor` 没有 Disabled override、但有 Selected override 时，结果是 Selected，
并不会凭空产生 Disabled 颜色。

焦点边框是独立叠加层：例如 Error + Focused 仍保留错误底色，同时在该组件的
`focusIndicator != null` 时绘制 focus indicator；焦点不会把错误、选择或按下底色替换掉。

```kotlin
/** Builds an error Button that can still expose an independent focus indicator. */
fun retryButton(onRetry: () -> Unit): Widget {
    /** Persistent business states; actual hover, press, and focus are merged by the runtime. */
    val states = PixelControlStateSet.of(PixelControlState.Error)
    return OutlinedButton(
        text = "RETRY",
        onPressed = onRetry,
        states = states,
    )
}
```

运行时拥有 Hovered、Pressed 和实际 Focused；业务通常只传 Selected、Error、Loading 或 Disabled。
为了确定性截图和自定义组件适配，状态集合仍能显式表示全部八种状态。

### 能力契约

| 状态 | Pointer / keyboard / semantics mutation | 焦点 | 说明 |
|---|---|---|---|
| Normal / Hovered / Pressed / Focused / Selected / Error | 可用（前提是回调存在） | 可进入并保留 | Error 改变状态呈现，不自动禁用修复动作。 |
| Loading | 全部禁用；旧 pointer owner 立即 cancel | 已有焦点保留 | 适用于提交中控件，避免焦点跳到背景。 |
| Disabled | 全部禁用；不导出可变 action | 立即失去且不可遍历 | 回调为 `null` 或 `enabled=false` 也会归一化为 Disabled。 |

焦点列适用于本身拥有键盘动作的可聚焦控件。Scrollbar 不新增独立 Tab stop；底层 List/ScrollView
继续拥有键盘与无障碍滚动动作，Scrollbar 的 Loading/Disabled 只撤销 thumb drag target。

Loading/Disabled 切换会同步清除 retained pressed/hover、Host down/hover/continuous owner 和未完成反馈
ticker。之后到达的 pointer-up 不会调用旧组件，也不会穿透点击同坐标背景。

## 3. 组件状态矩阵

以下 21 个 token 属性均有真实生产消费者。第二列与 Theme Showcase 的 21 个生产组件工厂一一对应；
“相关消费者”共享该族 token，但不是额外的 token 属性。所有族都能解析八种视觉状态，非交互组件
会把没有业务动作的状态作为纯视觉或语义状态处理。

| `PixelComponentTokens` 属性 | 标准生产工厂 | 相关消费者 / capability 约定 |
|---|---|---|
| `button` | `OutlinedButton` | Selected 由业务传入；Loading 保留已有焦点。 |
| `textButton` | `TextButton` | 与 Button 相同，默认无边框。 |
| `textField` | `TextField` | read-only/selection 与编辑焦点独立；Loading/Disabled 不接收编辑。 |
| `listTile` | `ListTile` | 可表示当前行；回调为空时归一化为 Disabled。 |
| `checkbox` | `Checkbox` | `checked=true` 自动合入 Selected。 |
| `switch` | `Switch` | `checked=true` 自动合入 Selected，thumb 位置与逻辑值同步。 |
| `slider` | `Slider` | value 仍由调用方控制；状态只控制呈现和输入能力。 |
| `tabs` | `Tabs` | 当前 tab 自动 Selected；方向键只在可交互时改变选择。 |
| `segmented` | `SegmentedControl` | 当前 segment 自动 Selected。 |
| `valueAdjuster` | `ValueAdjuster` | `Stepper`、`ShortcutHint`；两侧 action 可独立禁用。 |
| `menu` | `Menu` | `PixelMenuItem`；Loading 不提交 dismiss/selection。 |
| `dropdown` | `Dropdown` | `expanded=true` 合入 Selected；Loading 不展开或收起。 |
| `slidable` | `Slidable` | `SlidableAction`；Loading 取消拖动和 action。 |
| `dialog` | `Dialog` | `ConfirmDialog`；modal capability 与 surface 状态分离。 |
| `bottomSheet` | `BottomSheet` | 与 Dialog 共用安全视口，但使用独立 token。 |
| `toast` | `Toast` | `ToastQueue`、`Badge`；通知为被动 live region。 |
| `snackbar` | `Snackbar` | `SnackbarQueue`；action 在 Loading/Disabled 时移除且至多执行一次。 |
| `tooltip` | `Tooltip` | 被动 Overlay；状态改变 surface/content/border。 |
| `progress` | `ProgressBar` | `PixelLoadingBar`、`AnimatedPixelLoadingBar`、`ActivityIndicator`；保留进度语义。 |
| `refresh` | `RefreshIndicator` | `SwipeRefreshScaffold`；Loading 不重复触发刷新。 |
| `scrollbar` | `Scrollbar` | 不新增 Tab stop；Loading/Disabled 撤销 thumb drag target。 |

## 4. 参数优先级与旧 API

对某个公开覆写通道，通常按以下顺序解析：

```text
该通道适用的显式组件参数 > component token > foundation token / color scheme
```

这不是“任意显式参数永远压过所有状态”的承诺。Checkbox/Switch 等旧 facade 的 active/inactive
颜色用于 Normal/Selected 基础通道；Error、Loading、Disabled 等 capability/validation 状态仍可按
组件契约覆盖它们。完整且无歧义的状态/token 契约以带 `states` 的 state-aware 重载为准。

旧 facade 的参数类型、默认值、JVM descriptor 和 Kotlin `$default` bridge 均保留。state-aware 重载
在 Kotlin 中仍使用相同工厂名，并要求传入 `states`；JVM 侧通过稳定的 `@JvmName` 区分，例如
`OutlinedButtonWithControlStates`。因此旧源码与已编译二进制都能继续调用原 descriptor。

无 `PixelTheme` provider 的旧调用保持历史像素。在显式主题内，许多旧默认具体值只在兼容 facade 中
作为“参数未提供”的 sentinel，再转发到 nullable 的 state-aware 通道，使 token 可以传播；但兼容
路径不会承诺每个旧 facade 都消费每一种新 token 通道，某些复合组件仍保留旧视觉图。任意旧的组件
具体颜色也无法无损投影为新的语义颜色角色。

一个兼容限制是：旧重载无法区分“省略默认参数”和“调用方恰好显式传入与旧默认完全相同的值”。
需要锁定该具体值时，请改用 state-aware 重载并为它暴露的 nullable 覆写通道传非空值；若该工厂没有
对应覆写参数，则复制相应 component token。

```kotlin
// 兼容 facade：保留旧源码、默认参数和 JVM descriptor。
OutlinedButton(text = "SAVE", onPressed = ::save)

// State-aware facade：同一个 Kotlin 工厂名，states 为必填参数。
OutlinedButton(
    text = "SAVE",
    onPressed = ::save,
    states = PixelControlStateSet.of(PixelControlState.Loading),
)
```

## 5. 验收主题

当前应在 `app` 的真实页面或 SDK 测试中验证 Light、Dark、高对比度、自定义 token、组件状态色板，
以及切换主题时受控状态不被重置。可搜索 `PixelThemeTokens` 或 `high-contrast` 定位现有覆盖。

```bash
./gradlew :app:assembleDebug
./gradlew :pixel-engine:testDebugUnitTest
```

## 6. Snapshot、Golden 与覆盖门禁

- `PixelThemeTokenSnapshotTest` 锁定四组 preset、全部 foundation token、label、motion 和
  21×8 component role；
- `PixelThemeRenderGoldenTest` 用真实 `OutlinedButton` pipeline 锁定四组 preset、消费者自定义主题
  及八状态的精确 ARGB、边界和 interaction target；
- `ProductionComponentStateMatrixTest` 对 21 个生产工厂执行完整 21×8 状态矩阵，并用三种互异
  container/content/border 哨兵色要求每个组件至少在真实输出中绘制两个独立颜色通道；
- 各组件契约测试继续锁定 semantics、键盘、pointer、焦点、几何 token、优先级和资源清理；
- `checkThemeTokenCoverage` 扫描每个 component 族与完整 foundation token 图的生产运行时消费者，
  并把 JSON 证据写入 `pixel-engine/build/reports/theme/`。

更新主题时不要直接接受 snapshot/golden。先检查角色变化、像素边界和状态差异是否符合设计，再把
生成的候选报告复制为评审基线。发布门禁会把覆盖缺口、一个像素的差异和状态行为回归分别报告。

## 7. 迁移清单

1. 把应用根部 `PixelTheme(data = ...)` 迁移为 `PixelTheme(tokens = ...)`；旧形式可分阶段保留。
2. 把散落的品牌颜色映射到 `PixelColorScheme`，不要逐组件复制具体颜色。
3. 把间距、尺寸、边框和圆角差异放进 foundation 或 component token。
4. 用 Selected、Error、Loading、Disabled 表达业务状态，不用修改回调或颜色模拟视觉状态。
5. 保持受控值仍由业务拥有；状态主题不延迟 checked、value、expanded 或 progress 更新。
6. 对 custom theme 执行完整状态矩阵、键盘/语义测试及 snapshot/golden 评审。
7. 在 Theme Showcase 中切换四个内置 preset 和 Custom，对照 21 个生产组件与 21×8 色板检查主题。
