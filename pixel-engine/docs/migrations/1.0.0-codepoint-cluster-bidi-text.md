# pixel-engine 1.0.0 code-point 字体、cluster 段落与 Bidi 迁移指南

## 影响范围

1.0.0 的字体查找从 UTF-16 `Char` 主路径迁移到 Unicode scalar `Int`，段落布局从 code unit
迁移到 Unicode 17.0.0 extended grapheme cluster，并使用固定 Unicode 17.0.0、UAX #9
revision 51 解析 Bidi 视觉顺序。公开 selection、composition 和 Accessibility 索引仍是 Android
兼容的 UTF-16 offset。

这次迁移覆盖 `Text`、`RichText`、`TextField` 的测量、wrap、ellipsis、letter spacing、绘制、
caret、hit test、selection/composition 几何、selection handle 和 Android character bounds。
引擎不会因为布局而改写 backing `String`，也不会执行 NFC/NFD normalization。

## 固定文本模型

| 层级 | 1.0 契约 |
|---|---|
| selection / composition / Accessibility | UTF-16 offset |
| glyph pack key 与字体查找 | Unicode scalar `Int` |
| wrap / ellipsis / caret / hit test / selection 几何 | extended grapheme cluster |
| Bidi | Unicode 17.0.0、UAX #9 revision 51 |
| unsupported cluster | 一个 U+FFFD fallback 单元 |

LF、CR、CRLF、NEL、LINE SEPARATOR 和 PARAGRAPH SEPARATOR 都是硬换行。连续、开头和结尾
换行会保留空行及原始 source range。RichText span 边界落在一个 grapheme 内部时不会拆分
cluster；该 cluster 使用其首个 UTF-16 code unit 对应的 style，下一条 style 从下一个合法
grapheme boundary 开始。

## 字体 SPI 兼容

`GlyphSource` 和 `GlyphProvider` 新增 code-point overload。新实现应覆盖 `Int` 入口；旧实现可以
继续只实现冻结的 `Char` 入口：

```kotlin
/** Resolves full Unicode scalar values without narrowing supplementary glyph keys. */
class AppGlyphSource : GlyphSource {
    /** Immutable application glyph records keyed by complete Unicode scalar values. */
    private val glyphsByCodePoint: Map<Int, GlyphBitmap> = loadApplicationGlyphs()

    /** Preserves the frozen BMP entry point for previously compiled callers. */
    override fun findGlyph(character: Char, style: GlyphStyle): GlyphBitmap? {
        return findGlyph(character.code, style)
    }

    /** Looks up BMP and supplementary records using the complete scalar key. */
    override fun findGlyph(codePoint: Int, style: GlyphStyle): GlyphBitmap? {
        return glyphsByCodePoint[codePoint]
    }
}
```

旧 `GlyphSource.findGlyph(Char, ...)` 默认只能接收非 surrogate BMP。旧
`GlyphProvider.rasterizeGlyph(Char, ...)` 遇到 supplementary scalar 时收到一次 U+FFFD 请求，
不会收到两个 surrogate 请求。`BitmapGlyphSource`、`CompositeGlyphProvider` 和
`PixelFontEngine` 均保留完整 scalar key；`glyphs.bin` 的 `codePoint` 字段也按完整 `Int`
解析。

公开 `Int` 入口会拒绝负数、超过 U+10FFFF 的值和 surrogate 范围 U+D800–U+DFFF，避免非法
key 污染 cache 或与真实 glyph record 冲突。历史 backing text 中的非配对 surrogate 不会被
重写，但绘制时每个隔离恢复单元使用一个 U+FFFD glyph。

## 整 cluster rasterizer

原有 `PixelTextRasterizer` 继续兼容单 scalar cluster，包括 supplementary scalar。要声明一个
多 code-point cluster 可被原子绘制，消费者必须实现 additive `PixelClusterTextRasterizer`：

```kotlin
/** Rasterizer backed by an application shaper and cluster glyph atlas. */
class AppClusterRasterizer : PixelClusterTextRasterizer {
    /** Returns whether the atlas contains one atomic record for the exact cluster. */
    override fun canRasterizeCluster(cluster: String): Boolean {
        return clusterAtlasContains(cluster)
    }

    /** Measures the exact cluster or scalar payload supplied by paragraph layout. */
    override fun measureText(text: String): Int = measureAtlasPayload(text)

    /** Returns the fixed application font cell height. */
    override fun measureHeight(text: String): Int = applicationCellHeight()

    /** Draws one exact payload without normalizing or splitting it. */
    override fun drawText(
        buffer: PixelBuffer,
        text: String,
        x: Int,
        y: Int,
        color: PixelColor,
    ) {
        drawAtlasPayload(buffer, text, x, y, color)
    }
}
```

`canRasterizeCluster` 返回 `true` 后，`measureText` 与 `drawText` 会收到完全相同的原始 cluster；
实现必须真正原子测量和绘制，不能再按 code point 产生多个 fallback。内置
`PixelStyledTextRasterizer` 只声明单 scalar cluster，因为 `PixelFontEngine` 当前是一条记录对应
一个 code point。

`PixelTextRasterizer.drawText` 的冻结签名包含 Kotlin value class `PixelColor`，因此现有 Java
源码可以消费 `PixelStyledTextRasterizer`、`PixelClusterTextRasterizer.canRasterizeCluster` 和
Java-friendly 的 `GlyphSource`/`GlyphProvider`，但不能直接用 Java `implements`
`PixelTextRasterizer`/`PixelClusterTextRasterizer`。需要自定义 cluster rasterizer 时使用 Kotlin
实现并从 Java 注入；1.0 不为修复这一历史限制破坏旧 JVM 描述符。

多 scalar cluster 未被声明支持时，paragraph 只测量和绘制一个 U+FFFD。纯
default-ignorable、ZWJ、variation selector 或 Bidi control cluster 保留在 source/Bidi 输入中，
但宽度为零且不绘制 tofu。该 fallback 不改变 selection/composition offset，也不污染相邻
cluster 的测量。

## Bidi 与共享几何

引擎使用生成的固定 Unicode 属性表和完整 `BidiTest.txt` / `BidiCharacterTest.txt` corpus，生产
布局不依赖桌面 JDK、Android `java.text.Bidi` 或设备 ICU 版本。每条物理行先解析逻辑 embedding
level，再构造视觉 cluster 顺序；奇数 level 的规范 paired punctuation 使用固定 mirroring 表，
backing text 保持不变。

`paragraph`、TextField selection/composition、pointer hit test 和 Accessibility character bounds
消费同一个视觉 cluster 列表：

- mixed Bidi 边界可以有 upstream/downstream 两个视觉 caret；selection start 使用 downstream，
  selection end 使用 upstream；
- 一个 grapheme 中的所有 UTF-16 code unit 返回完全相同的 character rect，supplementary
  surrogate pair 也不会分裂；
- CRLF 的两个 code unit 共享上游行尾 caret rect；
- ellipsis 截掉或不可见的 source code unit 返回 `null` character rect；
- Android API 26+ 通过 `EXTRA_DATA_TEXT_CHARACTER_LOCATION_KEY` 返回屏幕坐标 `RectF[]`，数组
  长度等于平台请求长度，API 24–25 继续使用既有 node bounds/action fallback。

## 明确不承诺的能力

1.0 保证 grapheme-safe 布局、Unicode 17 UBA 视觉重排和 deterministic fallback，但不承诺：

- 内置 Arabic 或 Indic contextual shaping；
- 彩色 emoji；
- 全部 ZWJ ligature 字形资产；
- script-specific line breaking、hyphenation 或 OpenType shaping。

消费者只有在自己的 rasterizer/shaper 能完整处理 cluster 时，才能把对应脚本或 emoji 声明为
“受支持”。逻辑 grapheme 支持、Bidi 排序和真实 glyph 覆盖是三个独立能力。

## 迁移检查清单

1. glyph map、cache key 和 binary record 使用 `Int`，不要把 supplementary scalar 转成 `Char`。
2. 保留旧 `Char` override，或确认所有旧二进制消费者均由默认兼容方法承接。
3. 不要用 `String[index]` 做 wrap、ellipsis、caret 或 hit test。
4. 只有真正原子绘制 cluster 时才实现 `PixelClusterTextRasterizer` 并返回 `true`。
5. selection/composition/Accessibility 仍传 UTF-16 offset，不改成 code-point index。
6. 对纯 RTL、`ABC אבג 123`、RTL 内嵌 LTR/数字、paired punctuation、decomposed Latin、
   supplementary emoji、CRLF、ellipsis、RichText 跨 span 和 unsupported cluster 建立回归。
7. 不要根据 Android ICU 的版本差异改变引擎固定 Unicode 17 布局结果。
