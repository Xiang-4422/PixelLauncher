# pixel-engine 1.0.0 本地化迁移指南

## 影响范围

1.0.0 新增平台中立的 `PixelLocale`、`PixelLocalizationBundle`、
`PixelLocalizationDelegate`、`PixelLocalizationResolver`、`PixelLocalizationProvider` 和
`PixelLocalizations`。标准组件可以在运行时切换默认名称、Loading/Error 状态文案、Navigation
容器名称以及整数和百分比格式，同时保留 keyed State、焦点、选择、语义身份和 Android 节点角色。

本次能力是**显式 opt-in**：

- `PixelHostView` 根环境只提供有序的 `HostCapabilitiesData.locales`，不会自动安装
  `PixelLocalizationProvider` 或 `PixelLocalizations`；
- 没有显式 provider 时，既有 `PixelThemeTokens.labels`、English fallback 和 scope-less legacy
  行为保持不变；
- `PixelLocalizationBundle.Default` 等于 `English`，但读取该常量不会把 provider 安装进树；
- 一旦应用显式安装 provider，provider 文案会按既定优先级压过 theme label。这是 opt-in 后的预期
  行为，不是自动迁移。

因此，已有应用可以先升级二进制而不改变界面文案，再按页面或子树逐步安装 provider。

## Provider 与 Host 的职责

### `PixelLocalizationProvider`：解析并安装

`PixelLocalizationProvider` 是通常放在应用内容根部的便捷入口。它读取最近的
`HostCapabilitiesData.locales`，用 `PixelLocalizationResolver` 选择 bundle，然后在子树中安装
`PixelLocalizations`。

当 `localeOverride == null` 时，它订阅 Host 的完整有序 locale 列表；当 override 非空时，它只解析
该 locale，不读取 Host locale 依赖。Host scope 缺失时，从 resolver 的 `defaultLocale` 开始。

```kotlin
/** Installs host-driven localization around one application subtree. */
fun localizedApplication(child: Widget): Widget {
    return PixelLocalizationProvider(
        child = child,
        resolver = PixelLocalizationResolver.Default,
        key = "application-localization",
    )
}
```

当前 Android Host 会把一个完整 `HostCapabilitiesData` 注入根树；未提供应用 override 时，locale
兼容默认值为 English。应用或测试可以显式提供有序偏好，但仍需自己安装 localization provider：

```kotlin
/**
 * Supplies ordered Host locales and explicitly opts the rendered content into localization.
 *
 * @param hostView Activity-attached Host whose environment is being configured.
 * @param content Application content factory evaluated by the retained Host.
 */
fun configureLocalizedHost(
    hostView: PixelHostView,
    content: () -> Widget,
) {
    hostView.capabilitiesOverride = HostCapabilitiesData(
        locales = listOf(
            PixelLocale("zh-CN"),
            PixelLocale("en-US"),
        ),
    )
    hostView.setContent {
        PixelLocalizationProvider(
            child = content(),
            resolver = PixelLocalizationResolver.Default,
            key = "host-localization",
        )
    }
}
```

`capabilitiesOverride` 必须在拥有该 View 的线程赋值。未来 Host 如何从平台采集 locale 不改变这里的
边界：Host 发布有序偏好，应用决定是否安装和使用 localization provider。

### `PixelLocalizations`：直接安装

已经选好 bundle，或只想覆盖一个局部子树时，直接构造 `PixelLocalizations`：

```kotlin
/** Installs a resolved Chinese bundle without consulting Host locale preferences. */
fun chineseSubtree(child: Widget): Widget {
    return PixelLocalizations(
        locale = PixelLocale("zh-CN"),
        bundle = PixelLocalizationBundle.Chinese,
        child = child,
        key = "chinese-localizations",
    )
}
```

这里 `locale` 是当前请求值，`bundle.locale` 是实际资源值；语言级 `zh` bundle 服务 `zh-CN` 请求是
合法的。也可以把 resolver 直接交给次构造器：

```kotlin
/** Resolves one explicit locale and installs the resulting inherited bundle. */
fun resolvedFrenchSubtree(
    child: Widget,
    resolver: PixelLocalizationResolver,
): Widget {
    return PixelLocalizations(
        locale = PixelLocale("fr-CA"),
        resolver = resolver,
        child = child,
        key = "french-localizations",
    )
}
```

`PixelLocalizations.of(context)` 与 `localeOf(context)` 要求祖先已经显式安装 provider；没有时会抛出
`IllegalStateException`。需要兼容未迁移子树时使用 `maybeOf(context)` / `maybeLocaleOf(context)`，它们
在 provider 缺失时返回 `null`，不会暗中回退或安装 English。

### 嵌套 provider

最近的 inherited `PixelLocalizations` 获胜。外层可以跟随 Host，内层可以锁定某一语言：

```kotlin
/** Keeps the app host-driven while pinning one account region to Chinese. */
fun localizedRegions(
    applicationContent: Widget,
    chineseAccountContent: Widget,
): Widget {
    /** Inner direct provider overrides only its own descendant region. */
    val accountRegion = PixelLocalizations(
        locale = PixelLocale("zh-CN"),
        bundle = PixelLocalizationBundle.Chinese,
        child = chineseAccountContent,
        key = "account-region-localization",
    )
    return PixelLocalizationProvider(
        child = Column(
            children = listOf(applicationContent, accountRegion),
            key = "localized-regions",
        ),
        key = "outer-host-localization",
    )
}
```

保持 provider 和组件 key 稳定时，替换 bundle 只更新 inherited 文案；组件 State、TextField text / selection /
composition / focus、Navigation 选择和稳定语义身份不会因为 locale 本身被重建。

## Locale 与 bundle 回退顺序

`PixelLocale` 接收 BCP-47 language tag，拒绝空白或不合法输入，并把大小写、分隔符和兼容 tag
规范化到 `languageTag`。例如 `ZH-hans-cn` 公开为 `zh-Hans-CN`。

对 Host locale 列表中的每个偏好，resolver 按以下顺序构造候选，并保持首次出现顺序：

1. 第一个 Host preference 的 exact canonical tag；
2. 该 tag 的 language-only 候选；
3. 后续每个 Host preference 的 exact，再到各自 language-only；
4. `PixelLocalizationResolver.defaultLocale` 的 exact，再到 language-only；
5. English 终端回退。

例如 Host 提供 `[zh-Hant-TW, fr-CA]`，configured default 是 `ja-JP`，候选顺序为：

```text
zh-Hant-TW → zh → fr-CA → fr → ja-JP → ja → en
```

每个候选内部先查询自定义 `delegate`，再查询内置 bundle。delegate 必须是 exact lookup：只有请求
`fr` 时才能返回 `bundle.locale == fr` 的 bundle；不支持时返回 `null`。把 `fr` bundle 错误地从
`fr-CA` 查询返回会立即抛出异常，而不是静默接受不一致映射。

`PixelLocalizationProvider` 发布的 active locale 始终是第一个请求 locale，即使实际 bundle 来自后续
Host preference 或 configured default。因此诊断时应同时观察：

- `PixelLocalizations.localeOf(context)`：当前请求的 active locale；
- `PixelLocalizations.of(context).locale`：最终命中的资源 bundle locale。

内置资源包括：

- `PixelLocalizationBundle.English`：locale 为 `en`；
- `PixelLocalizationBundle.Chinese`：locale 为 `zh` 的内置简体中文，供 `zh-*` 通过 language
  fallback 使用；需要繁体等 script-specific 资源时应注册 exact custom bundle；
- `PixelLocalizationBundle.Default`：与 English 相同；
- `PixelLocalizationDelegate.BuiltIn`：内置 exact lookup delegate。

## 组件文案优先级

Provider-aware 的可选组件文案固定按以下顺序解析：

```text
组件显式文案 → 最近的 PixelLocalizations bundle → PixelThemeTokens.labels → English fallback
```

自定义组件应复用同一公开 helper，而不是复制一套优先级：

```kotlin
/** Resolves one optional custom-component label with the SDK's fixed precedence. */
fun providerAwareButtonLabel(explicitLabel: String?): Widget {
    return Builder(key = "provider-aware-label") { context ->
        /** Explicitly installed bundle, absent until the application opts in. */
        val providerBundle = PixelLocalizations.maybeOf(context)
        /** Current theme remains the fallback when no provider supplies this label. */
        val theme = PixelTheme.tokensOf(context)
        /** Final non-blank label shared with production component resolution. */
        val resolvedLabel = PixelLocalizationResolver.resolveText(
            explicitText = explicitLabel,
            providerText = providerBundle?.labels?.button,
            themeText = theme.labels.button,
            englishFallback = PixelLabelTokens.Default.button,
        )
        Text(data = resolvedLabel)
    }
}
```

显式安装 English provider 也属于 provider 层，因此会压过自定义 `PixelThemeTokens.labels`。如果应用
希望继续使用 theme label，应暂不安装 provider，或把相同文案写进应用 bundle。

### 强制显式的业务文案不会翻译

Localization 只提供框架默认文案和可选状态文本，不会推断或翻译业务内容。以下内容继续由调用方
显式拥有：

- `PixelNavigationDestination.label`、Radio / IconButton 的必填 `semanticLabel`；
- 非空显式 Button 文本、菜单项、表单 label / hint / error、Toast/Snackbar 消息；
- route 名称、业务 ID、用户输入以及服务端返回内容。

例如 NavigationBar 的容器默认名称和 Loading/Error status 可以来自 provider，但每个 destination
label 始终使用调用方传入值。业务若需要翻译，应先从自己的资源层取出字符串，再传给组件。

## `PixelLabelTokens` 的 29 字段 ABI 边界

`PixelLabelTokens` 的构造器、`copy` 和 component 顺序已经冻结为 29 个 `String` 字段，本次没有追加
Navigation 或 formatter 属性：

| 分组 | 字段 | 数量 |
|---|---|---:|
| 通用动作与状态 | `confirm`、`cancel`、`dismiss`、`empty`、`error`、`loading` | 6 |
| 标准组件 | `button`、`textButton`、`textField`、`listTile`、`checkbox`、`switch`、`slider`、`tabs`、`segmentedControl`、`valueAdjuster`、`decrease`、`increase`、`menu`、`dropdown`、`dialog`、`bottomSheet`、`toast`、`snackbar`、`tooltip`、`progress`、`refresh`、`scrollbar`、`slidable` | 23 |
| 合计 | — | 29 |

这样旧二进制仍能调用原构造器和 `copy` descriptor。新增但不适合扩展该 data class ABI 的值放在
`PixelLocalizationBundle`：

- `locale`：bundle 的 exact canonical locale；
- `labels`：上述 29 字段；
- `navigationBar` / `navigationRail`：Navigation 容器名称；
- `PixelIntegerFormatter`：由 `formatInteger(Int/Long)` 使用；
- `PixelPercentFormatter`：由 `formatPercent(Float)` 使用。

整数 formatter 接收有符号 `Long`。百分比 formatter 接收有限的闭区间 `0f..1f` fraction；默认实现
输出四舍五入后的整数和 ASCII `%`。Slider、ProgressBar 和 Stepper 等生成式语义值会使用 bundle
formatter；调用方显式传入的 `semanticValue` / `valueText` 仍优先。

## 自定义 delegate 与 formatter（Kotlin）

`PixelLocalizationDelegate.fromBundles` 会建立不可变 exact map，并拒绝 canonical locale 重复。下面
定义一个完整的 English 品牌变体，因此只需从 English labels 复制需要改变的字段：

```kotlin
import kotlin.math.roundToInt

/** Brand-specific English labels and deterministic numeric suffixes. */
private val acmeLocalizationBundle: PixelLocalizationBundle = PixelLocalizationBundle(
    locale = PixelLocale("en-x-acme"),
    labels = PixelLabelTokens.Default.copy(
        button = "Action",
        textField = "Entry field",
        loading = "Working",
    ),
    navigationBar = "Primary navigation",
    navigationRail = "Side navigation",
    integerFormatter = PixelIntegerFormatter { value -> "$value units" },
    percentFormatter = PixelPercentFormatter { fraction ->
        "${(fraction * 100f).roundToInt()} percent"
    },
)

/** Exact custom delegate followed by configured English and terminal English fallback. */
private val acmeLocalizationResolver: PixelLocalizationResolver = PixelLocalizationResolver(
    delegate = PixelLocalizationDelegate.fromBundles(acmeLocalizationBundle),
    defaultLocale = PixelLocale.English,
)

/** Installs the resolver while continuing to consume ordered Host preferences. */
fun acmeLocalizedApplication(child: Widget): Widget {
    return PixelLocalizationProvider(
        child = child,
        resolver = acmeLocalizationResolver,
        key = "acme-localizations",
    )
}
```

新增一种完整语言时，不要从 English `copy` 后只翻译少数字段；应显式构造全部 29 个 label，或从已
完整翻译且语义相同的 bundle 复制。formatter 不应依赖进程默认 locale，否则同一 bundle 在不同设备
上会产生不可预测输出。

也可以实现动态 delegate：

```kotlin
/** Exact runtime lookup that never performs fallback inside the delegate itself. */
fun mapLocalizationDelegate(
    bundles: Map<PixelLocale, PixelLocalizationBundle>,
): PixelLocalizationDelegate {
    return PixelLocalizationDelegate { requestedLocale ->
        bundles[requestedLocale]
    }
}
```

fallback 只属于 resolver；delegate 内部再次做 language/default fallback 会破坏候选顺序和 locale
一致性检查。

## Java 示例

Java 可以直接使用 `@JvmField` 内置 bundle、`@JvmStatic fromBundles` 和 `@JvmOverloads` 构造器。

```java
/** Java entry points for direct and Host-driven localization installation. */
public final class PixelLocalizationExamples {
    /** Utility class; instances carry no state. */
    private PixelLocalizationExamples() {}

    /** Resolves zh-CN through the built-in zh language bundle and installs it directly. */
    public static Widget chinese(Widget child) {
        return new PixelLocalizations(
            new PixelLocale("zh-CN"),
            PixelLocalizationResolver.Default,
            child,
            "java-chinese-localizations"
        );
    }

    /** Installs a custom exact bundle with Java SAM formatter implementations. */
    public static Widget customEnglish(Widget child) {
        /** Complete English labels reused by an English private-use variant. */
        PixelLabelTokens labels = PixelLocalizationBundle.English.getLabels();
        /** Exact custom bundle containing navigation names and numeric formatting. */
        PixelLocalizationBundle bundle = new PixelLocalizationBundle(
            new PixelLocale("en-x-java"),
            labels,
            "Primary navigation",
            "Side navigation",
            value -> value + " units",
            fraction -> Math.round(fraction * 100.0f) + " percent"
        );
        /** Exact custom lookup checked before built-ins for every resolver candidate. */
        PixelLocalizationDelegate delegate = PixelLocalizationDelegate.fromBundles(bundle);
        /** English configured default used after every Host preference is exhausted. */
        PixelLocalizationResolver resolver = new PixelLocalizationResolver(
            delegate,
            new PixelLocale("en")
        );
        return new PixelLocalizationProvider(
            child,
            resolver,
            null,
            "java-host-localizations"
        );
    }
}
```

Java 传 `null` 作为 `localeOverride` 表示跟随 Host；传 `new PixelLocale(...)` 则绕过 Host locale
依赖。Java formatter 即使类型系统允许返回 `null`，运行时仍会按无效结果拒绝。

## 旧 facade 与兼容边界

### 冻结默认值 sentinel

为保持旧源码、JVM descriptor 和 Kotlin `$default` bridge，一些旧 overload 仍保留具体 English
默认参数。运行时把这些冻结值作为“调用方省略参数”的 sentinel。例如：

- NavigationBar 的 `"Navigation bar"`；
- NavigationRail 的 `"Navigation rail"`；
- 旧 Slider、Menu、Dropdown 等 facade 的历史默认名称。

旧调用点无法区分“省略默认值”和“显式传入一个恰好等于默认值的字符串”。因此在 Chinese provider
内，旧 NavigationBar 即使显式传 `semanticLabel = "Navigation bar"`，也会按省略处理并得到
`"导航栏"`。这是 grandfathered 兼容边界。

需要强制显式值时：

1. 优先使用提供 nullable 显式通道的 state-aware overload，并传非空值；
2. Navigation 等没有可区分 overload 的旧入口，可在局部嵌套 English/custom bundle；
3. 不要依赖与冻结 sentinel 完全相等的字符串表达业务名称。

与 sentinel 不同，旧 TextField 的非空 placeholder 历史上就是 spoken label；它继续作为调用方显式
内容，而不是“省略”信号。

### Blank 值

新本地化数据要求非空白：

- `PixelLabelTokens` 的 29 个字段均不可 blank；
- `navigationBar` / `navigationRail` 不可 blank；
- `PixelLocalizationResolver.resolveText` 的任一 present candidate 不可 blank；
- formatter 结果不可为 `null` 或 blank。

少数旧组件 overload 历史上允许显式 blank，并在进入严格 resolver 前保留该行为。它们只属于既有
兼容路径，不应作为新代码的“省略”约定。新 nullable API 用 `null` 表示该层缺失；必填业务 label
必须传非空白值。

### Scope-less visual 兼容

`PixelLocalizationProvider` 不是 `PixelTheme`，不能成为视觉分支开关。只安装 localization 时：

- provider-aware 默认名称和状态文案可以更新；
- 旧 scope-less facade 仍走其历史像素路径；
- 不会因为 localization 存在就自动启用 component token、圆角、阴影或颜色动画；
- 无 provider 的旧应用连文案优先级也不会变化。

如果同时显式安装 `PixelTheme`，视觉变化来自 theme opt-in，而不是 localization。

## 调试、异常与明确排除项

### 调试

排查错误语言或状态文案时，按以下顺序检查：

1. `PixelLocalizations.maybeLocaleOf(context)?.languageTag`：active 请求；
2. `PixelLocalizations.maybeOf(context)?.locale?.languageTag`：实际 bundle；
3. 自定义 delegate 是否只执行 exact lookup；
4. 组件是否有显式文案或命中了 frozen sentinel；
5. `PixelTheme.tokensOf(context).labels`：provider 缺失时的 fallback；
6. `PixelHostView.dumpSemanticsTree()`：最终 role、label、value/error、稳定 id 与 bounds。

嵌套 provider 时必须在出问题的组件 `BuildContext` 内读取，不能只检查应用根。Provider 更新后若
key 和语义角色稳定，Android accessibility `className` 与 virtual ID 应保持；在固定尺寸或仅更新
spoken text 的组件上，bounds 也应保持。若本地化文字参与可见布局，更长文本引起的合法 reflow
可能改变 bounds，不应把它误判为语义身份替换。

### 常见异常

| 情况 | 结果 |
|---|---|
| blank / ill-formed BCP-47 tag | `PixelLocale` 抛 `IllegalArgumentException` |
| `HostCapabilitiesData.locales` 为空或 canonical 重复 | 构造时抛 `IllegalArgumentException` |
| `fromBundles` 存在重复 canonical locale | 构造 delegate 时抛 `IllegalArgumentException` |
| delegate 为候选 locale 返回了不同 `bundle.locale` | resolver 立即抛 `IllegalArgumentException` |
| provider/theme/explicit 的 present 文案 blank | 严格 resolver 抛 `IllegalArgumentException` |
| percent 不是有限 `0f..1f` | `formatPercent` 抛 `IllegalArgumentException` |
| formatter 返回 `null` 或 blank | 对应 format 调用抛 `IllegalArgumentException` |
| provider 外调用 `PixelLocalizations.of/localeOf` | 抛 `IllegalStateException`；改用 `maybeOf/maybeLocaleOf` |

### 不属于 localization 的字符串

以下值有意保持 locale-neutral，不应放进 bundle：

- debug label、Inspector、dump 和测试诊断文本；
- 异常消息、协议字段、route/business ID；
- `PixelSemanticRole` 到 Android `className` 的映射，例如 `android.widget.EditText`、
  `android.widget.Button`；
- `PixelInputType.ASCII` 的 Android IME hint：它固定请求 English `imeHintLocales`、uppercase/visible
  ASCII input 和 `IME_FLAG_FORCE_ASCII`，不会随 UI provider 切换；
- 用户输入、selection/composition offset、Unicode grapheme、Bidi 和字体 fallback 规则。

Localization 负责选择用户可见默认文案和数字格式，不改变 Android widget class、输入类型、IME
协议或 Unicode 编辑边界。Unicode/grapheme/IME 拦截与 Bidi 排版属于后续独立迁移范围。

## 迁移清单

1. 保持 Host locale preference 有序、canonical 且不重复。
2. 在应用根显式添加 `PixelLocalizationProvider`；需要分阶段迁移时只包裹目标子树。
3. 为自定义语言提供完整 29 字段、Navigation 名称和确定性 formatter。
4. 让 delegate 只做 exact lookup，把 language/default/English fallback 留给 resolver。
5. 把业务 label 在应用资源层翻译后显式传入，不期待 SDK 翻译 destination、菜单项或用户内容。
6. 检查旧 frozen sentinel 和 blank 兼容点；新代码用 nullable 通道表达省略。
7. locale 热切换时保持 provider、TextField、Navigation 和业务组件 key 稳定。
8. 验证最终 semantics label/status，同时确认 State、focus、selection、composition、Android class 和
   bounds 未被替换。
