# 1.0.0 资源加载与内存边界迁移

1.0.0 把资源路径从“调用方自行约束的同步加载 + 无界强引用 map”升级为有界解析、线程安全 LRU 和正式异步加载契约。旧的无参 `PixelResourceCache`、bitmap/sprite 读取、资源定义构造器、解构和 `copy` JVM 描述符仍保留；迁移重点是行为边界，而不是被迫改写所有调用点。

## 必须关注的行为变化

- `PixelResourceCache` 现在有默认字节和条目预算，达到预算会确定性 LRU 淘汰。依赖“对象永远驻留直到手动 clear”的代码，应显式提供足够预算或在业务层持有仍在使用的资源引用。
- `PixelBitmap.pixels` 和 `PackedGlyphRecord.packedPixels` 返回副本。修改 getter 返回数组不再修改资源；需要变更时应修改自己的数组并构造新对象。
- manifest、sprite、glyph 不再容忍正则解析曾经接受的重复 key、尾随文本、浮点数或模糊二进制长度。损坏输入会抛出对应公开加载异常。
- `PixelGlyphPackAssetLoader` 使用有界 `PixelResourceCache`，不再维护无容量私有 map。需要跨 loader 共享时把同一个 cache 传入构造器。

## 推荐接入

```kotlin
val cache = PixelResourceCache(
    limits = PixelResourceCacheLimits(
        maxTotalBytes = 48L * 1024L * 1024L,
        maxBitmapBytes = 32L * 1024L * 1024L,
        maxSpriteSheetBytes = 32L * 1024L * 1024L,
        maxGlyphPackBytes = 16L * 1024L * 1024L,
    ),
    evictionListener = PixelResourceEvictionListener(::recordResourceEviction),
)
val loader = PixelResourceLoader(
    cache = cache,
    executor = resourceExecutor,
)
val assetBitmaps = PixelBitmapAssetLoader(context.assets)

val request = loader.loadBitmapAsync("icon/$revision") {
    assetBitmaps.load(
        path = definition.path,
        expectedSha256 = definition.sha256,
    )
}
```

executor 的创建、并发度和关闭由应用负责。UI 层保存 `PixelResourceLoadHandle`；页面销毁时可取消自己的订阅，但共享 IO 会继续服务其他订阅者，并在成功后写入 cache。

## 主线程和失败策略

- `loadBitmap`、`loadSpriteSheet`、`loadGlyphPack` 默认禁止 Android 主线程；UI 使用对应 `load*Async` 或 `prefetch*`。
- 未完成句柄也禁止在主线程 `await()`。在协程中应把句柄接到项目自己的 future/coroutine adapter，而不是阻塞主线程。
- 默认失败缓存为 5 秒。同 key 的损坏文件或临时 IO 错误不会在每次重组/重绘时重复读取；资源被修复或网络状态恢复后可调用 `clearFailure`。
- `cancel()` 是订阅取消，不是任务取消。SDK 不抢占可能正在被其他消费者共享的磁盘读取。

## 完整性与格式限制

- bitmap asset/resource：限制编码字节，校验 PNG/JPEG/GIF/WebP/BMP magic、可选 SHA-256、bounds、单轴尺寸和总像素，再正式解码。
- manifest/catalog/sprite：限制总字符、32 层嵌套、对象/数组成员、字符串、metadata 和资源/frame 数；只接受协议所需整数 JSON。
- glyph：限制二进制总长和 glyph count，校验 PGLY magic/version、cell height、Unicode scalar、advance/width、精确 packed length、重复 code point、截断和尾随数据。
- 所有资源路径必须是安全相对路径，拒绝绝对路径、空段、`.` 和 `..`。

checksum 是外部完整性信号，不替代格式校验。建议 catalog 记录每个 bitmap/sprite/font 文件摘要，同时由分发层校验整个 catalog 摘要。

## 缓存生命周期

自动 LRU 只提供内存上限，不替代业务生命周期：

- 主题、locale、字体包或资源 revision 切换时，把 revision/checksum 纳入 key，并移除不再可达的旧 key。
- `onTrimMemory`、账户退出或大场景关闭时调用 `clear()`；清理前开始的旧任务不会把资源重新写回。
- `detailedSnapshot()` 只含 key、类型、估算字节和访问序，不持有 bitmap/sheet/glyph 引用，可安全用于 diagnostics。
- eviction listener 在缓存锁外调用；监听器只做轻量记录，不应同步执行 IO。

## 兼容性

本次变更未删除既有资源 API 的 JVM 描述符。三个资源定义为保持 checksum 扩展与旧二进制 `copy$default` 共存，继续支持旧构造、`componentN`、`copy`、相等性、哈希和无 checksum 的旧诊断文本。`PixelBitmap` 旧三参数构造和 `pixels` getter 也保留，但 getter 的数组所有权从共享改为副本。
