# pixel-engine 1.0.0 动画正确性迁移指南

## 影响范围

M3-1 固定了动画在显式起点、中途反向、取消、快速 retarget、Host 暂停和子树切换时的
行为。受影响的主要 API 是：

- `PixelAnimationController`；
- `Tween` / `TweenAnimationBuilder` 与基于它的隐式动画；
- `Opacity` / `AnimatedOpacity`；
- `AnimatedSwitcher`。

`PixelAnimationController`、`Opacity` 和 `AnimatedSwitcher` 的旧 JVM 签名保持不变。`Tween.begin`
和 `Tween.end` 从只读属性改为可变属性，保留构造器与 getter，只新增两个 setter；这是
source/binary additive 变化。其余都是运行时正确性修复。

## 1. Controller 时间与取消语义

`duration` 始终表示完整 `0f..1f` 距离的 active time。从中间值出发时，segment 时长按剩余
距离等比缩放；Host 暂停期间的 wall-clock 时间不计入。

```kotlin
/** Reverses continuously from the value currently visible on screen. */
fun reverseCurrent(controller: PixelAnimationController) {
    controller.reverse()
}

/** Cancels frame scheduling while preserving the current value for a later resume. */
fun cancelAndResumeLater(controller: PixelAnimationController) {
    controller.stop()
    // A later command starts a fresh segment from the retained visual value.
    controller.forward()
}
```

固定边界：

- `forward(from)` / `reverse(from)` 立即应用已 clamp 的显式起点；不传 `from` 则保留当前值。
- 重复 forward/reverse 或中途反向都重建新的 elapsed 锚点，不复用旧 ticker 时间。
- `stop()` 幂等取消 pending frame，保留 value 和 `Forward/Reverse` status，但
  `isAnimating == false`。
- 零或不足 1ns 的 duration 同步收敛；负 duration 在 ticker 创建前拒绝。
- `NaN` 起点/赋值被拒绝，无穷值和有限越界值按 `0f..1f` clamp。
- 超大 frame delta 直接到达确切端点；repeat 使用取模/奇偶 leg，单帧跨多周期不丢余量。
- dispose 后的动画与赋值命令抛出 `IllegalStateException`，`stop()` / `dispose()` 仍保持幂等。

## 2. 隐式动画 retarget

旧 `TweenAnimationBuilder` 在 target 变化时可能沿用旧进度，或从新 Tween 声明的原始 begin 重启，
从而产生跳变。现在 builder 先记录最后一次真正 build 的值，把新 segment 的 `begin`
重定基到该值，再从零进度开始。

```kotlin
/** Builds a fresh tween for each declarative target. */
fun animatedWidth(
    targetWidth: Int,
    vsync: PixelTickerProvider,
): Widget {
    return TweenAnimationBuilder(
        tween = IntTween(begin = 0, end = targetWidth),
        duration = 400.milliseconds,
        vsync = vsync,
    ) { _, width ->
        SizedBox(width = width, height = 1)
    }
}
```

不要让多个正在运行的 builder 共享同一个 Tween 实例；builder 会拥有并在 retarget 时重定基
该实例。`AnimatedContainer`、`AnimatedPadding` 和 `AnimatedPositioned` 等声明式组件已遵循
同一连续性契约。

## 3. 零透明度契约

`Opacity(0f)` 和动画到精确零的 `AnimatedOpacity` 现在：

- 继续参与 layout；
- 保留 child Element/State；
- 不 paint；
- 不参与 hit test；
- 不导出 click/pager/list/scrollbar/refresh/text-input/slider target；
- 不导出 semantics。

任意大于零的有效 opacity 都保留交互与 semantics，即使 8-bit alpha 取整后像素仍看起来
是透明的。非有限 opacity 按零处理。

## 4. AnimatedSwitcher 的子树身份

`AnimatedSwitcher` 不再串行“淡出旧 child→换 child→淡入新 child”，而是在稳定 `Stack` 中同时
挂载 outgoing 和 incoming：

- runtime type 与 key 都相同时原地更新，不启动转场；
- type 或 key 任一不同时交叉淡化，两个子树同时 layout/paint；
- 快速连续替换保留所有仍有视觉贡献的 outgoing entry；
- 切回某个 outgoing type/key 时提升原 entry，保留其 State；
- 转场完成时只卸载 outgoing，incoming wrapper 不重挂载；
- 中途 dispose 释放所有子树、listener、ticker 和 pending frame。

如果旧业务依赖“切换期间只存在一个 child”的未文档化行为，应改为给子树稳定 key，并把不能
并行存活的业务资源所有权上移到 switcher 之外。

0% / 25% / 50% / 75% / 100% 帧同时验证精确 ARGB 像素、retained/render tree 与资源计数。
