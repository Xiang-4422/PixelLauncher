# pixel-engine 1.0.0 RouteEntry 导航迁移指南

## 影响范围

M2-1 把 `PixelNavigatorState` 的内部栈单位从可复用 `PixelRoute` 定义改为独立
`PixelRouteEntry<A, R>`，并新增 typed destination、参数、结果、entry-local state、生命周期、
observer、failure 和 inspection API。

原有 `PixelRoute`、`push(PixelRoute)`、`pop(Any?)`、`replace(PixelRoute)`、`currentRoute`、
`stack`、字符串 deep link 和 route-name snapshot 继续保留，可以渐进迁移。以下运行时行为已
明确为 entry 语义：

- 相同 `PixelRoute` 或 `PixelRouteDestination` 重复 push，每次都创建独立 entry ID、bucket、
  result channel 和 lifecycle。
- entry 先完成离栈、转场与 `onDispose`，再交付 result callback。
- `onDispose` 和 result delivery 都有 exactly-once guard。
- `maintainState` 控制真实 Stateful subtree 是否跨 inactive 阶段保留，不只是保存滚动值。

这次迁移没有删除 legacy API，但依赖“同一个 route 对象在多个栈位置共享状态”的代码必须修正；
共享是旧实现缺陷，不再支持。

## 概念迁移对照

| 旧模型 | RouteEntry 模型 | 迁移建议 |
|---|---|---|
| `PixelRoute` 同时被当作定义和栈位置 | `PixelRouteDestination<A, R>` 是定义，`PixelRouteEntry<A, R>` 是位置 | destination 可复用；需要身份时保存 push 返回的 entry |
| route name 区分页面实例 | `PixelRouteEntryId` 区分每次实例 | 不要把 destination ID 当 entry ID |
| builder 只接收 `BuildContext` | builder 接收 `BuildContext` 与 `PixelRouteEntryScope<A, R>` | 从 scope 读取参数、bucket，并 complete/cancel/replace |
| 参数由闭包、全局对象或字符串传递 | `PixelRouteRequest(destination, arguments)` | 为每个 destination 定义非空参数类型 `A : Any` |
| `(Any?) -> Unit` 同时表示值与取消 | `PixelRouteOutcome.Success<R>` / `Cancelled(reason)` | nullable 成功值与取消分支分别处理 |
| route 级临时 Map | `PixelRouteStateBucket` + `PixelRouteStateKey<T>` | key 声明为稳定属性；bucket 自动随 entry 清理 |
| `currentRoute` / `stack` | `currentEntry` / `entries` | 新代码使用真实 entry；旧属性仅是兼容投影 |
| `replace(PixelRoute)` 转移 slot callback | typed replace 取消旧 channel，并创建新 channel | 只有 legacy replace 继续转移 legacy callback |
| `PixelNavigatorSnapshot.routeNames` | `PixelNavigatorSnapshotCodec` + destination adapter | legacy restore 继续兼容；新代码迁移到 typed root 和版本化 bytes |

## 旧写法

```kotlin
/** Legacy detail route whose argument and result are not type checked. */
private val detailRoute = PixelRoute(
    name = "detail",
    builder = { Text("DETAIL") },
)

/** Opens the legacy route and receives either a value or cancellation as nullable Any. */
private fun openLegacyDetail(navigator: PixelNavigatorState) {
    navigator.push(detailRoute) { value ->
        // This callback cannot distinguish a successful null from cancellation.
        println("Legacy result: $value")
    }
}
```

## 新写法

```kotlin
/** Arguments captured by one concrete detail entry. */
private data class DetailArgs(
    /** Item identifier displayed by this detail entry. */
    val itemId: String,
)

/** Arguments captured by a replacement confirmation entry. */
private data class ConfirmationArgs(
    /** Item identifier whose edit should be confirmed. */
    val itemId: String,
)

/** Stable identity key for the draft owned by one concrete entry. */
private val detailDraftKey = PixelRouteStateKey<String>("detail.draft")

/** Replacement destination with the same String? result contract as detail. */
private val confirmationDestination: PixelRouteDestination<ConfirmationArgs, String?> =
    pixelRouteDestination(id = "confirmation") { _, scope ->
        Column(
            children = listOf(
                Text("CONFIRM ${scope.arguments.itemId}"),
                TextButton(
                    text = "CONFIRM",
                    onPressed = { scope.complete("confirmed") },
                ),
                TextButton(
                    text = "CANCEL",
                    onPressed = { scope.cancel() },
                ),
            ),
        )
    }

/** Reusable typed detail definition; requests create independent entries. */
private val detailDestination: PixelRouteDestination<DetailArgs, String?> =
    pixelRouteDestination(
        id = "detail",
        maintainState = true,
    ) { _, scope ->
        // The stable key reads only from this entry's isolated state bucket.
        val draft = scope.stateBucket.read(detailDraftKey).orEmpty()
        Column(
            children = listOf(
                Text("DETAIL ${scope.arguments.itemId}"),
                Text("DRAFT $draft"),
                TextButton(
                    text = "SAVE NULL",
                    onPressed = { scope.complete(null) },
                ),
                TextButton(
                    text = "REPLACE",
                    onPressed = {
                        // NextA changes, while the String? result type must remain unchanged.
                        val replacementRequest = PixelRouteRequest(
                            destination = confirmationDestination,
                            arguments = ConfirmationArgs(scope.arguments.itemId),
                        )
                        scope.replaceWith(replacementRequest) { outcome ->
                            println("Replacement outcome: $outcome")
                        }
                    },
                ),
            ),
        )
    }

/** Pushes one typed request and handles success and cancellation explicitly. */
private fun openTypedDetail(navigator: PixelNavigatorState) {
    // The request binds DetailArgs to the destination's String? result contract.
    val request = PixelRouteRequest(
        destination = detailDestination,
        arguments = DetailArgs(itemId = "item-42"),
    )
    // The returned handle refers to this exact stack entry, even after duplicate pushes.
    val entry: PixelRouteEntry<DetailArgs, String?> = navigator.push(request) { outcome ->
        when (outcome) {
            is PixelRouteOutcome.Success -> {
                // Success(null) reaches this branch and remains a successful completion.
                println("Typed success: ${outcome.value}")
            }
            is PixelRouteOutcome.Cancelled -> {
                // Cancellation identifies the operation that ended the entry.
                println("Typed cancellation: ${outcome.reason}")
            }
        }
    }
    println("Opened entry ${entry.id.value}")
}
```

`PixelRouteEntryScope.replaceWith` 的签名是
`PixelRouteRequest<NextA, R>`：replacement 可以接受另一种参数，但必须继续返回当前 entry 的
`R`。如果业务流程需要改变结果类型，应由持有 `PixelNavigatorState` 的上层明确结束旧 entry，
再 push 一个新请求，而不是在 scope 内偷换协议。

## Nullable success 与 cancellation

typed API 不把取消编码成 nullable value：

```kotlin
// A successful operation whose declared String? value is null.
val successfulNull: PixelRouteOutcome<String?> = PixelRouteOutcome.Success(null)

// An operation removed explicitly without producing a business value.
val cancellation: PixelRouteOutcome<String?> =
    PixelRouteOutcome.Cancelled(PixelRouteCancellationReason.Explicit)
```

legacy `push(route) { value -> ... }` 为兼容原有签名，会把所有 cancellation reason 映射为
`null`。只有迁移到 `PixelRouteOutcome` 后才能区分上述两种情况。

## 生命周期顺序

生命周期状态在 callback 执行前已经提交。entry result callback 一定晚于该 entry 的
`onDispose`。

| 场景 | outgoing entry | incoming / revealed entry | result 时机 |
|---|---|---|---|
| push | `Active -> Inactive -> onExit` | `Created -> Active -> onEnter` | 新 entry 继续 pending |
| complete / pop | `Active -> Removing -> onExit -> Disposed -> onDispose` | `Inactive -> Active -> onEnter` | 离场转场与 dispose 后 |
| typed replace | 旧 entry 按 Removing / Disposed 路径 | 新 entry `Created -> Active -> onEnter` | 旧 channel 收到 `Cancelled(Replaced)`；新 channel 独立 pending |
| remove inactive | `Inactive -> Removing -> Disposed -> onDispose`，不重复 exit | 当前 entry 不变 | 同步 dispose 后 |
| clear | root 以上 entry bottom-to-top dispose | root 恢复 Active / onEnter | 所有 entry dispose 后，再 bottom-to-top 交付 |
| host dispose | 既有 pending entry 保持队列顺序，仍在 stack 的 entry top-to-bottom dispose | 无 incoming entry | 所有 entry dispose 后，再按 finalization 队列顺序取消 pending channel |

动画离场期间 entry 保持 `Removing`。开始下一次 mutation 会先 settle 前一个转场；迟到的旧
transition completion 不会造成第二次 dispose 或第二次 result delivery。

## maintainState 迁移

| 设置 | 行为 |
|---|---|
| `maintainState = true` | inactive 真实 subtree 继续挂载并保持同一个 State；后台 wrapper 跳过 child layout/paint，不命中、不暴露给 finder；bucket 保留 |
| `maintainState = false` | 离场转场结束后卸载 subtree；进入 inactive 时 bucket 清空并停止 retention；再次 active 时重新创建 State |

无论设置为何值，entry 到达 `Disposed` 都会清空 bucket。`PixelRouteStateKey` 使用对象身份，
不是 name 相等性；不要在每次 build 中重新创建 key。

自定义 `PixelRouteTransitionBuilder` 的 `outgoing` / `incoming` 是 presentation widget 副本。
真实 maintained entry host 仍在原 keyed 位置挂载并隐藏。不要从 presentation 副本推断长期
State 身份，也不要把它们缓存到转场之外。

## 操作与结果对照

| API | 成功行为 | 被拒绝 / terminal outcome |
|---|---|---|
| `push(request)` | 新 ID、新参数快照、新 bucket、新 channel | Navigator 已 dispose 时失败 |
| `complete(entry, result)` | 仅 exact active entry 可走 `Success(result)` | stale / inactive entry 返回 false 并记录 failure |
| `cancel(entry, reason)` | 移除 active 或 inactive entry | 默认 `Cancelled(Explicit)`；最后一个 root 不可移除 |
| `replace(request)` | replacement 独立 pending | outgoing 为 `Cancelled(Replaced)` |
| `remove(entry/id)` | inactive 同步 settle，active 可动画 | `Cancelled(Removed)`；未知 ID / final root 返回 false |
| `clear()` | 保留 root，清理其上全部 entry | 每个 pending channel 为 `Cancelled(Cleared)`；只有 root 时返回 false |
| host unmount | 所有 entry exactly-once dispose | pending channel 为 `Cancelled(NavigatorDisposed)` |
| restore / deep link reset | 新建一组 legacy entry | 被替换 channel 为 `Cancelled(StackReset)` |

`pop()` 和 `complete(...)` 会先调用 destination 的 `canPop(entry)`；拒绝或 callback 异常时
保持 stack 不变。显式 `cancel`、`remove`、`replace` 和 `clear` 不经过 `canPop`。

legacy `replace(PixelRoute)` 是一个有意保留的例外：它把旧 stack slot 尚未投递的 legacy
callback 转给 replacement。旧 entry 仍使用新 ID 隔离模型销毁，其自身 channel 终结为
`Cancelled(Replaced)`；callback 在 replacement 退出时收到 replacement value，或在任何取消时
收到 null。typed replace 从不转移旧 callback。

## Observer、failure 与 inspection

- `PixelNavigationObserver` 接收带递增 sequence 的 immutable Started / Completed / Failed
  event；一个 observer 抛错不会阻断导航或后续 observer。
- `lastFailure` 保存最近的结构化 `PixelNavigationFailure`，覆盖 root pop、unknown entry、stale
  completion、lifecycle callback、result callback 和 observer callback 等失败。
- `inspectionSnapshot()` 提供 entry 顺序、destination ID、lifecycle、result state、maintain
  policy、state key name、transition 与 failure，不持有 arguments 或 widget。

这三类数据都只用于进程内日志、测试和 inspector，不是持久化协议，不应写入 Bundle、数据库或
远端状态。

## M2-2 后的兼容边界

- 旧 `PixelNavigator(initialRoute = PixelRoute(...))`、`snapshot()` 和 route-name Bundle helper
  继续存在；它们仍是 legacy 格式，不会自动编码 typed 参数。
- 需要进程恢复的新代码使用 `PixelNavigator.typed(...)`、`PixelRouteSnapshotAdapter` 和
  `PixelNavigatorSnapshotCodec`。完整步骤见
  [导航恢复、多返回栈与 Predictive Back 指南](1.0.0-navigation-restoration.md)。
- typed snapshot 恢复 entry ID、destination 参数和 adapter allowlist 中的局部状态；不恢复
  pending callback、Widget/State 对象、ticker 或 listener。
- typed deep link 使用 `PixelTypedDeepLinkResolver`；旧 resolver 仍返回 legacy route stack。
- destination `id` 只是 registry key。参数和状态仍必须由应用 codec 校验，不能只凭同名 ID
  反射恢复。
- entry ID 会在一次 snapshot 恢复后继续单调分配，但仍不是数据库主键或跨独立 Navigator 的
  全局 ID。
- `PixelNavigatorInspectionSnapshot` 仍只用于当前进程诊断，不能替代持久化 codec。

## 推荐迁移步骤

1. 为每个业务目的地定义明确的参数类型 `A : Any` 与结果类型 `R`。
2. 用 `pixelRouteDestination<A, R>` 提取可复用 destination；把 builder 闭包参数迁到
   `scope.arguments`。
3. 把 route 局部内存值迁到稳定 `PixelRouteStateKey<T>` 与 entry 的 `stateBucket`。
4. 把 `push(PixelRoute)` 调用改成 `push(PixelRouteRequest(...))`，保存返回 entry 处理精确
   complete / cancel / remove。
5. 把 nullable callback 分成 `Success` 与 `Cancelled` 两个分支；逐一处理 cancellation reason。
6. 明确每个 destination 的 `maintainState`，为 Stateful subtree 保留或重建行为补测试。
7. 把需要进程恢复的 root 改为 `PixelNavigator.typed`，为 destination 注册参数/状态 adapter；
   再迁移 typed deep link、多栈 Bundle 和 predictive back。不要混用 inspection DTO。
