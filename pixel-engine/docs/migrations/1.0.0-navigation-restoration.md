# pixel-engine 1.0.0 导航恢复、多返回栈与 Predictive Back 迁移指南

## 范围

M2-2 在 RouteEntry 模型上补齐以下正式能力：

- `PixelNavigator.typed(...)`：可持久化的 typed root。
- `PixelNavigatorSnapshotCodec`：带 outer schema、checksum 和尺寸边界的 entry snapshot。
- `PixelRouteSnapshotAdapter<A, R>`：destination 自己负责参数和允许恢复的局部状态。
- `PixelTypedDeepLinkResolver`：URI matcher 与 typed argument decoder 绑定。
- `PixelNestedNavigator.typed(...)`、`PixelNestedNavigatorController`、
  `PixelMultiStackNavigator` 和 `PixelTypedNavigatorStack`。
- `PixelBackDispatcher` / `PixelHostView` 的 predictive back start、progress、cancel、commit。

旧 `PixelRoute`、route-name `PixelNavigatorSnapshot` 和 `PixelDeepLinkResolver` 继续保留。它们是
兼容入口，不会自动变成 typed snapshot，也不能恢复任意闭包或对象。

## 1. 使用 typed root

版本化 snapshot 只允许显式注册的 typed destination。不要以 legacy `PixelRoute` 作为需要进程
恢复的 root：

```kotlin
/** Route arguments whose wire representation is owned by the application. */
data class ArticleArgs(
    /** Stable article identifier. */
    val articleId: String,
)

/** Typed root and child destination reused across process recreation. */
val articleDestination: PixelRouteDestination<ArticleArgs, Unit> =
    pixelRouteDestination(id = "article") { _, scope ->
        Text("ARTICLE ${scope.arguments.articleId}")
    }

/** Creates a Navigator whose first entry is typed and therefore persistable. */
fun buildNavigator(vsync: PixelTickerProvider): PixelNavigator {
    return PixelNavigator.typed(
        initialRequest = PixelRouteRequest(
            destination = articleDestination,
            arguments = ArticleArgs("home"),
        ),
        vsync = vsync,
    )
}
```

`PixelNavigator.typed` 返回的仍是同一个 `PixelNavigator` JVM 类型；旧构造器和旧二进制消费者
不变。

多栈声明的共同基类是 `PixelNavigatorStackDefinition`：legacy root 使用
`PixelNavigatorStack`，需要进程恢复的 typed root 使用 `PixelTypedNavigatorStack<A, R>`。应用通常
不需要自行实现这个 sealed 类型。

## 2. 参数 codec 与 destination adapter

引擎不会反射序列化参数，也不会把整个 `PixelRouteStateBucket` 写入 Bundle。每个 destination
必须用 adapter 声明自己的 wire schema、校验和迁移：

```kotlin
/** Versioned UTF-8 codec for ArticleArgs. */
object ArticleArgsCodec : PixelRoutePayloadCodec<ArticleArgs> {
    /** Current payload schema emitted by encode. */
    override val schemaVersion: Int = 2

    /** Encodes only the stable article identifier. */
    override fun encode(value: ArticleArgs): ByteArray {
        require(value.articleId.isNotBlank())
        return value.articleId.encodeToByteArray()
    }

    /** Decodes current bytes and explicitly migrates schema 1. */
    override fun decode(
        schemaVersion: Int,
        payload: ByteArray,
    ): PixelRoutePayloadDecodeResult<ArticleArgs> {
        val articleId = payload.decodeToString()
        return when {
            schemaVersion !in 1..2 -> PixelRoutePayloadRejected(
                "Unsupported article argument schema $schemaVersion",
            )
            articleId.isBlank() -> PixelRoutePayloadRejected("Article id is blank")
            else -> PixelRoutePayloadDecoded(ArticleArgs(articleId))
        }
    }
}

/** In-memory key; it is not persistent unless the adapter explicitly includes it. */
val readingPositionKey = PixelRouteStateKey<Int>("article.readingPosition")

/** Allowlist adapter for arguments and one route-local state value. */
class ArticleSnapshotAdapter(
    /** Exact destination instance used in the current process. */
    destination: PixelRouteDestination<ArticleArgs, Unit>,
) : PixelRouteSnapshotAdapter<ArticleArgs, Unit>(destination, ArticleArgsCodec) {
    /** Current route-local payload schema. */
    override val stateSchemaVersion: Int = 1

    /** Captures only the approved reading position. */
    override fun encodeRouteState(
        entry: PixelRouteEntry<ArticleArgs, Unit>,
    ): Map<String, ByteArray> {
        val position = entry.stateBucket.read(readingPositionKey) ?: return emptyMap()
        return mapOf("position" to position.toString().encodeToByteArray())
    }

    /** Validates bytes before returning a detached bucket restorer. */
    override fun decodeRouteState(
        schemaVersion: Int,
        payloads: Map<String, ByteArray>,
    ): PixelRouteStateDecodeResult {
        if (schemaVersion != stateSchemaVersion) {
            return PixelRouteStateRejected("Unsupported reading-position schema")
        }
        if (payloads.isEmpty()) return PixelRouteStateDecoded(PixelRouteStateRestorer { })
        if (payloads.keys != setOf("position")) {
            return PixelRouteStateRejected("Unknown article state key")
        }
        val position = payloads.getValue("position").decodeToString().toIntOrNull()
            ?: return PixelRouteStateRejected("Reading position is invalid")
        return PixelRouteStateDecoded(
            PixelRouteStateRestorer { bucket -> bucket.write(readingPositionKey, position) },
        )
    }
}
```

Registry 使用稳定 destination ID 做查找，但编码当前进程时还会检查 destination 实例与 adapter
一致，避免同名实现被误写。进程重建后可以用新的 destination / adapter 实例，只要 ID 和迁移
协议一致。

## 3. 保存和恢复单栈

```kotlin
/** Explicit allowlist used by both save and restore. */
val registry = PixelRouteSnapshotRegistry(
    listOf(ArticleSnapshotAdapter(articleDestination)),
)

/** Saves a complete typed stack into Activity state. */
fun saveNavigator(
    navigator: PixelNavigatorState,
    outState: Bundle,
) {
    when (val result = navigator.savePersistentSnapshotToBundle(outState, registry)) {
        is PixelNavigatorSnapshotEncoded -> Unit
        is PixelNavigatorSnapshotEncodeRejected -> {
            error("Navigator snapshot rejected: ${result.failure}")
        }
    }
}

/** Restores after the recreated typed Navigator has mounted. */
fun restoreNavigator(
    navigator: PixelNavigatorState,
    savedInstanceState: Bundle?,
) {
    when (val result = navigator.restorePersistentSnapshotFromBundle(savedInstanceState, registry)) {
        null -> Unit // No saved snapshot.
        is PixelNavigatorSnapshotDecoded -> Unit
        is PixelNavigatorSnapshotDecodeRejected -> {
            // Keep the already mounted safe typed root and report the structured failure.
            println("Navigator restore rejected: ${result.failure}")
        }
    }
}
```

成功恢复保留：

- root-to-foreground entry 顺序和当前 entry；
- 每个 `PixelRouteEntryId`；
- destination 参数；
- adapter 明确允许的 route-local state；
- `Inactive` / `Active` 的栈位置语义。

恢复不会保留 pending result callback、Widget / State 对象、ticker、listener 或任意未允许的 bucket
值。进程死亡后调用栈已经不存在，伪造旧 callback 比取消它更危险。

Codec 当前 outer schema 为 `PixelNavigatorPersistentSnapshotSchemaVersion == 2`，可迁移 schema 1。
未知 destination、未来 schema、重复 ID、checksum 错误、截断或超限输入全部返回 `Rejected`，不会
局部替换 live stack。每个 snapshot 最大 1 MiB、最多 128 entries，并对子字段继续设限。

## 4. 多返回栈和嵌套 Navigator

底部导航使用 `PixelMultiStackNavigator`。所有 child Navigator 始终挂载；inactive stack 不绘制、
不命中、不导出 semantics、不出现在 finder 中，也不会收到 back：

```kotlin
/** Controller keeps active tab and each mounted child state. */
val tabs = PixelMultiStackNavigatorController(initialStackId = "home")

/** Builds two typed, persistable tab roots. */
fun buildTabs(vsync: PixelTickerProvider): PixelMultiStackNavigator {
    return PixelMultiStackNavigator(
        stacks = listOf(
            PixelTypedNavigatorStack(
                id = "home",
                initialRequest = PixelRouteRequest(articleDestination, ArticleArgs("home")),
            ),
            PixelTypedNavigatorStack(
                id = "saved",
                initialRequest = PixelRouteRequest(articleDestination, ArticleArgs("saved")),
            ),
        ),
        controller = tabs,
        vsync = vsync,
    )
}
```

`selectStack(id)` 不清理旧栈；`popToRootOnReselect=true` 明确实现重复点击 tab 回根页。secondary
stack 在 root 收到 back 时先切回 initial stack，initial root 再把 back 交给外层 Host。

多栈进程恢复会先对全部 child bytes 解码，再安装 plan，避免一个损坏 tab 被静默跳过：

```kotlin
/** Registry is independent for each child stack namespace. */
val tabRegistries = mapOf(
    "home" to registry,
    "saved" to registry,
)

/** Captures child stacks and active selection, then writes one outer Bundle envelope. */
fun saveTabs(outState: Bundle) {
    val encoded = tabs.persistentSnapshot(tabRegistries)
        as? PixelMultiStackSnapshotEncoded ?: return
    encoded.snapshot.saveToBundle(outState)
}

/** Restores only after all recreated child Navigators have mounted. */
fun restoreTabs(savedState: Bundle?) {
    val decoded = savedState?.getPixelMultiStackSnapshot()
        as? PixelMultiStackSnapshotDecoded ?: return
    tabs.restorePersistentSnapshot(decoded.snapshot, tabRegistries)
}
```

多栈 API 不用异常表达可预期的持久化失败。捕获返回
`PixelMultiStackSnapshotEncodeResult`（成功分支 `PixelMultiStackSnapshotEncoded`，失败分支
`PixelMultiStackSnapshotEncodeRejected`）；Bundle 读取返回
`PixelMultiStackSnapshotDecodeResult`（`PixelMultiStackSnapshotDecoded` 或
`PixelMultiStackSnapshotDecodeRejected`）；原子恢复返回 `PixelMultiStackRestoreResult`
（`PixelMultiStackRestored` 或 `PixelMultiStackRestoreRejected`）。所有拒绝分支都携带
`PixelMultiStackSnapshotFailure`，并通过 `PixelMultiStackSnapshotFailureReason` 提供稳定、可测试的
失败分类；拒绝不会留下部分恢复的 child stack。

legacy 嵌套页面继续使用原 `PixelNestedNavigator(...)` 构造器。需要进程恢复时，改用 additive 的
`PixelNestedNavigator.typed(...)` 与 `PixelNestedNavigatorController`；旧构造器、属性及 JVM 描述符
没有变化：

```kotlin
/** Single-host controller owned by the surrounding maintained feature route. */
val nestedController = PixelNestedNavigatorController()

/** Builds a typed nested host and gates its back bridge with the concrete outer entry. */
fun buildNested(
    vsync: PixelTickerProvider,
    outerEntry: PixelRouteEntry<*, *>,
): PixelNestedNavigator {
    return PixelNestedNavigator.typed(
        initialRequest = PixelRouteRequest(
            destination = articleDestination,
            arguments = ArticleArgs("nested-root"),
        ),
        controller = nestedController,
        vsync = vsync,
        parentEntry = outerEntry,
    )
}

/** Captures the nested stack only after its host has mounted. */
fun captureNested(): PixelNavigatorSnapshotEncodeResult {
    return nestedController.persistentSnapshot(registry)
}

/** Restores versioned bytes only after the recreated typed nested host has mounted. */
fun restoreNested(bytes: ByteArray): PixelNavigatorSnapshotDecodeResult {
    return nestedController.restorePersistentSnapshot(bytes, registry)
}
```

Controller 挂载后通过 `navigatorState` 暴露准确的 child state，并直接复用单栈的版本化 codec，因而
恢复同样保留 entry ID、typed arguments 与 adapter 明确允许的 local state。一个 controller 同时只能
属于一个 host；第二个 host 会立即失败，避免 capture/restore 指向不确定的子树。host dispose 后
`isAttached == false` 且 `navigatorState == null`，controller 不会泄漏已销毁的 entry 或 Widget State。

若嵌套 host 位于 maintained route 内，必须传入该 route 的 `parentEntry`（typed builder 中通常就是
`scope.entry`）。parent inactive 时 nested back bridge 会禁用，隐藏子树不能抢走当前页面的离散或
predictive back；parent 再次 active 后原有 nested stack 与 back 能力继续生效。

## 5. 类型安全 Deep Link

Matcher 只决定 URI 属于哪个 destination；decoder 再区分缺失和非法参数。匹配后解码失败不会
继续尝试另一个 route，也不会改变 stack：

```kotlin
/** One legal typed deep-link route for ArticleArgs. */
val articleLink = PixelTypedDeepLinkRoute(
    destination = articleDestination,
    matcher = PixelTypedDeepLinkMatcher { link ->
        link.scheme == "pixel" && link.host == "app" &&
            link.pathSegments == listOf("article")
    },
    argumentDecoder = PixelDeepLinkArgumentDecoder { link ->
        val id = link.queryParameter("id")
            ?: return@PixelDeepLinkArgumentDecoder PixelDeepLinkDecodeRejected(
                PixelDeepLinkArgumentFailure(
                    reason = PixelDeepLinkArgumentFailureReason.Missing,
                    parameterName = "id",
                    message = "Article link requires id",
                ),
            )
        if (id.isBlank()) {
            PixelDeepLinkDecodeRejected(
                PixelDeepLinkArgumentFailure(
                    reason = PixelDeepLinkArgumentFailureReason.Invalid,
                    parameterName = "id",
                    rawValue = id,
                    message = "Article id is blank",
                ),
            )
        } else {
            PixelDeepLinkDecoded(ArticleArgs(id))
        }
    },
)

/** Applies valid links as DeepLink observer actions. */
val result = navigator.handleTypedDeepLink(
    uri = "pixel://app/article?id=42",
    resolver = PixelTypedDeepLinkResolver(listOf(articleLink)),
)
```

参数 decoder 的完整返回类型是 `PixelDeepLinkDecodeResult<A>`，其成功/失败分支分别是
`PixelDeepLinkDecoded<A>` 与 `PixelDeepLinkDecodeRejected`。导航调用的完整返回类型是
`PixelTypedDeepLinkResult`，调用方应显式处理成功、未匹配和拒绝分支，避免把非法 URI 当成已导航。

结果是 `PixelTypedDeepLinkNavigated`、`NotMatched` 或带
`MalformedUri / MissingArgument / InvalidArgument / ResolverFailure` 的 `Rejected`。多栈版本先向指定
stack 导航，只有成功后才切换 active stack。

## 6. Predictive Back

`PixelHostView` 默认自动接入：

| Android | 行为 |
|---|---|
| API 24–32 | Activity 继续调用 `handleBackPressed()` |
| API 33 | `OnBackInvokedCallback`，只有离散 commit |
| API 34+ | `OnBackAnimationCallback`，完整 start / progress / cancel / commit |

Host 只在文本输入、widget handler 或 app fallback 存在时注册平台 callback，root 页面不会无条件
吞掉系统返回。手势 start / progress 只更新 Navigator presentation；cancel 不改变 entry 生命周期、
stack 或 pending result；commit 才移除 entry，并返回 `Cancelled(Back)`。typed back 不复用 legacy
`pop() == Success(null)`。

自定义 Host 可调用：

- `handlePredictiveBackStarted(event)`
- `handlePredictiveBackProgressed(event)`
- `handlePredictiveBackCancelled()`
- `handlePredictiveBackCommitted()`

`PixelPredictiveBackEvent.progress` 必须是有限的 `0f..1f`。同一 session 的进度可以非单调变化；
Navigator 直接用最新进度绘制，不在 commit 后重播一条新的定时动画。并发导航会使旧 session 的
迟到 commit 失效。
