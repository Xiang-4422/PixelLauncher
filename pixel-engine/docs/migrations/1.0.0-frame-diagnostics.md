# 1.0.0 完整帧诊断迁移指南

## 适用范围

本指南面向使用 `PixelHostView.frameStatsObserver`、自定义性能面板、benchmark 或 Inspector 的
消费者。旧 API 没有删除；迁移的目的，是停止把一个粗粒度 `paintTimeNanos` 当作完整瓶颈归因。

## 兼容入口变化

`PixelHostFrameStats` 的构造器、属性和 observer JVM 描述符保持不变。它的
`paintTimeNanos` 现在从 Host `onDraw` 入口计时到真实 Canvas 提交完成，因此不再遗漏
`drawBuffer`；它仍只适合兼容 FPS/整体 draw 展示，不能区分 build、layout、engine paint 和
Android submit。

## 新的稳定模型

- `PixelFrameTimings`：互斥的 build、layout、paint、buffer submit、Android draw、total 和
  unattributed 时间。
- `PixelFrameWorkload`：dirty Element/RenderObject、paint/submit 逻辑像素、进程 allocation/GC
  delta、buffer pool hit/miss 与完整 render cache hit。
- `PixelFrameDropReason`：BUILD、LAYOUT、PAINT、BUFFER_SUBMIT、ANDROID_DRAW、
  GARBAGE_COLLECTION、FRAME_SCHEDULER 或 UNATTRIBUTED。
- `PixelHostFrameDiagnostics`：帧号、start interval、refresh-rate budget、timing、workload、原因和
  missed vsync 数量。

所有计数和时间必须非负；五个互斥 phase 加 `unattributedNanos` 必须等于 total；只有
`missedVsyncCount > 0` 时才允许非空 drop reason。无效的消费者构造会立即抛
`IllegalArgumentException`，避免把损坏数据带入报告。

## 启用和关闭

```kotlin
hostView.frameDiagnosticsObserver = { frame ->
    report(frame)
}

// 诊断结束后恢复默认 release 路径。
hostView.frameDiagnosticsObserver = null
hostView.frameDiagnosticsEnabled = false
```

非空 observer 会隐式启用采样。只需要 Inspector 拉取、不要每帧 callback 时，设置
`frameDiagnosticsEnabled = true`，然后读取 `latestFrameDiagnostics` 或
`inspect().frameDiagnostics`。

observer 在 Android UI 线程、`onDraw` 末尾同步调用。不要在 callback 中执行 IO、sleep、锁等待、
递归 `draw` 或直接更新会触发新 build 的状态；需要持久化或聚合时先复制 immutable snapshot，再
交给后台执行器。

## 指标边界

- build：`BuildOwner.renderPass` 的 reconcile 和 dirty queue 排空。
- layout：`RenderObject.layout`。
- paint：buffer acquire、RenderObject paint、lifted overlay、target/semantics 导出。
- buffer submit：no-gap 的 `Bitmap.setPixels + Canvas.drawBitmap`，或 gap 路径的逐格 Canvas 绘制，
  以及 bezel overlay。
- Android draw：submit 之外的 View/background/accessibility 工作。
- total：`onDraw` 入口到 terminal ART sample；不包含 snapshot 构造和消费者 callback。

allocation/GC 来自 `Debug.getRuntimeStat` 的进程级累计值边界差，并非 UI 线程独占值。某些运行时
不公开对应 key 时字段为 null，消费者不得把 null 当作零。首帧 `frameIntervalNanos` 为零；后续预算
来自 Host capability refresh rate，无有效值时回退 60 Hz。

## 成本与验收

默认 `frameDiagnosticsEnabled` 为 false 且 observer 为 null：Host 不读取 ART counter、不遍历
dirty subtree、不读取 buffer pool stats、不创建完整诊断 snapshot。启用时每帧有固定的 clock read、
两个 ART boundary sample 和小型 immutable snapshot 成本，因此它是 debug/benchmark 能力，不应在
普通 release UI 中永久打开。

SDK 自测必须同时证明：

1. 人工拉长任一互斥 phase 时，drop reason 指向该 phase。
2. 真实 API 24/37 Canvas 路径的 `bufferSubmitNanos > 0`。
3. cache-hit 帧 `paintedPixelCount == 0`，但 `submittedPixelCount > 0`。
4. 关闭诊断后不产生新 snapshot，也不调用 ART sampler。
5. Kotlin/Java 外部消费者能从隔离 Maven POM/AAR 构造并读取完整模型。
