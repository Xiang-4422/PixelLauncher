# pixel-engine 1.0.0 Unicode 文本编辑迁移指南

## 影响范围

1.0.0 把 TextField 的用户可见编辑边界从 UTF-16 `Char` 固定为 Unicode 17.0.0
extended grapheme cluster，同时继续使用 Android 兼容的 UTF-16 offset 公开
selection、composition 和 Accessibility 范围。

这次迁移覆盖 Controller、saved state、剪贴板、选词、方向移动、前后删除、点击/拖动
selection、`PixelTester`、Accessibility 和 Android `InputConnection`。它不会对文本执行 NFC、
NFD 或大小写变换，消费者写入的原始 UTF-16 文本会逐 code unit 保留。

本指南只说明编辑/IME 迁移；后续 code-point 字体、cluster paragraph 和固定 Unicode 17 Bidi
契约已经由独立迁移完成，见
[code-point 字体、cluster 段落与 Bidi 迁移指南](1.0.0-codepoint-cluster-bidi-text.md)。编辑安全、
Bidi 视觉排序和真实 glyph/shaping 覆盖仍是三个独立能力；内置字体不承诺绘制所有 emoji、Indic
或 Arabic cluster。

## 固定索引模型

| 层级 | 1.0 契约 |
|---|---|
| selection / composition / Accessibility | UTF-16 offset，与 Android API 一致 |
| 字符解码和后续 glyph key | Unicode code point `Int` |
| 光标、删除、选择和用户可见编辑 | extended grapheme cluster |
| Unicode 数据 | 引擎固定 Unicode 17.0.0、UAX #29 revision 47 |

`PixelGraphemeBoundaryMap` 是平台中立的边界权威，不调用 Android ICU，也不会因设备 API
版本改变行为：

```kotlin
/** Selects the complete grapheme intersected by one Android UTF-16 range. */
fun stableSelection(text: String, start: Int, end: Int): PixelUtf16Range {
    /** Immutable Unicode 17 boundary authority for the exact source text. */
    val boundaries = PixelGraphemeBoundaryMap(text)
    return boundaries.expand(start, end)
}
```

边界规则固定如下：

- 非空范围通过 `floor(start)` / `ceil(end)` 向外扩展；
- 折叠 caret 使用 `nearest`，距离相同时选择更大的 UTF-16 offset；
- `previous` / `next` 是严格移动，已经位于边界时移动一个完整 cluster；
- 范围查询会 clamp 到 `0..text.length`；
- Controller 的历史倒序范围继续折叠在 start 附近；Android InputConnection 和
  Accessibility 的倒序参数先排序，再向外扩展；
- CRLF、Hangul、Extend、SpacingMark、Prepend、variation selector、emoji modifier、ZWJ
  extended-pictographic、RI 奇偶和 keycap 按 Unicode 17 默认扩展字素规则处理。

## TextField 行为变化

以下操作现在共享同一边界图：

- `setSelection`、`updateComposition`、`selectWordAt`、saved-state restore；
- `replaceSelection`、paste、cut、backward/forward delete；
- `moveCaretBackward` / `moveCaretForward`，包括连续 Shift 扩选锚点；
- tap caret、drag selection handle 和 Accessibility `ACTION_SET_SELECTION`；
- `PixelTester.composeText`、`updateComposition`、`performTextEditAction` 和 `pressText`。

例如 `e\u0301`、`😀`、`👍🏽`、family ZWJ、keycap、国旗和 CRLF 都只能整体移动、选择或删除。
范围规范化只改变 offset，不会把 `e\u0301` 改写为预组字符 `é`。

已有状态中出现的非配对 surrogate 会被保留为一个隔离的恢复单元，避免升级时静默改写数据；
新的 IME commit/composition 不允许引入非配对 surrogate。Android
`deleteSurroundingTextInCodePoints` 在请求路径遇到非配对 surrogate 时按平台严格契约 no-op，
不会删除半个未知字符。

## Android InputConnection

默认 `PixelTextInputBridge` 现在创建 engine-owned 隐藏编辑器，并包装平台 InputConnection：

- selection-only 和 composition-only 更新会回写 retained TextField；
- `commitText`、`setComposingText/Region`、UTF-16/code-point surrounding delete、
  `setSelection`、硬件方向/删除键和 API 34 `replaceText` 都经过 grapheme guard；
- begin/end batch 只按平台实际接受的 nesting 合并 callback；
- target 切换、`restartInput`、blur 和 `closeConnection` 会淘汰旧 generation；
- 同一隐藏编辑器在 TextField A → B → A 复用时，旧连接不能修改新目标；
- Host rebind 不会覆盖尚未发布的平台 batch，真实并发 Host 更新在外层 batch 结束时获胜。

显式传给 `PixelTextInputBridge` 的普通自定义 `EditText` 仍是兼容路径，但它不能提供完整保证：
SDK 无法包装任意子类的 InputConnection，也不能可靠观察 selection-only 或
composition-only 变化。需要 1.0 完整契约时应使用默认编辑器。

自定义 Host bridge 如果需要保存 composition，应实现 additive
`PixelTextEditingHostBridge`：

```kotlin
/** Host adapter that accepts the complete editing value without changing the frozen request ABI. */
class FullEditingBridge : PixelTextEditingHostBridge {
    /** Most recent editing value owned by this sample Host session. */
    private var currentValue: PixelTextEditingValue? = null

    /** Starts one platform editor session from the complete value. */
    override fun showTextEditing(
        request: PixelTextInputRequest,
        value: PixelTextEditingValue,
    ) {
        currentValue = value
    }

    /** Updates selection/composition without forcing a new session. */
    override fun updateTextEditing(
        request: PixelTextInputRequest,
        value: PixelTextEditingValue,
    ) {
        currentValue = value
    }

    /** Preserves the frozen compatibility entry point for older callers. */
    override fun showTextInput(request: PixelTextInputRequest) {
        showTextEditing(
            request,
            PixelTextEditingValue(request.text, request.selectionStart, request.selectionEnd),
        )
    }

    /** Retires this sample's current editor value. */
    override fun hideTextInput() {
        currentValue = null
    }

    /** Sample Host does not provide native haptics. */
    override fun performHapticFeedback(type: PixelHapticType): Unit = Unit

    /** Sample Host schedules frames elsewhere. */
    override fun requestFrame(): Unit = Unit

    /** Sample Host has no typed system-action integration. */
    override fun dispatchSystemAction(action: PixelSystemAction): Unit = Unit
}
```

旧 `PixelHostBridge` 实现无需新增抽象方法，仍只接收冻结的八字段
`PixelTextInputRequest`。这条路径不能承诺 composition 跨 Host 同步。

## 补充平面文本输入

`PixelKeyEvent.character: Char?` 保留给旧版单 BMP 字符。新增 `PixelTextInputEvent(text)`、
`Focus(onTextInput = ...)`、`PixelHostView.dispatchPixelTextInput` 和 `PixelTester.pressText`，让
supplementary code point、完整 grapheme 或多 code-point IME commit 保持一个 String payload：

```kotlin
/** Handles one exact text payload before the legacy single-Char fallback. */
fun exactTextFocus(onText: (String) -> Unit): Widget {
    return Focus(
        child = Text("INPUT"),
        onTextInput = { event ->
            onText(event.text)
            true
        },
    )
}
```

未消费的 payload 只有在恰好包含一个非 surrogate BMP 字符时才会回退到旧
`PixelKey.CHARACTER` 路径；supplementary 或多字符 payload 不会被拆成两个 surrogate 事件。

## 迁移检查清单

1. 不要把 selection/composition offset 当作 code-point 或 grapheme 数量；它们仍是 UTF-16。
2. 不要用 `String[index]` 实现用户可见删除、移动或截断；使用
   `PixelGraphemeBoundaryMap` 或 TextField Controller。
3. 自定义 Host 需要 composition 时实现 `PixelTextEditingHostBridge`。
4. 自定义 Android 输入层不要替换默认 `PixelTextInputBridge.inputView`，除非接受弱兼容边界。
5. 测试 supplementary 或多 code-point 输入时使用 `pressText`，不要把 surrogate 强塞进
   `PixelKeyEvent.character`。
6. 对 decomposed Latin、emoji modifier、ZWJ family、keycap、RI flag、CRLF 和 malformed legacy
   UTF-16 建立业务回归。
7. 不要因为编辑安全或 Bidi 排序就声明某个 cluster 的字形已受支持；按独立字体/Bidi 迁移指南
   实现 `PixelClusterTextRasterizer` 并验证真实原子绘制。
