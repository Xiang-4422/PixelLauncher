# 0.1.0-SNAPSHOT 真实 RenderObject SPI 迁移指南

## 影响范围

本次变更影响 `com.purride.pixelui.advanced` 下的 RenderObject、RenderObjectWidget、布局值、
绘制上下文、命中结果和 child 协议。旧实现使用 Kotlin `typealias` 指向
`com.purride.pixelui.internal.*`；新实现为同名真实公共类型，并由 internal adapter 接入
retained 管线。

- 使用 `advanced.Pixel*` 名称的源码：重新编译后保持兼容。
- 使用旧 snapshot 编译且未重新编译的 class：二进制描述符不同，不属于兼容承诺。
- 直接 import `com.purride.pixelui.internal.*` 的源码：不受支持，必须迁移。
- 从首个真实 SPI AAR 与其 SHA-256 baseline 开始，稳定 SPI 进入持续二进制保护。

## 破坏性变更

### typealias 被真实公共类型替代

旧源码表面写法如下，但生成的 class 实际继承 internal 类型：

```kotlin
import com.purride.pixelui.advanced.PixelRenderBox

/** 旧 snapshot 中表面使用公开名称、字节码却引用 internal 的渲染对象。 */
private abstract class OldSnapshotRenderObject : PixelRenderBox()
```

新源码继续使用相同 import；重新编译后，父类和方法描述符会指向真实的
`com.purride.pixelui.advanced.PixelRenderBox`：

```kotlin
import com.purride.pixelui.advanced.PixelRenderBox

/** 重新编译后只依赖真实公共 SPI 的渲染对象。 */
private abstract class RecompiledRenderObject : PixelRenderBox()
```

迁移步骤：

1. 删除消费者工程中旧 snapshot 产生的 build、Gradle build cache 和已发布的本地可变
   snapshot 缓存。
2. 确认代码只 import `com.purride.pixelui.advanced.Pixel*`，不得 import
   `com.purride.pixelui.internal.*`。
3. 重新解析当前 AAR，并完整重新编译消费者模块及其测试。
4. single-child、multi-child、hit-test 或 `bufferPool` 使用点增加最小范围的
   `@OptIn(PixelExperimentalApi::class)`。
5. 运行消费者行为测试，并扫描 class 常量池，确认不存在
   `com/purride/pixelui/internal/`。

当前仓库保留旧 internal JVM 类型作为尽力而为的过渡壳，只用于降低内部 snapshot
迁移风险。它们不属于 stable API，不得继续编译新的消费者依赖。
