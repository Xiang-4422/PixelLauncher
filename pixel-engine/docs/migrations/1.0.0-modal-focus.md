# 1.0.0 模态焦点与背景隔离迁移

1.0.0 为 Dialog、Menu 和 Popover 建立了生产级的模态焦点基础。该变更只处理焦点、键盘关闭、
背景 interaction/semantics 隔离和退出动画的逻辑所有权；anchor 定位、边缘翻转、SafeArea、IME
避让和统一 OverlayEntry 生命周期由后续完成的
[生产级 Overlay 迁移](1.0.0-production-overlay.md) 定义。

## 默认行为变化

- `Dialog`、`Menu` 和 `Popover` 默认是模态层。
- 打开时，焦点优先使用后代 `autofocus`，否则进入第一个 enabled 控件。
- Tab、Shift+Tab 和方向键不会移动到背景；Escape/Back 调用当前最上层的 dismiss callback。
- 逻辑关闭时立即恢复 opener；退出 fade 只保留像素绘制。
- active modal 之外的 pointer、scroll、TextField、Slider 和 semantics targets 不再导出。
- `Tooltip` 始终非模态，不改变当前焦点和背景可访问性。
- 每个 `PixelHostView` / `PixelTester` 拥有独立 focus owner；销毁或操作一个 Host 不会清除另一个。
- 标准控件自动加入焦点顺序；disabled 控件跳过，应用 `Focus.onKeyEvent` 先于组件默认动作。

## 非模态 Popover

只用于补充信息、且不应阻止页面操作的 Popover 需要显式关闭模态行为：

```kotlin
Popover(
    anchor = HelpButton(),
    content = HelpPreview(),
    expanded = helpVisible,
    modal = false,
)
```

标准 `Tooltip` 已自动使用该配置。

## Menu 与外层 modal 的组合

默认 `Menu` 直接作为 `Popover.content` 时会自动复用 Popover 的 modal token，无需手动配置：

```kotlin
Popover(
    anchor = MenuAnchor(),
    content = Menu(
        items = actions,
        onDismissRequest = { menuOpen = false },
    ),
    expanded = menuOpen,
    onDismiss = { menuOpen = false },
)
```

标准 `Dropdown` 同样只持有一个 token。Menu 位于 Dialog 内部但代表新一层临时窗口时，则保留
默认 `modal = true`：它会成为 Dialog 上方的独立焦点域，关闭后恢复 Dialog 内的 opener。
只有业务自建了框架无法识别的 modal presentation 时，才显式传 `Menu(modal = false)` 让外层统一
管理焦点、Back 和背景隔离。

## 关闭与退出动画

受控组件必须在 dismiss callback 中更新 `expanded` 或移除 Dialog。只有逻辑状态真正关闭后，
框架才会弹出 modal token、恢复 opener 并重新导出背景 targets。视觉退出可以继续运行，但退出
子树不会重新获得焦点、IME、点击或 semantics。

如果 opener 在弹层打开期间被删除或禁用，框架会回退到原 scope 的第一个有效节点；没有有效
节点时清除 focus。这一行为不应由业务通过延时 `requestFocus` 覆盖。

节点从 Host runtime 卸载后，直接调用旧节点的 `requestFocus()` 会返回 `false`；只有把它重新
挂载进一个有效 focus scope 后才能再次请求焦点。该规则防止退出动画或异步回调把旧弹层节点
迁移到兼容用的全局 detached focus tree。

## 键盘、DPAD 与 IME 优先级

同一个 Host 内的分发顺序固定为：最上层 modal 的 Escape/Back、当前焦点到祖先的应用快捷键、
标准组件默认动作、最后是 Tab/Shift+Tab/方向遍历。Button 类控件用 Enter/Space 激活；Slider、
ValueAdjuster、Tabs 和 SegmentedControl 使用方向键。Android DPAD、游戏手柄确认/取消键和
Switch Access semantic action 都进入相同业务回调。

TextField 编辑时，字符、物理键盘方向键与 Enter 先交给隐藏 editor 处理光标、换行和 IME action；
Tab、Escape，以及来自 DPAD/游戏手柄的方向/确认/取消键转交当前 Host 的 focus owner。IME `NEXT`
等价于该 Host 的 Tab，不会选择或提交另一个 Host 的输入目标。

## 0.1-SNAPSHOT 二进制迁移

`Popover`、`Menu`、`Dialog`、`Slider`、`Tabs`、`SegmentedControl`、`RefreshIndicator` 和
`SwipeRefreshScaffold` 追加了带默认值的 Kotlin 参数。已有源码调用在重新编译后继续成立，但旧
`0.1.0-SNAPSHOT` JVM descriptor 不会自动链接，消费者必须重新编译。`PixelKey.SPACE` 和
`PixelHostView.dispatchPixelKeyEvent` 是新增 API。
