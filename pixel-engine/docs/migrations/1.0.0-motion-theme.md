# pixel-engine 1.0.0 MotionTheme 与组件微状态迁移指南

## 影响范围

M3-2 为标准组件建立了统一、可继承且可测试的运动配置。新增 API 均为 additive：

- `PixelMotionTheme` / `PixelMotionThemeData`；
- `PixelMotionSpec` / `PixelResolvedMotion`；
- `PixelMotionRole` / `PixelMotionTransitionPreset` / `PixelSpringSpec`；
- `PixelMotionScope` / `PixelMotionSettings`；
- `PixelHostView.motionSettingsOverride`。

在 `PixelHostView` 中运行的组件会自动取得 Host 的 ticker 与 Android animator scale；业务不需要
再为 Button、Switch、Slider、Tabs、Slidable、Dialog、Popover 或 Navigator 创建第二套时钟。
不在 Host 中运行时，这些标准组件同步呈现终态，避免隐藏的私有 ticker。

## 1. 配置主题 token

`PixelMotionThemeData` 分别提供 feedback、selection、Slidable settle、Dialog、Popover 和 route
token。`duration` 是实际插值时间，`delay` 是插值开始前的等待，二者都会乘以系统 duration
scale。`transition=None` 表示同步切换；`spring` 由支持物理 settle 的组件（当前为 Slidable）消费。

```kotlin
/** Builds one application motion theme with explicit interaction and route policies. */
fun appMotionTheme(child: Widget): Widget {
    /** Fast local response shared by pressed, hover, and focus feedback. */
    val feedback = PixelMotionSpec(
        duration = 80.milliseconds,
        curve = Curves.EaseOut,
        role = PixelMotionRole.Feedback,
    )
    /** Spatial route token with a short, intentional delay. */
    val route = PixelMotionSpec(
        duration = 240.milliseconds,
        delay = 20.milliseconds,
        curve = Curves.EaseInOut,
        transition = PixelMotionTransitionPreset.SlideHorizontal,
        role = PixelMotionRole.Spatial,
    )
    return PixelMotionTheme(
        data = PixelMotionThemeData.Default.copy(
            feedback = feedback,
            route = route,
        ),
        child = child,
    )
}
```

Button、Switch、Slider 和 Tabs 把非 `None` preset 映射到各自的颜色、位置或选择视觉通道；
Dialog 与 Popover 使用稳定 opacity 通道。组件不会因为反馈动画改变布局尺寸。Slidable 拖动阶段
始终直接跟手，只有 release 后的 snap/dismiss 使用 settle token。

Navigator 保留已有公开 `transitionDuration`、`PixelRoute.transition` 和 `defaultTransition` 的优先级，
同时从 route token 读取 curve、delay、系统倍率和 reduce-motion 策略。route token 为 `None` 时会
同步关闭内置与自定义转场；其他 preset 表示允许 Navigator 使用上述公开路由配置选择具体通道。
自定义 route transition 仍使用同一 retained route State，不会为 outgoing/incoming 再挂载一份
页面子树。

## 2. 系统倍率与 reduce motion

Host attach 后会读取并监听 Android animator duration scale：API 33+ 使用
`ValueAnimator.DurationScaleChangeListener`，API 24–32 监听
`Settings.Global.ANIMATOR_DURATION_SCALE`。普通 detach 会注销监听，重新 attach 后重新同步；
Host destroy 会终态释放监听。

`PixelMotionRole` 决定 reduce-motion 替代策略：

| Role | reduce-motion 行为 |
|---|---|
| `Feedback` | 同步呈现 pressed/hover/focus 终态 |
| `Selection` | 同步呈现 checked/value/tab 终态 |
| `Spatial` | 删除 delay，改为最长 80ms 的线性 fade；原 token 为 `None` 时仍保持 `None` |
| `Continuous` | 停止非必要连续运动并呈现静态终态 |

因此 reduce motion 不是简单把所有 duration 改成零：局部状态立即可读，页面与 Overlay 的空间
关系仍以短 fade 表达，而且所有退出清理、回调和路由结果仍在确定的终点执行。

应用可以用 Host override 提供设置内预览或更严格的无动画模式；设回 `null` 后继续跟随系统：

```kotlin
/** Applies an in-app motion preview without replacing the Host clock. */
fun previewReducedMotion(hostView: PixelHostView, enabled: Boolean) {
    hostView.motionSettingsOverride = if (enabled) {
        PixelMotionSettings(reduceMotion = true)
    } else {
        null
    }
}

/** Forces every standard transition to its terminal state synchronously. */
fun disableMotionForScreenshot(hostView: PixelHostView) {
    hostView.motionSettingsOverride = PixelMotionSettings(animatorDurationScale = 0f)
}
```

## 3. 中断、移除与交互所有权

运行中的 token、系统倍率或 reduce-motion 发生变化时，组件先采样当前视觉值，再从该帧重定向；
切换到 scale 0 或 `None` 时同步收敛。快速 pressed/release、selection 反向、Popover/Dialog
enter→exit→enter 和连续路由 mutation 都不会跳回旧起点。

退出中的 Dialog/Popover 与 opacity 为零的子树只保留 paint，不导出点击、Slider、hover、finder
或 semantics。Host 和 `PixelTester` 还会在每个新 render snapshot 上核对 down/hover/slider owner：
目标被移除、禁用或变为不可交互后立即 cancel，之后的 up 不会调用旧回调，也不会点击同坐标的
背景控件。

Slidable action 的命中区域只包含实际露出的 pane；阈值和 settle 终点使用组件真实布局宽度，不使用
整屏宽度。`dismissible=true` 只有同时提供 `onDismissed` 时才允许整行离场。

## 4. 测试与迁移建议

组件动画测试应使用 `PixelTester.vsync` 与 `pumpFrame`，不要使用 `Thread.sleep`：

```kotlin
/** Advances a delayed selection token with deterministic active time. */
fun advanceSelection(tester: PixelTester) {
    tester.pumpFrame(0) // Establishes the ticker timestamp anchor.
    tester.pumpFrame(100) // Advances exactly 100ms of active Host time.
}
```

迁移检查：

1. 删除业务层为标准组件创建的独立 `PixelTickerProvider`。
2. 把散落的 duration/curve 合并进根部 `PixelMotionThemeData`。
3. 保留受控组件的业务状态所有权；Motion 只插值视觉值，不延迟 checked/value/route 逻辑更新。
4. 用 scale 0、reduce motion、中途换主题、快速反向和组件移除覆盖回归。
5. 自定义 transition builder 不应缓存收到的 presentation widget，也不应在转场外复用它。

完整 controller、隐式动画和零 opacity 行为另见
[动画正确性迁移指南](1.0.0-animation-correctness.md)。
