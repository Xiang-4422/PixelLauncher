# 1.0.0 Compose Host 互操作迁移指南

## 适用范围

`pixel-compose` 只解决一个方向：在现有 Compose 页面中托管完整 `PixelHostView`。Launcher app 和
非 Compose SDK 消费者不需要迁移，也不会传递解析 `androidx.compose`。legacy `pixel-engine` 聚合坐标
继续不包含 Compose；需要 wrapper 的页面必须显式依赖 `com.purride:pixel-compose`。

## 构建配置

Kotlin 2 项目需要在使用 Compose 的 module 应用与 Kotlin 同版本的 Compose compiler plugin。仓库
使用 Kotlin/Compose compiler 2.0.21 与稳定 Compose BOM 2026.06.00；发布 POM 写入解析后的
runtime/ui 1.11.3 版本，Maven 消费者不依赖 Gradle Module Metadata 也能解析。

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.plugin.compose") version "2.0.21"
}

android {
    buildFeatures { compose = true }
}

dependencies {
    implementation("com.purride:pixel-compose:1.0.0")
}
```

## 最小接入

```kotlin
/** 页面生命周期内复用的独立 Engine。 */
val engine = PixelEngine.Builder().build()

PixelHost(
    engine = engine,
    modifier = Modifier.fillMaxSize(),
    stateKey = "profile-pixel-host",
    content = {
        Semantics(
            label = "Profile",
            child = Center(child = Text("PROFILE")),
        )
    },
)
```

`PixelHost.content` 是 `RootWidgetProvider`，即非 Composable 的 `() -> Widget`。不要把 Compose
`Text`、`LazyColumn` 或其他 `@Composable` 传进 retained pixel tree；1.0 不提供也不承诺反向嵌入。
需要混排时，在 Compose 布局层把整个 `PixelHost` 当作一个 AndroidView 节点，与其他 Composable
并列布局。

## 环境传递契约

| 能力 | Compose wrapper 行为 |
|---|---|
| lifecycle | AndroidView 的 ViewTree owner 由现有 Host 自动绑定；pause/stop/destroy 与普通 Host 一致 |
| saved state | `rememberSaveable` 提供有界 fallback；Engine 显式 capability 优先 |
| density/configuration | Host 与 Compose 使用同一 Android Context/configuration，配置变化请求新 Insets |
| WindowInsets / IME Insets | wrapper 容器显式转发到 `PixelHostView.onApplyWindowInsets` |
| focus | 真实 `PixelHostView` 保持可聚焦并参与 AndroidView 焦点互操作 |
| IME | 继续使用标准 `PixelTextInputBridge` 和隐藏 `EditText`，不模拟 Compose TextField |
| accessibility | Pixel virtual nodes 作为 AndroidView 子树暴露，不复制为第二套 Compose semantics |

Compose saved-state fallback 最多保存 64 个 key、每值 256 KiB、总计 1 MiB，读写均防御性复制。
空 key、超长 key 或超限值返回 `PixelCapabilityResult.Failed`；缺失值仍是成功返回 null。调用方已有
saved-state capability 不会被 wrapper 覆盖：`PixelEngine.withHostServicesFallback` 只补缺，并共享
原 Engine 的 clock、scheduler、cache、resolver 与 logger 引用。

## 重组、旋转与释放

- 普通重组复用同一个 Android Host，并同步 Engine、Host config、back dispatcher 和 Pixel 根 provider。
- `stateKey` 改变会重置该组合位置的 saved state；同屏多个业务 Host 应使用稳定且不同的 key。
- Activity 旋转/重建会创建新 Host；旧 ViewTree owner destroy 后终结 retained runtime，新 Host 从
  SavedStateRegistry 恢复 capability 数据。
- AndroidView `onRelease` 始终调用 `PixelHostSetup.dispose()`，结束输入桥、ticker 与 retained tree。

## 验证与依赖隔离

仓库提供 `pixel-compose-sample` 和 `PixelComposeInteropInstrumentedTest`。后者在 API 37/16KB AVD
验证 ViewTree lifecycle、density、WindowInsets、Android focus、精确文本输入、真实 IME bridge、
virtual accessibility subtree、Activity recreate saved state 和旧 Host destroy。隔离 Maven 消费者只
声明 `pixel-compose`，真实编译 `PixelHost` Composable，并完成 Debug、Release R8；反向门禁继续
要求 core/runtime/widgets/navigation/android/testing/debug/legacy aggregate 的非 Compose 图不含
`androidx.compose`。
