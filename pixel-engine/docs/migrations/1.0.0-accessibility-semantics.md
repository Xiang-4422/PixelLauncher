# 1.0.0 Accessibility Semantics 迁移

## 适用范围

本说明面向从 0.1 flat semantics / index virtual ID 迁移到 1.0 semantics tree 的 SDK
使用方。旧的 `Semantics(label, child, role, enabled, focused, key)` 调用仍可源码兼容；新增
参数都有默认值。

## 二进制兼容说明

本次迁移发生在尚未正式发布的 `0.1.0-SNAPSHOT` 基线上。为了让标准组件直接暴露结构化
semantics，`Semantics`、`PixelSemanticsNode`、`ListTile`、`PixelMenuItem`、`Menu`、
`Dialog`、`TextField` 和 `Slider` 的既有 Kotlin 函数或构造器追加了默认参数。已有源码调用
重新编译后保持有效，但 JVM descriptor 和 Kotlin `$default` bridge 会变化；使用旧 snapshot
AAR 编译的二进制必须随 1.0 SDK 重新编译，不能把源码兼容误认为旧二进制兼容。

1.0.0 正式发布时会冻结 released Metalava baseline；此后的稳定 API 变更必须遵守发布与兼容
策略，不再使用 snapshot 阶段的重编译约定。

## 身份不再等于展示下标

旧 bridge 使用 `semanticsNodes` 当前下标生成 Android virtual ID。列表头插或重排后，
TalkBack 持有的旧 ID 可能静默指向另一项。1.0 把稳定 ID 绑定到 retained render node，
Android ID 再由每个 Host 独立、单调分配并且不复用。

动态集合必须给逻辑项目稳定 key：

```kotlin
Column(
    children = records.map { record ->
        Semantics(
            label = record.title,
            role = PixelSemanticRole.LIST_ITEM,
            key = record.id,
            child = RecordRow(record),
        )
    },
)
```

不要使用 label 充当身份；重复 label 是合法内容。若业务只提供 index key，重排会被视为旧
逻辑节点结束、新节点开始，这是 retained widget 的既有身份规则。

## 从拼接文案改为结构化状态

不要把状态拼进英文 label：

```kotlin
// 旧写法
Semantics(label = if (checked) "Wi-Fi on" else "Wi-Fi off", child = control)

// 1.0
Semantics(
    label = "Wi-Fi",
    role = PixelSemanticRole.SWITCH,
    checked = checked,
    child = control,
)
```

当前值、输入提示与校验错误分别放入 `value`、`hint`、`error`。Slider 使用
`PixelSemanticsRangeInfo`；列表和网格使用 `PixelSemanticsCollectionInfo` /
`PixelSemanticsCollectionItemInfo`；动态提示使用 `PixelSemanticsLiveRegion`。

可选择集合还应通过 `PixelSemanticsSelectionMode` 声明选择策略：普通列表使用 `NONE`，
单选菜单或单选列表使用 `SINGLE`，允许同时选中多个项目的集合使用 `MULTIPLE`。例如，单选
菜单的容器语义可以写成：

```kotlin
Semantics(
    label = "Theme",
    role = PixelSemanticRole.MENU,
    collectionInfo = PixelSemanticsCollectionInfo(
        rowCount = themes.size,
        columnCount = 1,
        selectionMode = PixelSemanticsSelectionMode.SINGLE,
    ),
    child = themeItems,
)
```

项目本身仍需通过 `selected` 和 `PixelSemanticsCollectionItemInfo` 暴露当前选择状态及位置；
不要用容器 label 拼接当前选项来代替结构化选择语义。

## 动作由语义节点直接拥有

0.1 bridge 会用节点中心点重新查找 click target。重叠、裁剪或树变化时，这可能调用错误
控件。1.0 使用 `PixelSemanticsActions` 将 typed callback 直接绑定到语义节点：

```kotlin
Semantics(
    label = "Archive",
    role = PixelSemanticRole.BUTTON,
    actions = PixelSemanticsActions(
        onClick = {
            archive(record.id)
            true
        },
        customActions = listOf(
            PixelSemanticsCustomAction(
                id = "archive-with-note",
                label = "Archive with note",
                onInvoke = {
                    openArchiveDialog(record.id)
                    true
                },
            ),
        ),
    ),
    mergeDescendants = true,
    key = record.id,
    child = row,
)
```

回调返回 `true` 表示请求已完成；disabled/read-only 节点不要提供不允许的 mutating action。
Android accessibility 和 `PixelTester.performSemanticsAction` 执行同一份 callback。

## 消除容器与文字重复朗读

标准 Button、Checkbox、Switch、Tab、Slider、MenuItem 会把装饰性文字合并到控件节点。
自定义单一控件应设置 `mergeDescendants = true`。如果父节点已经完整描述整个自绘子树，使用
`excludeDescendants = true`。二者不能同时为 `true`。

默认不合并，复合表单、列表和 Dialog 因而保留真实 parent/child 层级。不要为了解决一个
重复 label 而合并整个页面；这会让后代动作和 collection 结构丢失。

## Android 事件与焦点

accessibility focus 与 pixel-engine 的键盘/input focus 是两个状态。Android bridge 支持
`ACTION_ACCESSIBILITY_FOCUS` / `ACTION_CLEAR_ACCESSIBILITY_FOCUS` 和 `findFocus`，并按稳定
node ID 发送焦点、内容、选择、文本、滚动及窗口事件。节点移除后，旧 virtual ID 查询和动作
必须失败，且不会分配给随后插入的节点。

Dialog/Menu 的 Android virtual tree、role 与窗口事件属于本迁移；完整键盘/DPAD focus scope、
焦点陷阱与关闭恢复在 1.0 focus 迁移中说明。

## 测试迁移

字符串 `dumpSemanticsTree()` 仍用于诊断，但精确测试应改用结构化 API：

```kotlin
val nodes = tester.semanticsNodesByLabel("DELETE")
check(nodes.size == 2)
check(nodes[0].id != nodes[1].id)

val firstId = nodes[0].id
tester.pumpWidget(reorderedTree, logicalWidth = 80, logicalHeight = 32)
check(tester.semanticsNode(firstId)?.label == "DELETE")
```

至少覆盖重复 label、头插、删除、任意重排、disabled action、merge/exclude、TextField
selection、Slider progress、collection scroll 和 Dialog/Menu window event。
