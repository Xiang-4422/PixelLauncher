# 1.0.0 生产级 Overlay 迁移

1.0.0 把原先的“Widget 列表 + Dialog 特例”升级为统一 route 生命周期，并让声明式
Popover、Dialog/BottomSheet 和通知队列共享可验证的窗口、安全区与资源释放契约。

## 统一 route 与结果

需要 layer、barrier、关闭策略或结果的自定义浮层应改用 `PixelPopupRoute<R>`：

```kotlin
val entry: PixelOverlayEntry<String> = overlay.show(
    PixelPopupRoute(
        content = Dialog(content = Text("PICK"), modal = false),
        layer = PixelOverlayLayer.Modal,
        dismissPolicy = PixelOverlayDismissPolicy.Dismissible,
        barrier = PixelOverlayBarrier(),
        modal = true,
        motion = PixelOverlayMotion.Dialog,
        onOutcome = ::handleOutcome,
    ),
)

entry.complete("A")
```

`complete`、无参 `dismiss` 和带 `PixelOverlayDismissReason` 的 `dismiss` 只有第一次返回
`true`。逻辑关闭后 entry 立即进入 `Removing`，不再接收 Back、焦点、指针或 semantics；所有
挂载 Host 的 keyed presentation 实际卸载后进入 `Disposed`。outcome 在卸载后按逻辑关闭顺序
FIFO 交付，因此回调不会观察到半卸载子树，不同退出动画时长也不会改变结果顺序。
Outcome 回调异常不会中止剩余 presentation/State/监听/focus/scheduler 清理；retained teardown
完成后异常仍会交回当前 build/render 调用。业务应在回调内部完成自己的错误上报，不要依赖异常
来重试 outcome（该 outcome 已经 exactly-once 交付）。

`show(widget)`、`showDialog`、`showToast` 和 `showSnackbar` 保留为兼容入口。Toast/Snackbar
现在使用 `PixelOverlayDismissPolicy.Passive`，不会再抢占 Back；如果旧业务依赖 Back 关闭通知，
请创建显式 route 并选择 `Dismissible`。

## Barrier 与 surface

`PixelOverlayDismissAction` 对 Back 和 barrier tap 分别选择：

- `Ignore`：当前 entry 不处理，继续扫描下层。
- `Consume`：拦截但不关闭，适合不可关闭 modal。
- `Dismiss`：消费并关闭当前 entry。

系统 Back 与键盘 Escape/gamepad Back 使用相同的 canonical route 扫描；较高 route 为 `Ignore`
时会继续检查下层。所有 route 都为 `Ignore` 时，统一 host 会把未处理按键继续交回应用，而不是仅因
modal focus trap 存在就强制消费。

独立使用的 Dialog、BottomSheet、Popover 和 Menu 会同时建立焦点边界与平台 Back entry；没有
dismiss callback 的 modal 会消费 Back。它们放入 `PixelPopupRoute` 或可识别的 Popover/Menu
组合后会复用外层 owner，不会双重注册或触发两次关闭。高于 modal 的非模态 route 可以获得焦点，
关闭后会恢复低层 modal 的焦点；它本身不形成 traversal trap。

Barrier route 的可见内容需要有明确 surface bounds。标准 Dialog、BottomSheet 和 Popover 已自动
建立 surface hit boundary；自定义 route 若表面本身没有点击 target，应使用
`PixelOverlaySurface` 包住真实表面，避免点击 padding 或 disabled 内容穿透到外部 barrier。

## Popover 定位变化

旧 Popover 只在局部 Stack 内按固定 offset 绘制，可能占满父约束并被 List/ClipRect 裁切。
1.0.0 的 anchor 分支只参与普通布局，presentation 提升到 Host 根层，并使用真实全局 anchor
bounds。默认 `PixelPopoverPlacement.Auto` 在空间不足时上下翻转，所有模式都会夹取到 SafeArea、
IME 和 `viewportMargin` 内；`PixelPopoverAlignment.Start/End` 随 RTL 镜像。滚动、IME、旋转和
resize 会自动重定位。

Root portal 与 route layer 共用总序：低层 route 内的 Popover 不会在最终合成时盖过更高
Modal/System route；更高的非模态 route 仍能在低层 modal 之上接收点击与 semantics。
当 route Stack 位于 Opacity、ClipRect、Translate 或缩放产生的 scratch buffer 内时，较高 sibling
会以原 clip、alpha 和全局变换捕获为同一根平面；绘制、点击、semantics 与 raw hit-test 仍使用同一
顺序，较高 sibling 不会为了覆盖 portal 而逃出自己的裁切范围。

既有 8 参数 Popover JVM overload 保留并映射到 `Auto + Start + margin 1`。需要显式策略时调用
带必传 `placement` 的新 overload：

```kotlin
Popover(
    anchor = anchor,
    content = menu,
    expanded = expanded,
    placement = PixelPopoverPlacement.Above,
    alignment = PixelPopoverAlignment.End,
    viewportMargin = 2,
)
```

依赖旧版“允许越出窗口”或手写负 offset 的调用应删除补偿值，并以 placement/alignment 表达意图。

## Dialog、BottomSheet 与 IME

Dialog 和新增 BottomSheet 会把 `viewPadding` 与 `viewInsets` 每边取最大值，在剩余矩形内测量、
对齐并裁切 paint、hit-test、所有交互 target 与 semantics。BottomSheet 填满安全宽度并贴安全
底边。通过 `PixelPopupRoute(modal = true)` 承载标准表面时，route 会复用现有 modal owner，
不会创建一个把同 route barrier 排除在外的嵌套 owner。
在正文高度超过小窗口或 IME 剩余空间时，title/content 使用弹性裁切区，footer actions 优先保留；
被裁掉的正文不会继续导出隐藏点击、scrollbar thumb 或 semantics。

## Toast/Snackbar 队列

`PixelToastQueueController.enqueue` 新增显式 `Duration` timeout overload，旧 overload 与 JVM
descriptor 保留；`PixelSnackbarQueueController`、`SnackbarQueue` 和
`PixelSnackbarQueueItem` 提供同样的 FIFO 队列及一次性 action。timeout 使用 Host active time：
pause 期间冻结，manual dismiss/action/clear/dispose 同步取消 ticker，reduce motion 与 animator
scale 不改变可读停留时间。未处于 `PixelMotionScope` 时队列不会创建隐式时钟，需手动关闭。

Controller 通知使用快照 fan-out：某个外部 listener 抛异常不会阻止 Host/队列 listener 收到同一
次 mutation，也不会阻止已经 ready 的 outcome 或 ticker 清理；所有清理完成后首个异常携带
suppressed 异常重新抛出。
