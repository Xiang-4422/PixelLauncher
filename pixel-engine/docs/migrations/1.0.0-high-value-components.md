# pixel-engine 1.0.0 高价值组件迁移指南

## 适用范围

本指南说明 1.0.0 新增或收紧的高价值组件契约：

- `Radio`、`PixelRadioOption<T>`、`RadioGroup` 与 `IconButton`；
- `TextField` 的显式 `FormFieldDecoration`；
- `Tabs` / `SegmentedControl` 的稳定 identity 与 `SINGLE` collection；
- `Slidable` 的 expand、collapse、dismiss 无障碍动作；
- `PixelNavigationDestination`、`NavigationBar` 与 `NavigationRail`，包括
  `PixelMultiStackNavigatorController` 绑定。

这些能力继续使用像素逻辑坐标、受控状态和统一 `PixelControlStateSet`，不引入 Material / Cupertino
依赖，也不会把业务校验、字符计数、路由定义或数据删除策略藏进 UI 组件。

## 1. 组件 token 与 25×8 生产矩阵

M5-1 首次交付了 21 个组件 token 族；对应的
[主题 Token 与组件状态迁移指南](1.0.0-theme-tokens-and-component-states.md) 是当时里程碑的历史记录，
其中 21-family 数字不应改写。当前 `PixelComponentTokens` 在此基础上增加 4 个独立族：

| 新 token 属性 | 生产消费者 | identity / 状态要点 |
|---|---|---|
| `iconButton` | `IconButton` | 必填非空 `semanticLabel`；`selected` 由调用方控制 |
| `radio` | `Radio`、`RadioGroup` | group 使用 `PixelRadioOption.id`，不是展示下标 |
| `navigationBar` | `NavigationBar` | 横向、单 Tab stop、稳定 destination id |
| `navigationRail` | `NavigationRail` | 纵向、单 Tab stop、稳定 destination id |

因此当前主题图包含 25 个生产组件族。每一族都覆盖 Normal、Hovered、Pressed、Focused、Selected、
Disabled、Error、Loading 八种状态，完整生产矩阵为 `25 × 8 = 200` 个状态格。

`FormFieldDecoration` 不是第 26 个组件族。它与输入 surface、focus indicator 和状态颜色一起消费
`components.textField`，避免 label/helper/error 因另一个 token 族与输入框发生视觉漂移。

## 2. Radio、RadioGroup 与 IconButton

### 单个 Radio

`Radio` 是受控组件：`selected` 是当前事实，`onSelected` 只是请求调用方更新事实。pointer、Enter、
Space 与 accessibility click 共用同一个 callback。`semanticLabel` 必须非空；组件不会从周围文本猜测
名称。

```kotlin
Radio(
    selected = notificationMode == "mentions",
    onSelected = { notificationMode = "mentions" },
    semanticLabel = "MENTIONS ONLY",
    key = "notification-mentions",
)
```

`onSelected = null` 或 `enabled = false` 会归一化为 Disabled。Loading 保留已有焦点但撤销 pointer、
keyboard 和 semantics 变更动作；Disabled 还会移除焦点遍历资格。

### 稳定 id 的 RadioGroup

`RadioGroup` 不用 index 作为业务身份。`PixelRadioOption<T>.id` 同时用于受控选择、callback、retained
key 与动态重排后的语义 identity：

```kotlin
/** Stable business options independent from current visual position. */
val qualityOptions = listOf(
    PixelRadioOption(id = "low", label = "LOW"),
    PixelRadioOption(id = "high", label = "HIGH"),
)

RadioGroup(
    options = qualityOptions,
    selectedId = selectedQualityId,
    onSelected = { id -> selectedQualityId = id },
    semanticLabel = "RENDER QUALITY",
    key = "render-quality",
)
```

构造约束会在挂载前 fail fast：

- option label 必须非空，option id 必须唯一；
- group 的 `semanticLabel` 必须非空；
- 非空 options 必须提供一个恰好命中的 `selectedId`；
- 空 options 只接受 `selectedId = null`；
- 单项 `enabled = false` 只禁用该业务项，不改变其他项的 identity。

整组导出一个纵向 `SINGLE` collection；可交互且至少有一项 enabled 时占一个 Tab stop。Left/Up
选择前一个 enabled option，Right/Down 选择后一个，方向移动循环且跳过 disabled option；
Enter/Space 重新请求当前 keyboard anchor。回调只返回稳定 id，组件不会内部提交新选择。

### IconButton

`IconButton` 把 `PixelIconData.bitmap` 当作 alpha mask，并用 `components.iconButton` 当前 content role
着色。图形后代不会产生第二个 accessibility image 节点，整个控件只导出一个 button 节点：

```kotlin
/** Opaque source mask; active theme supplies its rendered color. */
val saveIcon = PixelIconData(
    bitmap = PixelBitmap(
        width = 3,
        height = 3,
        pixels = IntArray(9) { PixelColor.White.argb },
    ),
)

IconButton(
    icon = saveIcon,
    onPressed = { saveDocument() },
    semanticLabel = "SAVE DOCUMENT",
    selected = documentSaved,
    key = "save-document",
)
```

不要使用空白 `semanticLabel`，也不要把文件名或业务动作只编码在 bitmap 中。`selected` 会合入
Selected 视觉和结构化语义，但仍由调用方维护。

## 3. 使用 FormFieldDecoration 表达表单状态

不要再把校验错误替换进 placeholder：错误会伪装成空值占位，而且字段有值时不可见。1.0.0 应把
placeholder 保持为输入提示，并显式传入 `FormFieldDecoration`：

```kotlin
TextField(
    state = nameInputState,
    controller = nameInput,
    decoration = FormFieldDecoration(
        label = "NAME",
        helper = "PUBLIC PROFILE NAME",
        error = field.errorText,
        required = true,
        // The application chooses and formats its own counting policy.
        counter = formatNameCounter(field.value),
    ),
    placeholder = "ENTER NAME",
    onChanged = field::setValue,
    key = "profile-name",
)
```

固定规则如下：

- 非空 `error` 覆盖 `helper`，不会让两者同时显示或重复朗读；
- `counter` 在 helper 和 error 状态下都保留；
- `required` 只给可见与朗读 label 添加 `*`，不会自动创建 validator；
- `counter` 是调用方格式化的字符串，SDK 不选择 UTF-16、code point 或 grapheme cluster 规则；
- decoration error 会进入 TextField 的结构化 `error`，Android bridge 同时暴露 content-invalid；
- label、supporting text 和 counter 是 paint-only decoration，合入唯一的 TextField 语义节点；
- decoration 更新保留输入节点 identity、focus、selection、composition 与 IME target。

`semanticLabel` 可以显式覆盖 decoration label；`semanticHint` 会与当前非错误 supporting text 和 counter
组合。兼容的旧 `TextField` 路径仍然存在。新增 JVM 入口是 `TextFieldWithDecoration` 与
`TextFieldWithControlStatesAndDecoration`，不会替换原有 TextField descriptor 或 `$default` bridge。

## 4. Tabs 与 SegmentedControl 的单选集合契约

`Tabs` / `SegmentedControl` 的 public callback 仍返回 index，但 1.0.0 不再把 index 当作 retained item
identity。当前 label 同时承担显示文本与稳定 identity，因此动态集合必须满足：

- 每个 label 非空且互不重复；
- 同一个逻辑项插入或重排时保留相同 label；
- 非空集合的 `selectedIndex` 必须位于 `labels.indices`；
- 空集合只接受 `selectedIndex = -1`，并导出 0 行、0 列 collection。

```kotlin
Tabs(
    labels = listOf("APPS", "WIDGETS"),
    selectedIndex = selectedPage,
    onSelected = { index -> selectedPage = index },
    key = "launcher-pages",
)
```

两者均导出水平 `SINGLE` collection，每个 item 提供当前 column 与 selected 元数据。非空且可交互
时整组只有一个 Tab stop，Left/Right 循环请求相邻选择，Enter/Space 重新请求当前项。列表重排后
位置元数据更新，但相同 label 的 retained state、焦点和语义 id 不会被旧下标重定向。

这是一项更严格的 fail-fast 契约。过去依赖重复 label、空白 label 或越界 index 被隐式容错的调用方，
必须在升级时先规范业务数据。当前 API 没有独立 item id；若显示文案本身会频繁变化，应由业务层
提供稳定且唯一的 label，或选择具备独立 business id 的 `RadioGroup` / navigation 组件。

## 5. Slidable 的标准无障碍动作

pointer 拖动与键盘路径保持不变，1.0.0 还把 pane 状态直接映射为标准 semantics action：

| 当前状态 | 导出动作 | 行为 |
|---|---|---|
| 关闭且至少有一侧 pane | `EXPAND` | 优先打开 end pane；没有 end 时打开 start |
| 任一 pane 打开 | `COLLAPSE` | 立即关闭逻辑 pane，视觉 settle 可继续 |
| 当前 pane 可 dismiss 且存在 `onDismissed` | `DISMISS` | settle 到整行终点后回调一次方向 |

这些动作与 Left/Right、pointer release 使用同一个 pane/settle 状态机，不会旁路 capability 检查。
Loading 保留节点和已有焦点，但撤销 expand、collapse、dismiss；Disabled 还会移除 traversal。关闭
或 dismiss 后 pane 后代立即退出 semantics/focus，避免视觉退出期间仍可触发旧 action。

`onDismissed` 仍只是业务事件。SDK 不会自动从列表删除行，调用方必须按 `SlidableDirection` 更新
自己的数据源。

## 6. NavigationBar、NavigationRail 与多返回栈

### 稳定 destination 模型

两个组件共享 `PixelNavigationDestination`：

```kotlin
/** Stable destinations used by selection, callbacks, retained state, and optional stack binding. */
val destinations = listOf(
    PixelNavigationDestination(
        id = "home",
        label = "HOME",
        icon = homeIcon,
        selectedIcon = homeSelectedIcon,
    ),
    PixelNavigationDestination(
        id = "settings",
        label = "SETTINGS",
        icon = settingsIcon,
    ),
)
```

`id`、label 与 collection 的 `semanticLabel` 都必须非空；一个 navigation collection 内的 id 与 label
分别唯一。destinations 不能为空，受控 `selectedId` 必须恰好命中一项。`selectedIcon` 可省略，
此时选中态继续使用普通 `icon`。
destination id 是选择、callback、controller stack 和 retained identity；展示下标只用于当前 collection
位置，所以插入、删除或重排不会把动作指向另一个 stack。

### 受控入口

```kotlin
NavigationRail(
    destinations = destinations,
    selectedId = activeDestinationId,
    onSelected = { id -> activeDestinationId = id },
    semanticLabel = "PRIMARY NAVIGATION",
    key = "primary-rail",
)
```

Bar 使用 Left/Right，Rail 使用 Up/Down；两者都循环跳过 disabled destination，Enter/Space 重新请求
当前 id。可交互且至少有一个 enabled destination 时，每个控件整体只有一个 Tab stop；collection
始终按对应横向或纵向导出 `SINGLE` 元数据。与其他受控组件一样，callback 只报告请求，必须由调用方
重建并提交新 `selectedId`。

### 绑定 PixelMultiStackNavigatorController

当目的地直接对应 `PixelMultiStackNavigator` 的子栈时，可以省略 `selectedId` / `onSelected`，改传
controller：

```kotlin
/** Multi-stack owner shared by PixelMultiStackNavigator and its navigation control. */
val navigationController = PixelMultiStackNavigatorController(initialStackId = "home")

NavigationBar(
    destinations = destinations,
    controller = navigationController,
    popToRootOnReselect = true,
    animated = true,
    key = "primary-bar",
)
```

Host 挂载后，每个可见 destination id 必须对应 controller 的真实 stack id。选择另一 destination
调用 `selectStack`，只切换 active stack；其他子栈持续挂载并保留 route history。默认
`popToRootOnReselect = false`；显式设为 `true` 后，重选 active destination 只 clear 该子栈 root
以上的 entry，`animated` 传给该 clear 操作。

NavigationBar/Rail 不接管 Back。controller 继续先把 Back 交给 active nested stack；secondary stack
已经位于 root 时回到 `initialStackId`；initial root 再把未处理 Back 交给外层 Host。这样视觉选择、
独立栈 history 和返回策略仍由同一个 controller 驱动。

## 7. 迁移清单

1. 把需要单选业务 identity 的 index 列表迁移为 `PixelRadioOption.id` 或
   `PixelNavigationDestination.id`。
2. 为 `Radio`、`RadioGroup`、`IconButton` 和 navigation collection 提供非空语义名称；不要让 bitmap
   或展示位置承担业务身份。
3. 把表单 error 从 placeholder 移到 `FormFieldDecoration.error`，保留独立 placeholder。
4. 由业务明确选择 counter 计数规则，再把最终字符串传给 decoration。
5. 清理 Tabs/SegmentedControl 的空白、重复 label 和越界 selection；空集合使用 `-1`。
6. 保留 `Slidable.onDismissed` 中的数据更新，不能把标准 `DISMISS` 动作误认为 SDK 自动删行。
7. 多栈导航让 destination id 与 stack id 对齐；只有产品明确要求重选回根时才启用
   `popToRootOnReselect`。
8. 自定义主题补齐 4 个新增 component token 覆写；没有差异时继承 `PixelComponentTokens.Default`。
9. 在 Theme Showcase 检查 25 个生产组件族及 200 个状态格，并对动态重排、键盘、语义和 Back 做
   业务级验收。

完整 API 参数表见 [使用说明与 API 手册](../使用说明与API手册.md)。
