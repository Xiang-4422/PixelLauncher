# pixel-engine 1.0.0 自适应 Host 与 Viewport 迁移指南

## 影响范围

1.0.0 把物理窗口、逻辑像素格、Android 环境能力和自适应布局拆成明确的正交契约：

- `PixelViewportPolicy` 控制 Contain/Cover、Integer/Fractional 和九宫格 alignment；
- `PixelHostProfilePolicy` 控制逻辑 profile 是固定、按 px、按 dp，还是固定逻辑尺寸；
- Android capability source 自动发布 locale、direction、text scale、contrast、density、motion、
  refresh rate 和 display features；
- `PixelAdaptiveLayoutData` / `AdaptiveBuilder` 在同一帧暴露物理 dp 分类、逻辑尺寸、inset 和
  fold/hinge/cutout；
- system bars、IME 和 cutout 先以原始物理值保存，窗口、profile 或 viewport 改变后再投影，
  不会继续使用旧逻辑 inset。

这些能力都是 additive。没有显式设置新策略时，已有 `ScreenProfile`、`ScaleMode.FIT_CENTER`、
`PixelHostProfilePreference`、`MediaQueryData` 和 `PixelHostSetupConfig` 的构造器、copy 及 JVM
描述符保持不变。

## Viewport 与 profile 是两个维度

`PixelViewportPolicy` 只负责“已经确定的逻辑网格如何映射到物理 View”：

| 维度 | 选项 | 含义 |
|---|---|---|
| fit | `CONTAIN` / `COVER` | 完整显示并留边，或铺满并裁切 |
| quantization | `INTEGER` / `FRACTIONAL` | 整数 cell，或精确浮点 cell |
| alignment | 九宫格 | 剩余空间或裁切原点的位置 |

旧 `ScaleMode.FIT_CENTER` 精确等价于：

```kotlin
/** Exact policy represented by the frozen legacy FIT_CENTER mode. */
val legacyFitCenterPolicy = PixelViewportPolicy(
    fit = PixelViewportFit.CONTAIN,
    quantization = PixelViewportQuantization.INTEGER,
    alignment = PixelViewportAlignment.CENTER,
)
```

`PixelHostProfilePolicy` 负责“逻辑网格本身怎样得到”：

- `Fixed(profile)`：窗口和 density 改变时保持调用方 profile；直接赋值
  `PixelHostView.screenProfile` 会切回该模式。
- `AdaptivePixels(dotSizePx, shape)`：按一个逻辑点占用的物理 px 推导网格。
- `AdaptiveDp(dotSizeDp, shape)`：先用当前 density 得到物理 dot，再推导网格。
- `AdaptiveLogicalSize(width, height, shape)`：固定逻辑行列，viewport 决定实际 cell 大小。

典型 Android Host 可以同时配置两者：

```kotlin
/** Configures an adaptive grid without changing the frozen setup-config constructor. */
fun configureAdaptiveHost(hostView: PixelHostView) {
    hostView.profilePolicy = PixelHostProfilePolicy.AdaptiveDp(
        dotSizeDp = 3f,
        pixelShape = PixelShape.SQUARE,
    )
    hostView.viewportPolicy = PixelViewportPolicy(
        fit = PixelViewportFit.CONTAIN,
        quantization = PixelViewportQuantization.FRACTIONAL,
        alignment = PixelViewportAlignment.CENTER,
    )
}
```

`profilePolicy` 在 width、height、density 或 viewport strategy 改变后重新求值。手工设置
`screenProfile` 明确表示调用方接管，因而自动切回 `Fixed`；旧 `profilePreference` 继续映射为
`AdaptivePixels`，用于兼容现有接入。

## Android capability 的自动与覆盖模式

普通 `PixelHostView` 不需要应用转发 `Configuration`。Host 在主线程自动观察：

- `Configuration.locales`、layout direction、fontScale 和 density；
- 系统 animator duration/reduce-motion；
- API 支持时的高对比度设置和 refresh rate；
- Android display cutout，以及应用通过 capability override 注入的 fold/hinge。

`HostCapabilities.of(context)` 订阅最近的 immutable snapshot。只需要调试或测试时才设置
`capabilitiesOverride`；非空 override 是完整替换，不会和自动快照逐字段拼接。只覆盖旧方向行为时可
使用 `layoutDirectionOverride`，设回 `null` 后恢复 Android 自动方向。

```kotlin
/** Installs one deterministic environment for a screenshot or integration test. */
fun installAdaptiveTestEnvironment(hostView: PixelHostView) {
    hostView.capabilitiesOverride = HostCapabilitiesData.Default.copy(
        locales = listOf(PixelLocale("ar")),
        layoutDirection = TextDirection.RTL,
        textScaleFactor = 2f,
        highContrast = true,
        density = 3f,
        refreshRateHz = 120f,
    )
}
```

Host capability source 的 attach、detach、destroy、refresh 和 override 都具有主线程契约。
pause/detach 期间只保留最新完整快照，恢复时不会重放过期中间状态。

## System bars、IME、cutout 与重投影

`PixelHostView` 把平台值分成两个公开逻辑通道：

- `windowInsets` / `MediaQuery.viewPadding`：system bars 与 cutout-safe edge；
- `viewInsets` / `MediaQuery.viewInsets`：IME 等临时遮挡。

API 30+ 直接读取 `WindowInsets.Type.systemBars()`、`ime()` 和 `displayCutout()`。API 24–29
使用 current system-window inset 与 stable inset 分离导航栏和更大的临时 IME；不再把 legacy
IME 无条件设为零。

平台原始物理值不会在第一次回调后丢弃。窗口 resize、分屏、profile、density、Contain/Cover、
quantization 或 alignment 改变时，Host 会用同一 `PixelGridGeometry` 重新计算：

- paint origin 与 cell size；
- pointer inverse；
- Accessibility bounds；
- system/IME logical inset；
- cutout logical display feature。

因此业务不应缓存 `MediaQuery` 或 `PixelAdaptiveLayoutData` 跨帧使用。需要长期状态时保存业务值，
每次 build 重新读取环境。

## AdaptiveBuilder

`AdaptiveBuilder` 订阅 `PixelAdaptiveEnvironment`，一次获得：

- `physicalWidthPx` / `physicalHeightPx`；
- `widthDp` / `heightDp` 与 width/height `PixelWindowSizeClass`；
- portrait、landscape 或 square orientation；
- 当前逻辑 width/height；
- density、viewInsets、viewPadding、padding；
- immutable display feature 列表。

```kotlin
/** Chooses one application skeleton while preserving keyed child state across changes. */
fun adaptiveApplication(content: Widget): Widget {
    return AdaptiveBuilder(
        builder = { _, window ->
            when (window.widthSizeClass) {
                PixelWindowSizeClass.COMPACT -> SafeArea(child = content)
                PixelWindowSizeClass.MEDIUM,
                PixelWindowSizeClass.EXPANDED,
                -> Row(
                    children = listOf(
                        NavigationRail(
                            destinations = appDestinations,
                            selectedIndex = selectedDestination,
                            onSelected = ::selectDestination,
                            key = "adaptive-rail",
                        ),
                        Expanded(child = SafeArea(child = content)),
                    ),
                    key = "adaptive-shell",
                )
            }
        },
        key = "adaptive-builder",
    )
}
```

环境更新会 rebuild 依赖者，不会主动替换具有稳定 key/type/slot 的 retained element。应用仍应给
TextField、滚动视口、导航容器和可重排业务节点提供稳定 key。这样 resize、IME、density、fold 或
locale 更新时，State、FocusNode、scroll offset、text、selection、composition 和语义身份可以保留。

## Text scale、高对比度与 RTL

`Text`、`RichText` 和 `TextField` 自动读取 `HostCapabilities.textScaleFactor`。缩放同时影响测量、
font metrics、line height、letter spacing、paint、caret 和 selection；非整数倍率使用确定性的最近邻
像素缩放，不把 backing text 或 UTF-16 offset 改写。

主题可以按当前能力选择标准或高对比度 preset：

```kotlin
/** Selects a dark preset and subscribes to Host contrast changes. */
fun capabilityAwareTheme(child: Widget): Widget {
    return Builder { context ->
        /** Preset changes only when the inherited capability dependency changes. */
        val tokens = PixelThemeTokens.forHost(
            context = context,
            brightness = PixelThemeBrightness.Dark,
        )
        PixelTheme(tokens = tokens, child = child)
    }
}
```

RTL `Row`/Flex 会反转真实视觉 child 顺序和 main-axis START/END，但 retained child 列表、声明顺序和
semantics traversal 顺序保持稳定。不要为了 RTL 手工 `children.reversed()`，否则会同时反转声明身份和
无障碍顺序。

## 兼容与测试建议

- 保留旧外观：不设置 `viewportPolicy`，并直接使用既有 `screenProfile`。
- 从固定 px 迁移到 density-aware dot：使用 `AdaptiveDp`，同时在不同 density 下建立 golden。
- 测试 fold/hinge：通过 `HostCapabilitiesData.displayFeatures` 注入逻辑 feature，不在公共 API 中传
  AndroidX Window 类型。
- 测试窗口环境：覆盖 LTR/RTL、1×/2× text scale、高对比度、portrait/landscape、小窗口和 IME。
- 自定义 Host 手工赋值逻辑 `windowInsets`/`viewInsets` 后由调用方拥有；下一次真实 Android
  `WindowInsets` 回调会重新切回平台拥有和物理重投影。
- `PixelAdaptiveLayoutData.displayFeatures` 是 defensive immutable snapshot，不需要调用方复制。

1.0 保证 viewport 的 paint/touch/semantics/inset 几何一致，以及环境变化不主动重置 retained 业务
状态；它不承诺替业务自动选择具体 NavigationBar/Rail 布局，也不把 AndroidX Window 类型暴露到
平台中立 API。
