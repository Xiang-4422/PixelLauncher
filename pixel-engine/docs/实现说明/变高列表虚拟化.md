# 变高列表虚拟化设计

## Summary

当前 `ListViewBuilder(itemExtent != null)` 已支持固定高度 lazy，`itemExtent == null` 仍保持 eager 兼容。本设计只新增显式 opt-in 的变高 lazy 路径，不改变现有调用语义。

## Public API

在 `ListViewBuilder` 现有参数上新增可选参数：

```kotlin
estimatedItemExtent: Int? = null
```

行为：

- `itemExtent != null`：继续走固定高度 lazy 路径，优先级最高。
- `itemExtent == null && estimatedItemExtent != null`：走变高 lazy 路径。
- `itemExtent == null && estimatedItemExtent == null`：继续 eager 兼容路径。

`estimatedItemExtent` 必须大于 0；非法值按 eager 路径处理并在文档说明，不抛异常。

## Data Model

新增 internal state：

- `MeasuredItemExtentCache`：保存已布局 item 的真实高度。
- `EstimatedItemOffsets`：用已测高度 + 未测估算高度计算 item top。
- `VariableLazyListRange`：根据 scroll offset、viewport height、cacheExtent 计算需要 build 的 index 区间。

`PixelListState.itemTopOffsetsPx` 和 `itemHeightsPx` 仍表示真实 item index。未测 item 的 height 使用 `estimatedItemExtent`，测量后替换为真实高度。

## Rendering Flow

1. build 阶段根据估算 offset 得到可见区 + cache 的 index range。
2. render layout 阶段对子节点使用普通列表约束，不强制固定高度。
3. layout 后把本轮真实高度写入 cache。
4. 若真实高度改变导致 total content height 或 visible range 变化，mark layout 并在下一帧稳定。
5. `scrollItemIntoView` 使用当前 offset cache；目标未测时用估算 offset 定位，测量后允许下一帧微调。

## Compatibility

- 不改变 `ListView(items)` eager 行为。
- 不改变 `ListViewBuilder(itemExtent != null)` 固定高度 lazy 行为。
- 不让 `itemExtent == null` 自动 lazy，避免历史调用突然改变 build 时机。
- 不复用 `ListViewSeparatedBuilder` 的 separator 模型；分隔变高列表后续单独设计。

## Test Plan

- 1000/5000 个变高 item 初始 render 只 build 可见区 + cache。
- 滚动后 range 向前/向后更新，已测高度 cache 不丢失。
- `scrollItemIntoView` 对已测和未测 item 都能把目标拉入 viewport。
- item 高度变化后 `contentHeightPx`、`maxScrollOffsetPx` 和 target 裁剪正确。
- demo 新增 `VARIABLE_HEIGHT_LIST`。
