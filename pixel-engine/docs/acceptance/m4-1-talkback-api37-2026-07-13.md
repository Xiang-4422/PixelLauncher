# M4-1 TalkBack / Android 无障碍验收记录

## 结论

状态：**PASS**

2026-07-13 在 API 37 模拟器上启用真实 TalkBack 17.0 后，标准 Button、表单、
动态列表、Slider、Menu、Dialog 均可通过 Android 公共无障碍连接完成焦点与动作。
测试使用 `UiAutomation.FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`，运行期间 TalkBack
保持 Bound，未被 instrumentation 临时关闭。测试结束后已恢复模拟器原始设置。

## 行为验收

| 流程 | 实际结果 |
|---|---|
| Button | `SAVE` 只有一个可朗读节点；真实触摸探索手势建立焦点并触发一次业务回调，没有重复激活。 |
| 表单 | `NAME` 暴露为 `EditText`，通过公共 `ACTION_SET_TEXT` 把值从 `ADA` 改为 `GRACE`，随后可获得 TalkBack/无障碍焦点。hint、editable、selection action 由同一节点提供。 |
| Slider | `VOLUME` 暴露为 `SeekBar` 和结构化 range；`ACTION_SET_PROGRESS` 将值从 `0.4` 更新为 `0.8`。 |
| 动态列表 | `ROW 1` 获得全局无障碍焦点后，两个可见 keyed 行交换位置；焦点仍指向 `ROW 1`，激活后回调仍返回业务索引 `1`。随后 List 的 scroll-forward action 使真实 viewport offset 增大。 |
| Dropdown / Menu | `THEME` 暴露 expanded 状态和 collapse action；独立 Menu 可获得焦点，`Light` item 可选择，Menu dismiss action 可关闭窗口。 |
| Dialog | 插入 `SETTINGS DIALOG` 后，Dialog role 可获得焦点，dismiss action 关闭窗口并更新受控状态。 |

所有非物理手势动作均从 `UiAutomation.rootInActiveWindow` 返回的公共
`AccessibilityNodeInfo` 发起，不直接调用引擎内部 Provider。这样既验证 Android Binder
无障碍连接，也验证真实 TalkBack 与 instrumentation 同时运行时不会互相压制。

## 可视镜像补充检查

用户明确授权后，在 API 37 模拟器安装了 AndroMeld Helper
`com.catchingnow.andfiles.helper`，并把 `Pixel Demo` 映射到本机窗口。镜像中的真实拖动触发
Accessibility Flow 的 `ADD`，页面出现新的 `NEW ITEM`。该镜像工具的输入注入可能绕过
TalkBack 的部分触摸探索焦点策略，因此这项观察只作为可视补充，不替代上面的
unsuppressed instrumentation、稳定焦点断言和 TTS 证据。Helper 按用户授权保留安装；
TalkBack 系统开关仍按下节恢复。
