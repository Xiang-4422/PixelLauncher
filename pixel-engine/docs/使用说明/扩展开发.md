# 扩展 pixel-engine

当 SDK 内置的 widget / 手势 / 字体不够用时，你可以通过四类扩展点添加自己的能力，无需修改 SDK 源码。

| 想做的事 | 用到的扩展点 |
|---|---|
| 自己画一个全新的可视化组件（圆环、波形图、像素小动画……） | `PixelLeafRenderObjectWidget` |
| 调整翻页 / 列表的手势识别灵敏度 | `PagerGesturePolicy` / `NestedScrollGesturePolicy` |
| 用自己的字体（ttf 离散化、自定义点阵） | `PixelTextRasterizer` |
| 替换帧调度时钟（测试 / 重放 / 自定义 vsync） | `PixelFrameScheduler` |

扩展点公开在两个 package：

```kotlin
import com.purride.pixelui.advanced.*    // RenderObject 家族
import com.purride.pixelui.gesture.*      // 手势策略
```

---

## API 稳定性

`com.purride.pixelui.advanced` 是公开扩展入口，但其中类型分为两类：

| 稳定性 | 含义 |
|---|---|
| Stable | 会保持源码兼容，后续只做兼容扩展 |
| Experimental | 可以用于自定义组件，但协议细节可能随 runtime / 手势 / paint 管线继续收敛 |

当前分级：

| 类型 | 稳定性 | 说明 |
|---|---|---|
| `PixelRenderObjectWidget` | Stable | RenderObject widget 公共根基类 |
| `PixelLeafRenderObjectWidget` | Stable | 无 child 叶节点的推荐入口 |
| `PixelSingleChildRenderObjectWidget` | Stable | 单 child widget 基类 |
| `PixelMultiChildRenderObjectWidget` | Stable | 多 child widget 基类 |
| `PixelRenderObject` | Stable | render object 根基类 |
| `PixelRenderBox` | Stable | 盒模型扩展的推荐基类 |
| `PixelRenderConstraints` | Stable | 布局约束值对象 |
| `PixelRenderSize` | Stable | 布局尺寸值对象 |
| `PixelSingleChildRenderObject` | Experimental | 子节点挂接协议后续可能收敛 |
| `PixelMultiChildRenderObject` | Experimental | 子节点列表协议后续可能收敛 |
| `PixelPaintContext` | Experimental | buffer pool / paint context 后续可能扩展 |
| `PixelHitTestResult` | Experimental | hitTest API 仍可能随手势系统演进 |
| `PixelRenderObjectWithChild` | Experimental | 单 child 协议类扩展点 |
| `PixelRenderObjectWithChildren` | Experimental | 多 child 协议类扩展点 |

## 1. 自定义 RenderObject

`PixelLeafRenderObjectWidget` 让你完全接管一块区域的布局和绘制。

### 完整例子：HollowSquareWidget

```kotlin
import com.purride.pixelcore.PixelColor
import com.purride.pixelui.BuildContext
import com.purride.pixelui.advanced.*

/** Widget：不可变的配置，从这里创建 / 更新 render object。 */
class HollowSquareWidget(
    val side: Int,
    val color: PixelColor,
    override val key: Any? = null,
) : PixelLeafRenderObjectWidget(key = key) {

    override fun createRenderObject(context: BuildContext): PixelRenderObject =
        HollowSquareRender(side = side, color = color)

    override fun updateRenderObject(context: BuildContext, renderObject: PixelRenderObject) {
        (renderObject as HollowSquareRender).update(side = side, color = color)
    }
}

/** RenderObject：实际写像素的对象。 */
internal class HollowSquareRender(
    private var side: Int,
    private var color: PixelColor,
) : PixelRenderBox() {

    override fun layout(constraints: PixelRenderConstraints) {
        size = PixelRenderSize(
            width = constraints.constrainWidth(side),
            height = constraints.constrainHeight(side),
        )
    }

    override fun paint(context: PixelPaintContext, offsetX: Int, offsetY: Int) {
        // 画一个空心方框
        for (y in 0 until size.height) {
            for (x in 0 until size.width) {
                val edge = x == 0 || y == 0 || x == size.width - 1 || y == size.height - 1
                if (edge) context.setColor(offsetX + x, offsetY + y, color)
            }
        }
    }

    /** widget 配置变更时同步到 render object。务必做 equality 检查，避免无谓重绘。 */
    fun update(side: Int, color: PixelColor) {
        val sizeChanged = this.side != side
        val colorChanged = this.color != color
        if (!sizeChanged && !colorChanged) return
        this.side = side
        this.color = color
        if (sizeChanged) markNeedsLayout()
        markNeedsPaint()
    }
}
```

使用：

```kotlin
content = {
    Center(child = HollowSquareWidget(side = 16, color = PixelColor.fromRgb(255, 200, 0)))
}
```

### 关键规则

| 规则 | 原因 |
|---|---|
| 改字段前先 equality 检查，再 `markNeedsLayout` / `markNeedsPaint` | 防止 widget 重建时全树重绘 |
| `markNeedsLayout()` 隐含会重绘，不需要再 `markNeedsPaint()` | layout 通过则 paint 自动跟进 |
| `paint()` 中不要 allocate | hot path；用 `context.buffer` 直接写，不要 `new` 数组 |
| 只在主线程调用 `markNeedsXxx` | retained build tree 不保证线程安全 |

### 常用扩展点类型（com.purride.pixelui.advanced）

| 类型 | 何时用 |
|---|---|
| `PixelLeafRenderObjectWidget` | 无 child 的叶节点（最常见自定义场景） |
| `PixelSingleChildRenderObjectWidget` | 包一个 child，自己控制其位置 / 尺寸（如 Padding） |
| `PixelMultiChildRenderObjectWidget` | 持有多个 child（如 Row / Stack 的自定义版本） |
| `PixelRenderBox` | 二维盒模型 render object 基类 |
| `PixelPaintContext` | `paint()` 入参，提供 `buffer`、`bufferPool` 和 `setColor` / `fillRect` / `drawRect` |
| `PixelRenderConstraints` | `layout()` 入参，告诉你父级给的尺寸约束 |
| `PixelRenderSize` | `layout()` 返回时设置的 `size` 字段 |

## 2. 自定义手势策略

继承 `PagerGesturePolicy` 或 `NestedScrollGesturePolicy`，通过 `PixelHostSetupConfig` 注入。

### 例：可运行时调参的翻页策略

```kotlin
import com.purride.pixelcore.PixelAxis
import com.purride.pixelui.gesture.PagerGesturePolicy

class TunablePagerGesturePolicy(
    private val axisBiasProvider: () -> Float,
) : PagerGesturePolicy() {

    override fun shouldStartDrag(
        axis: PixelAxis,
        deltaX: Float,
        deltaY: Float,
        touchSlopPx: Float,
        axisBias: Float,
    ): Boolean = super.shouldStartDrag(
        axis, deltaX, deltaY, touchSlopPx,
        axisBias = axisBiasProvider(),   // 用运行时变量替代静态默认
    )
}
```

注入：

```kotlin
val policy = TunablePagerGesturePolicy { tunableAxisBias.value }

createPixelHostSetup(
    context = this,
    config = PixelHostSetupConfig(
        pagerGesturePolicy = policy,
        // 也可以同时覆盖：
        // nestedScrollPolicy = MyNestedPolicy(),
        // scrollPhysics = PixelScrollPhysics(...)
    ),
)
```

`NestedScrollGesturePolicy` 模式相同：override `shouldDeferPagerToList(...)` 或 `shouldHandOffListToPager(...)`。

## 3. 自定义字体（PixelTextRasterizer）

`PixelTextRasterizer` 把文本测量、字体度量和像素绘制收敛成统一协议。默认的 `CompositeGlyphProvider` 会按 glyph source 顺序查找字形；如果所有 source 都缺字，ASCII/symbol 使用窄 missing-glyph 方框，CJK/emoji 等非 ASCII 使用宽 missing-glyph 方框，空白字符只保留 advance 不绘制墨迹。

### 接口

```kotlin
interface PixelTextRasterizer {
    fun measureText(text: String): Int
    fun measureHeight(text: String): Int
    fun fontMetrics(text: String = " "): PixelFontMetrics
    fun drawText(buffer: PixelBuffer, text: String, x: Int, y: Int, color: PixelColor)
}
```

`PixelFontMetrics` 暴露 `cellHeight`、`baseline`、`ascent`、`descent`、`inkTop` 和 `inkBottom`，用于 Text/RichText/TextField 在多字体场景下保持稳定测量。

### 用法 A：从字体资源包加载

字形包是一个包含 `manifest.json` 和 `glyphs.bin` 的 assets 目录：

```kotlin
val pack = PixelGlyphPackAssetLoader(this).load("glyphpacks/mono5x7")
val glyphProvider = CompositeGlyphProvider(
    listOf(BitmapGlyphSource(listOf(pack))),
)
val rasterizer = PixelStyledTextRasterizer(
    engine = PixelFontEngine(glyphProvider),
    style = glyphStyle,
)

createPixelHostSetup(
    context = this,
    config = PixelHostSetupConfig(textRasterizer = rasterizer),
)
```

仓库的 `tools/generate_pixel_glyph_packs.py` 可把 TTF / OTF / BDF 转成该目录格式。无参数运行会重新生成内置 Fusion Pixel packs；自定义字体使用显式参数：

```bash
python3 tools/generate_pixel_glyph_packs.py \
  --input fonts/custom.bdf \
  --output app/src/main/assets/glyphpacks \
  --pack-id custom_8px \
  --display-name "Custom 8px" \
  --cell-height 8 \
  --baseline 7 \
  --default-advance 8 \
  --ranges 0020-007E,4E00-9FFF
```

TTF / OTF 可额外传 `--font-size`；默认等于 `--cell-height`。BDF converter 读取 `ENCODING`、`DWIDTH`、`BBX` 和 `BITMAP`，并按指定 baseline 裁剪到输出 cell。构建入口：

```bash
./gradlew :pixel-engine:generatePixelGlyphPacks
./gradlew :pixel-engine:testPixelGlyphPackConverter
```

### 用法 B：从代码构造位图字体

```kotlin
val compact = PixelBitmapFont(glyphWidth = 4, glyphHeight = 5)

hostView.textRasterizer = compact   // 也可以运行时切换
```

### 单个 widget 覆盖

某段文字想用不同字体而不影响其它：

```kotlin
Text(
    "BIG HEADER",
    style = TextStyle(textRasterizer = bigFont),
)
```

`textRasterizer` 在 `PixelTextStyle` 的字段优先级最高，会覆盖宿主默认。

## 4. 自定义 PixelFrameScheduler

`PixelFrameScheduler` 解耦了帧节奏与 Android `Choreographer`。常见自定义场景：

- 测试：用 `ManualFrameScheduler` 同步驱动帧
- 录制 / 重放：用自定义时间戳源
- 替换 vsync 源（嵌入式 / 自渲染表面）

### 接口

```kotlin
interface PixelFrameScheduler {
    fun scheduleFrame(callback: (frameTimeNanos: Long) -> Unit)
}
```

### SDK 提供的实现

```kotlin
PixelFrameScheduler.Default          // 走 Android Choreographer
ManualFrameScheduler()               // 测试：自己调 advanceFrame()
```

### 注入

```kotlin
createPixelHostSetup(
    context = this,
    config = PixelHostSetupConfig(
        frameScheduler = MyCustomScheduler(),
    ),
)
```

测试场景：

```kotlin
val scheduler = ManualFrameScheduler()
val config = PixelHostSetupConfig(frameScheduler = scheduler)
// ...
scheduler.advanceFrame(frameTimeNanos = 16_666_666L)   // 模拟一帧
```

## 5. 编写自定义扩展时的最佳实践

### markNeedsLayout / markNeedsPaint 时机

- 字段改变时调用，**且只在改变时调用**
- 用 `===` / `==` 比较新旧值，相同则提前 return
- 一次 update 调一次 markNeedsXxx，不要循环里反复调

### 类型可见性

如果你在自己的 app 模块里写扩展，无需关心 explicitApi。但如果是把 pixel-engine 二次封装成自己的库，建议：

```kotlin
kotlin {
    explicitApi = ExplicitApiMode.Strict
}
```

确保你的公开 API 边界与 pixel-engine 一样严格。

### 性能注意

- `paint()` 是热路径，每帧调用一次或多次。避免：
  - 在 `paint()` 内创建对象（`String`、`List`、`ByteArray`）
  - 在 `paint()` 内做日志 / 反射 / lambda 调用
- 需要 scratch buffer 时通过 `context.bufferPool.acquire(w, h)` 借用，用完 `release` 还回
- 像素写入循环里直接调 `context.setColor(x, y, color)` 或 `context.fillRect(...)`，不要包装

### 错误处理

- 不要在 `paint()` 抛异常，会让一帧绘制崩溃且 SDK 不会处理
- 边界检查（坐标越界等）在你自己代码里 guard 住，传给 `PixelBuffer.setPixel` 之前夹紧
