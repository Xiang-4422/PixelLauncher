# Widget 目录

pixel-engine 内置 widget 按职责分组。每个 widget 都是 `Widget` 接口的实例，可以自由嵌套组合。本文档列出公开 widget 的签名与典型用法。

> **import：** 所有 widget 都在 `com.purride.pixelui` 包，统一 `import com.purride.pixelui.*` 即可。

## 布局类

### `Row` / `Column`

线性排列子节点。`Row` 水平、`Column` 垂直。

```kotlin
Row(
    children: List<Widget>,
    spacing: Int = 0,
    mainAxisAlignment: MainAxisAlignment = MainAxisAlignment.START,
    crossAxisAlignment: CrossAxisAlignment = CrossAxisAlignment.START,
    mainAxisSize: MainAxisSize = MainAxisSize.MIN,
)

Column(/* 同上 */)
```

- `spacing` —— 相邻 child 之间的间距（像素）
- `mainAxisAlignment` —— 主轴上的对齐：`START` / `CENTER` / `END` / `SPACE_BETWEEN` / `SPACE_AROUND` / `SPACE_EVENLY`
- `crossAxisAlignment` —— 交叉轴对齐：`START` / `CENTER` / `END` / `STRETCH`

### `Stack`

层叠排列。后加入的 child 在上层。配合 `Positioned` 控制每个 child 的偏移。

```kotlin
Stack(
    children = listOf(
        Container(/* 背景 */),
        Positioned(top = 4, left = 4, child = Text("OVERLAY")),
    ),
)
```

### `Padding`

为 child 添加内边距。三种重载：

```kotlin
Padding(child, all = 4)                                   // 四边相等
Padding(child, padding = EdgeInsets.symmetric(horizontal = 2, vertical = 4))
Padding(child, horizontal = 4, vertical = 2)              // 对称简写
```

### `PaddingDirectional`

与 `Padding` 相同，但接受 `EdgeInsetsDirectional`（start/end 感知文字方向），适合 RTL 场景：

```kotlin
PaddingDirectional(child, padding = EdgeInsetsDirectional(start = 8, end = 4))
```

### `SafeArea`

读取 `MediaQuery.padding` 并转换成普通 `Padding`，用于避让系统栏、cutout 或宿主注入的边缘保留区：

```kotlin
SafeArea(
    child = content,
    minimum = PixelWindowInsets(top = 2),
)
```

宿主层 `PixelHostView` 会在 `onApplyWindowInsets` 中把 Android window insets 转成逻辑像素；测试或自定义宿主也可以直接调用：

```kotlin
hostView.setWindowInsets(left = 0, top = 4, right = 0, bottom = 6)
```

`MediaQueryData` 现在包含：

```kotlin
MediaQuery.of(context).padding      // SafeArea 默认消费
MediaQuery.of(context).viewPadding  // 宿主系统栏 / cutout 保留区
MediaQuery.of(context).viewInsets   // 宿主输入法 / 遮挡区，当前与 padding 同步
```

### `SizedBox`

固定尺寸的空盒（占位 / 间隔）：

```kotlin
SizedBox(width = 10, height = 10)
SizedBox(height = 4)        // 仅在 Column 中做垂直间距
```

### `Align` / `Center`

把 child 在自身可用区域内对齐。`Center` 等价于 `Align(alignment = Alignment.CENTER)`。

```kotlin
Center(child = Text("HELLO"))
Align(child = Text("HELLO"), alignment = Alignment.TOP_END)
```

### `AlignDirectional`

与 `Align` 相同，但使用 `AlignmentDirectional`（start/end 感知方向）：

```kotlin
AlignDirectional(child, alignment = AlignmentDirectional.TOP_START)
```

### `Wrap`

水平主轴自动换行布局，适合 chip、图标矩阵等固定小块：

```kotlin
Wrap(
    children = chips,
    spacing = 2,
    runSpacing = 2,
)
```

### `AspectRatio` / `ConstrainedBox` / `FittedBox`

最小约束组件：

```kotlin
AspectRatio(aspectRatio = 16f / 9f, child = preview)
ConstrainedBox(
    constraints = PixelBoxConstraints(minWidth = 24, minHeight = 12),
    child = Text("OK"),
)
FittedBox(child = preview) // contain-only，按整数像素 nearest 缩放并居中
```

### `Expanded` / `Flexible` / `Spacer`

在 `Row` / `Column` 中按 flex 因子分配剩余空间：

```kotlin
Row(children = listOf(
    Text("LEFT"),
    Spacer(),               // 占满中间所有剩余空间
    Text("RIGHT"),
))

Column(children = listOf(
    Text("HEADER"),
    Expanded(child = ListView(/* ... */)),  // 占满 Column 剩余高度
    Text("FOOTER"),
))
```

- `Expanded` = `Flexible` + `fit = FlexFit.TIGHT`（强制填满 flex 分配）
- `Flexible` 默认 `fit = LOOSE`（最大可达到 flex 分配，但允许更小）
- `Spacer` = `Expanded(child = SizedBox())`

## 内容类

### `Text`

显示一行或多行文本。

```kotlin
Text(
    data: String,
    style: TextStyle = TextStyle.Default,
    color: PixelColor? = null,          // 覆盖文本颜色
    textAlign: TextAlign = TextAlign.START,
    softWrap: Boolean = false,
    maxLines: Int = 1,
    overflow: PixelTextOverflow = PixelTextOverflow.CLIP,
)
```

样式：
- `TextStyle.Default` —— 默认白色像素字体
- `TextStyle(color = PixelColor.fromRgb(...))` —— 自定义颜色
- `TextStyle(textRasterizer = customFont)` —— 单条文本覆盖字体栅格器

彩色文本：
```kotlin
Text("hello", color = PixelColor.fromRgb(0, 200, 255))
```

多行：
```kotlin
Text(
    "LONG PARAGRAPH ...",
    softWrap = true,
    maxLines = 4,
    overflow = PixelTextOverflow.ELLIPSIS,
)
```

### `RichText`

带多 span 样式的富文本。

```kotlin
RichText(
    spans = listOf(
        PixelTextSpan(text = "NORMAL "),
        PixelTextSpan(
            text = "ACCENT",
            style = TextStyle(color = PixelColor.fromRgb(255, 200, 0)),
        ),
    ),
)
```

### `Container`

带可选填充 / 边框 / 对齐 / 尺寸的容器。

```kotlin
Container(
    child = Text("INSIDE"),
    width = 40,
    height = 16,
    fillColor = PixelColor.fromRgb(12, 18, 24),
    borderColor = PixelColor.fromRgb(120, 220, 255),
    alignment = Alignment.CENTER,
    padding = EdgeInsets.all(2),
)
```

`ContainerDirectional` 接受 `paddingDirectional`（START/END），其余等价。

### `DecoratedBox`

只做装饰（填充 + 边框），不参与尺寸约束。可包 / 不包 child：

```kotlin
DecoratedBox(
    child = Text("BORDERED"),
    fillColor = PixelColor.fromRgb(0, 0, 0),
    borderColor = PixelColor.fromRgb(255, 200, 0),
)
```

### `Image`

把不可变 [`PixelBitmap`](#pixelbitmap) 1:1 blit 到目标 buffer。

```kotlin
val bitmap: PixelBitmap = PixelBitmap.fromAndroidBitmap(androidBitmap)
Image(bitmap = bitmap)
```

- **Layout**：intrinsic 尺寸 = bitmap (width, height)，再按父约束 clamp。
- **Paint**：行级 `System.arraycopy`，超出 layout size 自动裁剪，不缩放。
- 缩放由调用方完成（如 `Bitmap.createScaledBitmap`）后再构造 `PixelBitmap`。
- 暂不支持 tint / 颜色变换。如需上色，构造 `PixelBitmap` 前自行处理像素数组。

#### `PixelBitmap`

不可变的像素位图源（ARGB IntArray）。与 `PixelBuffer` 区别：buffer 是
engine 每帧重用的可变绘制目标，bitmap 是用户提供的常驻图像源。

```kotlin
// 从 Android Bitmap 拷贝
val bitmap = PixelBitmap.fromAndroidBitmap(androidBitmap)

// 程序化构造
val pixels = IntArray(8 * 8) { i -> PixelColor.fromRgb(i, 0, 0).argb }
val bitmap = PixelBitmap(width = 8, height = 8, pixels = pixels)
```

#### `PixelBitmapAssetLoader` / `PixelBitmapResourceLoader`

从 Android asset 或 resource 解码 PNG 到 `PixelBitmap`：

```kotlin
val assetBitmap = PixelBitmapAssetLoader(context.assets).load("pixel/sample.png")
val resBitmap = PixelBitmapResourceLoader(context.resources).load(R.drawable.sample)
```

解码失败会抛 `PixelBitmapLoadException`，消息包含 asset 路径或 resource id。

### `Sprite`

从 [`PixelSpriteSheet`](#pixelspritesheet) 中选择一个 frame 1:1 blit，不缩放。

```kotlin
val sheet = PixelSpriteSheet(
    bitmap = bitmap,
    frames = listOf(
        PixelBitmapRegion(left = 0, top = 0, width = 8, height = 8),
        PixelBitmapRegion(left = 8, top = 0, width = 8, height = 8),
    ),
)

Sprite(sheet = sheet, frameIndex = 0)
```

- `frameIndex` 越界会抛 `IllegalArgumentException`。
- frame region 必须完全落在 bitmap 内。
- bitmap 像素按 `srcOver` 写入目标 buffer；`alpha = 0` 不覆盖目标像素，`alpha = 255` 走 opaque fast path。

#### `PixelSpriteSheet`

不可变 sprite sheet，持有一张 `PixelBitmap` 和一组 frame region。

```kotlin
data class PixelBitmapRegion(left: Int, top: Int, width: Int, height: Int)
data class PixelSpriteSheet(bitmap: PixelBitmap, frames: List<PixelBitmapRegion>)
```

`frames` 不能为空；region 的 `left/top >= 0`，`width/height > 0`。

`PixelSpriteSheetJsonLoader` 可解析 JSON manifest。`version` 和 `metadata` 可选；当前 schema 版本为 `1`，metadata 只保留字符串键值：

```json
{
  "version": 1,
  "bitmap": "sprites/runner.png",
  "metadata": { "name": "runner", "fps": "8" },
  "frames": [
    { "left": 0, "top": 0, "width": 8, "height": 8 }
  ]
}
```

`parseDefinition` 返回 `PixelSpriteSheetDefinition`，包含 bitmap path、schema version、metadata 和 frame regions；`load(json, bitmap)` 会直接构造 `PixelSpriteSheet` 并复用 region 越界校验。不支持的 `version` 会抛 `PixelSpriteSheetLoadException`。

需要保留 atlas trim / pivot / scale 信息时使用 schema v2 和 `parseAtlasDefinition` / `loadAtlas`：

```json
{
  "version": 2,
  "bitmap": "sprites/runner.png",
  "scale": 2,
  "frames": [
    {
      "left": 0, "top": 0, "width": 6, "height": 8,
      "sourceWidth": 10, "sourceHeight": 12,
      "trimLeft": 2, "trimTop": 3,
      "pivotX": 5, "pivotY": 12
    }
  ]
}
```

`parseAtlasDefinition` 返回 `PixelSpriteAtlasDefinition`；`loadAtlas` 返回可直接访问旧 sheet 与逐帧 metadata 的 `PixelSpriteAtlas`。

- `PixelSpriteFrameDefinition.region` 是 atlas 中实际存储的裁剪区域。
- `sourceWidth` / `sourceHeight` 是裁剪前画布大小，`trimLeft` / `trimTop` 是区域在原画布中的偏移。
- `pivotX` / `pivotY` 使用原画布坐标，允许落在 `0..sourceWidth` / `0..sourceHeight` 边界上。
- `scale` 必须为正整数，描述 atlas 导出倍率。
- `PixelSpriteAtlas.sheet` 保持旧 `PixelSpriteSheet` 的 1:1 region 绘制语义；metadata 供布局、锚点或资源工具显式使用，不会隐式缩放 `Sprite`。

#### `PixelResourceManifest`

`PixelResourceManifestJsonLoader` 可解析资源包级 manifest，把 bitmap 和 sprite sheet 以稳定 id 统一登记。schema v1 只负责基础资源数据校验；实际 Android asset/resource 解码仍由 `PixelBitmapAssetLoader` / `PixelBitmapResourceLoader` 完成。

```json
{
  "version": 1,
  "metadata": { "pack": "demo" },
  "bitmaps": [
    { "id": "runner", "path": "sprites/runner.png" }
  ],
  "spriteSheets": [
    { "id": "runnerRun", "path": "sprites/runner.sheet.json", "bitmap": "runner" }
  ]
}
```

`parse(json)` 返回 `PixelResourceManifest`，其中 `bitmaps` 为 `PixelBitmapResourceDefinition` 列表，`spriteSheets` 为 `PixelSpriteSheetResourceDefinition` 列表。parser 会拒绝不支持的版本、空字段、重复 id，以及引用不存在 bitmap id 的 sprite sheet，并抛出 `PixelResourceManifestLoadException`。

schema v2 通过 `parseCatalog(json)` 增加颜色和字体资源：

```json
{
  "version": 2,
  "bitmaps": [
    { "id": "icons", "path": "images/icons.png" }
  ],
  "colors": [
    { "id": "accent", "value": "#22AAFF" },
    { "id": "overlay", "value": "#80224466" }
  ],
  "fonts": [
    {
      "id": "ui8",
      "manifest": "glyphpacks/ui8/manifest.json",
      "binary": "glyphpacks/ui8/glyphs.bin"
    }
  ]
}
```

`parseCatalog` 返回 `PixelResourceCatalog`：颜色项是 `PixelColorResourceDefinition`，支持 `#RRGGBB` 和 `#AARRGGBB`；字体项是 `PixelFontResourceDefinition`，分别保存 glyph pack manifest 和 binary 路径。v1 manifest 不允许 colors/fonts；v2 catalog 要求 bitmap、sprite sheet、color、font 的 id 全局唯一。当前支持版本为 1 和 2，其它版本会给出明确错误。

#### `PixelResourceCache`

按 key 缓存 bitmap 和 sprite sheet，适合 host、demo scene 或业务资源 owner 持有：

```kotlin
val cache = PixelResourceCache()
val bitmap = cache.getBitmap("icons/home") { PixelBitmapAssetLoader(assets).load("icons/home.png") }
val sheet = cache.getSpriteSheet("runner") { PixelSpriteSheetJsonLoader.load(json, bitmap) }
cache.remove("runner")
cache.clear()
```

`snapshot()` 返回 `PixelResourceCacheSnapshot`，用于调试资源生命周期和加载策略：包含当前 bitmap / sprite sheet 数量、两类资源的 cache hit / miss 次数，以及实际发生的 `remove` / `clear` 次数。空 `remove` 或空 `clear` 不会增加生命周期计数。

## 图形原语

非矩形图形 widget。矩形请直接用 [`Container`](#container) / [`DecoratedBox`](#decoratedbox)。

### `PixelShapeStyle`

`PixelShapeStyle(color, filled = true, strokeWidth = 1, blendMode = PixelBlendMode.SrcOver)`
是 `Line` / `Circle` / `Polygon` / `Path` 和 `PixelCanvas` shape helper 的统一样式对象。
旧的 `color` / `filled` / `strokeWidth` 参数仍可继续使用；style 重载适合一组图形共享颜色、
填充策略、线宽和 blend mode。

```kotlin
val outline = PixelShapeStyle(
    color = PixelColor.White,
    filled = false,
    strokeWidth = 2,
)

Line(startX = 0, startY = 0, endX = 8, endY = 0, style = outline)
Circle(radius = 5, style = outline)
Polygon(points = listOf(/* ... */), style = outline)
Path(path = PixelPath.rect(left = 1, top = 1, width = 8, height = 6), style = outline)
```

### `Line`

直线（Bresenham 算法）。端点相对 widget 左上角。

```kotlin
Line(
    startX = 0, startY = 0,
    endX = 7, endY = 3,
    color = PixelColor.fromRgb(0xE0, 0xE0, 0xE0),
)
```

- **Layout**：intrinsic 尺寸 = `(max(startX, endX) + 1, max(startY, endY) + 1)`，父约束更紧时被 clamp。
- **Paint**：逐像素 `setPixel`；style 重载可指定整数 `strokeWidth` 和 `blendMode`。

### `Circle`

圆形 widget。圆心 = 当前 layout box 中点。

```kotlin
Circle(radius = 4, color = PixelColor.fromRgb(0xFF, 0xC0, 0x40))             // 填充
Circle(radius = 4, color = PixelColor.fromRgb(0xE0, 0xE0, 0xE0), filled = false) // 描边
```

- **Layout**：intrinsic 尺寸 = `(2 * radius + 1, 2 * radius + 1)`，父约束更紧时被 clamp。
- **Paint**：
  - `filled = true`（默认）：逐 scanline 填充。
  - `filled = false`：中点圆轮廓算法；style 重载可指定整数 `strokeWidth`。

适合 radio dot、状态指示、装饰圆点等场景。

### `Polygon`

多边形 widget。`filled = true` 使用 even-odd scanline 填充并绘制边界；
`filled = false` 连接相邻点并自动闭合轮廓；style 重载可指定整数 `strokeWidth`。

```kotlin
Polygon(
    points = listOf(PixelPoint(0, 6), PixelPoint(4, 0), PixelPoint(8, 6)),
    color = PixelColor.fromRgb(255, 192, 64),
    filled = true,
)
```

填充规则使用半开边区间避免顶点重复计数；水平边不参与 interior 交点计算，
但会作为边界线绘制。连续重复顶点和首尾重复点会被视为零长度边并跳过，
凹多边形按 even-odd 规则留下缺口。`Polygon` widget 与
`PixelCanvas.drawPolygon` 共用同一 rasterizer 和边界语义；`filled = true`
补绘边界时会跳过已经由填充阶段写入的像素，避免半透明颜色在边界重复 blend。

### `Path`

路径 widget。支持 `MoveTo` / `LineTo` / `QuadraticTo` / `CubicTo` / `Close`、
整数 `strokeWidth` 或 `PixelShapeStyle`，以及 `PixelPath.rect(...)` / `PixelPath.circle(...)` helper。

```kotlin
Path(
    path = PixelPath(
        commands = listOf(
            PixelPathCommand.MoveTo(PixelPoint(0, 5)),
            PixelPathCommand.QuadraticTo(
                control = PixelPoint(3, 0),
                end = PixelPoint(6, 5),
            ),
            PixelPathCommand.CubicTo(
                control1 = PixelPoint(8, 0),
                control2 = PixelPoint(10, 0),
                end = PixelPoint(12, 5),
            ),
            PixelPathCommand.Close,
        ),
    ),
    color = PixelColor.White,
    strokeWidth = 2,
)
```

二次/三次曲线在 paint 时按控制折线长度确定 1..256 个采样段，再取整为
Bresenham 线段。`Path` widget 与 `PixelCanvas.drawPath` 共用同一 flattener，
因此相同命令会产生一致像素；采样循环不创建中间 `PixelPoint` 对象。Path 暂不支持
填充和 gradient stroke；`PixelShapeStyle.filled` 对 Path 暂不生效。

`closed = true` 时，即使命令里没有 `Close`，也会把最后一个点连回当前 subpath 起点。

```kotlin
Path(PixelPath.rect(left = 1, top = 1, width = 12, height = 8), color = PixelColor.White)
Path(PixelPath.circle(centerX = 8, centerY = 8, radius = 5), color = PixelColor.White)
```

### `CustomPaint` / `PixelCanvas`

`CustomPaint` 提供一次性批量绘制 API，适合业务在一个 render object 内组合多个低层像素命令，避免拆成大量 `Line` / `Circle` / `Polygon` 节点。

```kotlin
CustomPaint(width = 42, height = 28) {
    fillRect(0, 0, 42, 28, PixelColor.fromRgb(20, 20, 20))
    fillGradientRect(
        left = 2,
        top = 2,
        width = 12,
        height = 6,
        gradient = PixelGradient.Linear(
            start = PixelPoint(2, 2),
            end = PixelPoint(13, 2),
            stops = listOf(
                PixelGradientStop(0f, PixelColor.fromRgb(40, 80, 180)),
                PixelGradientStop(1f, PixelColor.fromRgb(255, 192, 64)),
            ),
        ),
    )
    fillRect(34, 2, 4, 4, PixelColor.White, blendMode = PixelBlendMode.Clear)
    drawRect(0, 0, 42, 28, PixelColor.White, strokeWidth = 2)
    drawLine(2, 24, 39, 3, PixelColor.fromRgb(255, 192, 64), strokeWidth = 2)
    drawCircle(11, 9, 5, PixelColor.fromRgb(80, 180, 110), filled = false, strokeWidth = 2)
    drawPolygon(
        points = listOf(PixelPoint(24, 20), PixelPoint(31, 8), PixelPoint(38, 20)),
        color = PixelColor.fromRgb(120, 160, 255),
        filled = true,
    )
    drawPath(path = PixelPath(listOf(/* MoveTo / LineTo / Close */)), color = PixelColor.White)
}
```

`PixelCanvas` 坐标相对 `CustomPaint` 左上角；越界像素由底层 `PixelBuffer` 裁剪。当前支持整数 `strokeWidth`、`PixelShapeStyle` 便捷重载、二次/三次 Path 曲线、`PixelBlendMode.SrcOver` / `Src` / `Clear`，以及 `PixelGradient.Linear` / `PixelGradient.Radial` 填充。需要动画渐变时，用 `PixelGradientTween` 配合 `TweenAnimationBuilder` 生成每帧 gradient 后传给 `fillGradientRect`。

## 按钮与选择控件

### `OutlinedButton`

像素风边框按钮。

```kotlin
OutlinedButton(
    text: String,
    onPressed: (() -> Unit)?,
    style: ButtonStyle = ButtonStyle.Default,
    enabled: Boolean = true,
    fillColor: PixelColor? = null,   // 覆盖填充色
    borderColor: PixelColor? = null, // 覆盖边框色
)
```

- `onPressed = null` 等价于禁用态（不响应点击）

## 输入、表单与焦点

### `TextField`

像素风文本输入框。需要先创建 `PixelTextFieldController` 和 `state`，详见 [状态管理](状态管理.md)。

```kotlin
private val tfController = PixelTextFieldController()
private val tfState = tfController.create()

TextField(
    state = tfState,
    controller = tfController,
    placeholder = "ENTER NAME",
    inputType = PixelInputType.TEXT,
    textInputAction = TextInputAction.DONE,
    onSubmitted = { value -> /* ... */ },
)
```

- `inputType` —— `TEXT` / `NUMBER` / `NUMBER_PASSWORD` / `EMAIL` / `PHONE` / `URL` / `PASSWORD`
- `textInputAction` —— 系统软键盘 action 按钮；公开枚举是 `PixelTextInputAction`，常用别名是 `TextInputAction`，取值为 `DONE` / `NEXT` / `SEND` / `SEARCH` / `GO`
- `focusNode` —— 可选 `FocusNode`；TextField 获得点击/IME 焦点时会同步节点，
  节点通过 `FocusScope` 遍历获得焦点时也会请求对应 TextField 焦点。
- **光标**：聚焦且 enabled 且非 readOnly 时，自动按当前 `selectionStart` 绘制 1px 光标（颜色取自
  [`PixelTextFieldStyle.cursorColor`](#textfieldstyle)）。空文本时光标在内容区左缘，多行文本会按 selection 所在行定位。默认开启闪烁，可通过
  `TextFieldStyle(cursorBlinkEnabled = false)` 关闭，或用 `cursorBlinkPeriodMs` 调整周期。
- **选区 / composition**：`selectionStart != selectionEnd` 时绘制选区色；IME composition 区段在聚焦时绘制 1px 下划线。多行文本会按行拆分选区和 composition，不再把跨行范围画成一整块。
- **选词**：`PixelTextFieldController.selectWordAt(state, index)` 可按字符 index 选中 ASCII 单词；宿主双击、长按以及 `PixelTester.doubleTap` / `PixelTester.longPress` 会复用该语义。
- **selection handle**：非空 selection 会绘制 start/end 两个最小拖拽 handle，颜色由 `selectionHandleColor` 控制，可通过 `selectionHandlesEnabled = false` 关闭；readOnly/disabled 不绘制也不允许拖动。handle 命中和拖动使用当前 `RenderText` 的行级 caret 映射，跨行 selection 会按实际渲染行移动。
- **平台编辑菜单**：Android host 中长按或双击选词后显示浮动
  `ActionMode`，按当前状态提供 Copy / Cut / Paste / Select all。Cut/Paste 会走
  `PixelTextFieldController` 并触发 `onChanged`；readOnly 字段不会导出修改动作。

### `Focus` / `FocusScope`

最小焦点系统用于键盘、手柄和 IME `NEXT` 行为。`FocusNode` 持有单个可聚焦节点状态，`FocusScopeNode` 持有作用域内的节点列表并按 `FocusTraversalPolicy` 遍历。默认策略是 `ReadingOrderFocusTraversalPolicy`，按 widget 构建顺序处理 `PixelFocusDirection.NEXT` / `PREVIOUS` / 方向键。网格场景可使用 `GridFocusTraversalPolicy(columns)`，方向键会按固定列数上下左右移动。

```kotlin
val nameFocus = FocusNode("name")
val nextFocus = FocusNode("next")

FocusScope(
    traversalPolicy = GridFocusTraversalPolicy(columns = 3),
    child = Column(
        children = listOf(
            Focus(
                node = nameFocus,
                autofocus = true,
                onKeyEvent = { event: PixelKeyEvent -> event.key == PixelKey.ENTER },
                child = Text("NAME"),
            ),
            Focus(node = nextFocus, child = Text("NEXT")),
        ),
    ),
)
```

- `PixelFocusManager.primaryFocus` 表示当前主焦点。
- `PixelKey.TAB` / `SHIFT_TAB` / `ARROW_*` 会触发默认遍历。
- Android 宿主会把 DPAD 方向键、A/Start 确认键映射到 `ENTER`，把 B/Select/Mode 映射到 `BACK`。
- Android joystick / gamepad 轴事件会按死区和 repeat interval 转成方向键，长按摇杆时连续移动焦点但不会每帧重复触发。
- `GridFocusTraversalPolicy` 保留 `TAB` 的阅读顺序，同时让 `ARROW_UP/DOWN` 按 `columns` 跨行移动。
- focused node 的 `onKeyEvent` 优先处理 `PixelKeyEvent`，返回 `true` 时事件被消费。
- `TextField(textInputAction = TextInputAction.NEXT)` 提交后会触发焦点下一项遍历。

滚动列表中的焦点项可以用 `PixelFocusScrollTarget` 保持可见：

```kotlin
Focus(
    node = rowFocus,
    scrollTarget = PixelFocusScrollTarget(
        state = listState,
        controller = listController,
        itemIndex = rowIndex,
    ),
    child = ListTile(title = Text("Row $rowIndex")),
)
```

`CustomScrollView` 的 lazy sliver 额外传 `sliverIndex`；Focus 会在滚动几何可用后执行一次最小位移滚动，避免每帧重复 notify。

宿主也可以直接执行当前字段的编辑动作：

```kotlin
hostView.performFocusedTextEditAction(PixelTextEditAction.COPY)
hostView.performFocusedTextEditAction(PixelTextEditAction.PASTE)
```

自定义 `PixelHostBridge` 可覆写 `readClipboardText()` /
`writeClipboardText(text)`；默认方法为空实现，Android
`PixelTextInputBridge` 使用系统 `ClipboardManager`。

### `Form` / `FormField` / `Validator`

`Form` 提供独立 `FocusScope` 和字段注册作用域。`FormController` 负责注册当前
挂载的字段并执行 `validate()` / `reset()`；`FormFieldState<T>` 持有字段值和
错误文本；`Validator<T>` 是 `(T) -> String?`，返回 `null` 表示通过，返回字符串
表示错误：

```kotlin
val form = FormController()
val name = FormFieldState("")
val nameFocus = FocusNode("name")

Form(
    controller = form,
    child = FormField(
        state = name,
        fieldId = "name",
        focusNode = nameFocus,
        validator = { value -> if (value.isBlank()) "required" else null },
    ) { _, field ->
        Column(
            children = listOfNotNull(
                Text("NAME"),
                TextField(
                    state = textState,
                    controller = textController,
                    onChanged = { value -> field.setValue(value) },
                ),
                field.errorText?.let { Text(it) },
            ),
        )
    },
)

val ok = form.validate()
form.reset()
```

`FormField(focusNode = ...)` 会把字段加入 Form 自己的 FocusScope；字段 builder
中的 TextField 会自动继承该节点，因此 `TextInputAction.NEXT` 可直接移动到下一
字段。业务仍通过 `TextField.onChanged` 同步 `FormFieldState.setValue()`。

跨字段校验使用稳定 `fieldId` 和 `FormValidator`。validator 接收当前命名字段值
快照，返回 `fieldId -> errorText`：

```kotlin
val form = FormController(
    validators = listOf { values ->
        if (values["password"] == values["confirmation"]) {
            emptyMap()
        } else {
            mapOf("confirmation" to "does not match")
        }
    },
)
```

重复 `fieldId` 或 validator 返回未注册 id 会抛出包含字段名的诊断错误。

自定义字段可以直接调用
`FormController.registerField(state, validator, fieldId)` 接入同一个校验队列；
返回的 `FormFieldRegistration` 需要在自定义 widget dispose 时调用 `dispose()`。

### `Semantics`

为子树补充基础可访问性语义；Text、TextField、OutlinedButton、ListTile、Checkbox、Switch、Tabs 和 SegmentedControl 会自动导出常用语义，业务自定义控件可用 `Semantics` 显式声明：

```kotlin
Semantics(
    label = "保存",
    role = PixelSemanticRole.BUTTON,
    enabled = true,
    focused = false,
    child = CustomButton(),
)
```

`PixelSemanticsNode` 包含 `label`、`role`、`enabled`、`focused` 和 bounds；测试可用 `PixelTester.dumpSemanticsTree()` 检查导出的 semantic tree。

## 滚动 / 翻页

### `ListView`

固定 items 列表（已知所有 child）：

```kotlin
ListView(
    items = listOf(Text("A"), Text("B"), Text("C")),
    state = listState,
    controller = listController,
    spacing = 2,
)
```

### `ListViewBuilder`

按 index 构造列表（带可选 lazy 渲染）：

```kotlin
ListViewBuilder(
    itemCount = 100,
    itemBuilder = { index -> Text("ITEM $index") },
    state = listState,
    controller = listController,
    spacing = 2,
    itemExtent = 12,    // 必传以启用 lazy 渲染（每 item 固定高度，单位像素）
    cacheExtent = 1,    // 可见区上下额外预渲染的页数
)
```

> ⚠️ **lazy 与 eager 的分界**：`itemExtent` **传入时走固定高度 lazy 路径**（只构造可见区 + `cacheExtent` 范围内的 item）。如果 item 高度不固定，可以传 `estimatedItemExtent` 显式启用变高 lazy 路径。不传 `itemExtent` 且不传 `estimatedItemExtent` 时回退到 eager 路径：一次性调 `itemBuilder` 构造所有 `itemCount` 个 widget。
>
变高 lazy 示例：

```kotlin
ListViewBuilder(
    itemCount = 1_000,
    itemBuilder = { index ->
        SizedBox(
            height = if (index % 5 == 0) 18 else 10,
            child = Text("ROW $index"),
        )
    },
    state = listState,
    controller = listController,
    estimatedItemExtent = 12, // 显式 opt-in，未测 item 会先按该高度估算
    cacheExtent = 2,
)
```

`itemExtent` 优先级高于 `estimatedItemExtent`。`estimatedItemExtent <= 0` 会按 eager 兼容路径处理。

### `GridView` / `GridViewBuilder`

固定 cell 宽高的二维垂直滚动网格，复用 `PixelListState` / `PixelListController`：

```kotlin
GridViewBuilder(
    itemCount = 100,
    itemBuilder = { index -> Text("$index") },
    cellWidth = 12,
    cellHeight = 10,
    state = listState,
    controller = listController,
    spacing = 2,
    runSpacing = 2,
    cacheExtent = 1,
)
```

`GridView` 接收完整 `items` 列表；`GridViewBuilder` 只构造可见窗口和 cache 范围内的 item。当前网格只支持垂直滚动和固定 cell extent。需要键盘/手柄导航时，把 cell 包在 `Focus` 中，并用外层 `FocusScope(traversalPolicy = GridFocusTraversalPolicy(columns = ...))` 固定方向键移动规则。

List/Grid/CustomScrollView 复用 `PixelListController.saveState()` / `restoreState()` 保存滚动 offset；恢复时传入当前 viewport/content 高度，默认按绝对 offset 夹紧。配置变化导致尺寸改变时，可传 `policy = PixelListRestorationPolicy.RelativeProgress` 保持原来的相对滚动进度。

### `CustomScrollView` / `SliverList` / `SliverListBuilder` / `SliverPinnedHeader` / `SliverAppBar`

`CustomScrollView` v1 复用 `PixelListState` / `PixelListController`，接收 sliver 描述列表。当前公开 sliver 包括：

- `SliverList(items, spacing)`：普通垂直滚动流，v1 为 eager children。
- `SliverListBuilder(itemCount, itemBuilder, itemExtent, estimatedItemExtent, spacing, cacheExtent)`：固定高度时传 `itemExtent`；变高 item 时传 `estimatedItemExtent` 显式启用估算 lazy sliver。两条路径都只构造可见窗口和 cache 范围内的 children。
- `SliverPinnedHeader(child)`：参与内容高度计算，滚过自身后固定在视口顶部；存在多个 pinned sliver 时按声明顺序堆叠，并继续导出点击、输入、滚动等 target。
- `SliverAppBar(child, expandedHeight, collapsedHeight, floating, snap, stretch, stretchLimit)`：参与内容高度计算，滚过后把 `child` 向上裁剪到 `collapsedHeight`。`floating` 让反向滚动提前浮出 AppBar；`snap` 在释放后吸附到展开/收起边界且要求 `floating = true`；`stretch` 配合启用 bounce 的 `PixelListController`，在顶部 overscroll 时最多拉伸 `stretchLimit` 像素。后续 pinned header 会从 AppBar 当前可见高度下方开始堆叠。

这些工厂分别返回公开 sliver 描述类型 `PixelSliverList`、`PixelSliverListBuilder`、`PixelSliverPinnedHeader` 和 `PixelSliverAppBar`；业务通常使用工厂函数即可，只有在需要暂存或组合 sliver 描述时才直接引用这些类型。

```kotlin
CustomScrollView(
    state = listState,
    controller = listController,
    slivers = listOf(
        SliverPinnedHeader(
            child = Container(
                fillColor = PixelColor.fromRgb(230, 180, 60),
                child = Text("PINNED"),
            ),
        ),
        SliverAppBar(
            expandedHeight = 18,
            collapsedHeight = 8,
            floating = true,
            snap = true,
            stretch = true,
            stretchLimit = 10,
            child = Text("APP BAR"),
        ),
        SliverList(
            spacing = 1,
            items = List(40) { index -> Text("ROW $index") },
        ),
        SliverListBuilder(
            itemCount = 1_000,
            estimatedItemExtent = 10,
            spacing = 1,
            itemBuilder = { index -> Text("ROW $index") },
        ),
    ),
)
```

`Scrollbar` 可以直接包裹 `CustomScrollView`，thumb 拖动会同步同一个 `PixelListState`。lazy sliver builder 已支持固定 `itemExtent` 和估算 `estimatedItemExtent` 两种路径；每个 lazy sliver 按 `sliverIndex` 隔离虚拟几何和变高测量缓存，可用 `PixelListController.scrollSliverItemIntoView(state, sliverIndex, itemIndex)` 定位远端 item，并在测量后自动二次校正。pinned header/app bar 已按声明顺序堆叠且不会互相覆盖，AppBar 也已支持 floating/snap/stretch。

### `Scrollbar`

包裹任意使用 `PixelListState` 的垂直滚动区域（List/Grid/SingleChildScrollView），在右侧绘制像素窄条。滚动条会从子树中的 List/Grid target 推导 controller，因此 thumb 可直接拖动并同步更新同一个 `PixelListState`：

```kotlin
Scrollbar(
    state = listState,
    width = 2,
    thumbColor = PixelColor.White,
    child = GridViewBuilder(/* ... */),
)
```

### `RefreshIndicator`

包裹任意使用 `PixelListState` 的垂直滚动区域，在列表位于顶部时接管向下拖拽。`PixelRefreshIndicatorState` 记录 pull / armed / refreshing 状态，`PixelRefreshIndicatorController` 负责开始、更新、释放和完成刷新；`onRefresh` 只表示阈值达成后的回调，不绑定网络或异步任务：

```kotlin
val refreshController = PixelRefreshIndicatorController()
val refreshState = refreshController.create()

RefreshIndicator(
    state = refreshState,
    controller = refreshController,
    thresholdPx = 12,
    onRefresh = { /* start loading */ },
    child = ListViewBuilder(/* ... */),
)

// 数据刷新结束后由业务层显式调用
refreshController.completeRefresh(refreshState)
```

### `ListViewSeparated`

在 items 之间插入分隔 widget：

```kotlin
ListViewSeparated(
    itemCount = 20,
    itemBuilder = { i -> Text("ROW $i") },
    separatorBuilder = { _ -> DecoratedBox(fillColor = PixelColor.fromRgb(80, 80, 80)) },
    state = listState,
    controller = listController,

```

`ListViewSeparated` 是 eager API，会一次性构造全部 item 和 separator。长列表请使用 lazy builder：

```kotlin
ListViewSeparatedBuilder(
    itemCount = 1_000,
    itemBuilder = { i -> Text("ROW $i") },
    separatorBuilder = { _ -> DecoratedBox(fillColor = PixelColor.fromRgb(80, 80, 80)) },
    state = listState,
    controller = listController,
    estimatedItemExtent = 12,
    estimatedSeparatorExtent = 1,
```

### `ListViewSeparatedBuilder`

真实 item 的滚动定位仍按 item index 工作：`controller.scrollItemIntoView(state, itemIndex)` 定位的是第 `itemIndex` 个 item，不会把 separator 算作 item；远端变高 item 会在真实测量后自动二次校正。

## 状态辅助 widget

### `Builder`

延迟构建子树，让 child 能拿到自己的 `BuildContext`。lambda 类型是 `WidgetBuilder`（即 `(BuildContext) -> Widget` 的 typealias）：

```kotlin
Builder { context ->
    Text("W: ${MediaQuery.of(context).logicalWidth}")
}
```

### `StatefulBuilder`

最轻量的局部 state holder。lambda 类型是 `(BuildContext, StateSetter) -> Widget`：

```kotlin
StatefulBuilder { context, setState ->
    var count = 0
    Column(children = listOf(
        Text("$count"),
        OutlinedButton(text = "+1", onPressed = { setState { count++ } }),
    ))
}
```

`StateSetter` 是 `(() -> Unit) -> Unit` 的 typealias，即接受一个无返回 lambda 并触发重建。

> ⚠️ 注意：`StatefulBuilder` 的 lambda 在每次重建都会执行。把状态变量放在 lambda 内只对最简单的 demo 适用——真实业务请用 `ValueNotifier` 或 `StatefulWidget`。

### `ListenableBuilder`

订阅一个 `Listenable`，每当它通知就重建 child：

```kotlin
ListenableBuilder(listenable = myListController) {
    Text("CURRENT OFFSET: ${listState.scrollOffsetPx}")
}
```

### `ValueListenableBuilder<T>`

订阅 `ValueListenable<T>`，每次值变化就重建并把新值传给 builder：

```kotlin
val counter = ValueNotifier(0)

ValueListenableBuilder(listenable = counter) { _, value ->
    Text("$value")
}
```

### `AsyncBuilder<T>`

订阅 `PixelAsyncSource<T>` 并按当前 snapshot 重建子树。pixel-engine 不依赖
`kotlinx.coroutines`；source 是一个最小 callback 协议，调用方按需把 `Flow` /
`Future` / 任意异步框架适配进来。

```kotlin
AsyncBuilder(source = appListSource) { _, snapshot ->
    when (snapshot) {
        is PixelAsyncSnapshot.Loading -> Text("LOADING…")
        is PixelAsyncSnapshot.Success -> AppList(snapshot.value)
        is PixelAsyncSnapshot.Failure -> Text("ERR: ${snapshot.error.message}")
    }
}
```

`PixelAsyncSource<T>` 是 `fun interface`：

```kotlin
fun interface PixelAsyncSource<T> {
    fun subscribe(listener: (PixelAsyncSnapshot<T>) -> Unit): () -> Unit
}
```

适配 Coroutines `Flow` 示例：

```kotlin
fun <T> Flow<T>.asPixelAsyncSource(scope: CoroutineScope): PixelAsyncSource<T> =
    PixelAsyncSource { listener ->
        val job = scope.launch {
            catch { e -> listener(PixelAsyncSnapshot.Failure(e)) }
                .collect { listener(PixelAsyncSnapshot.Success(it)) }
        }
        return@PixelAsyncSource { job.cancel() }
    }
```

生命周期：`initState` 订阅、`didUpdateWidget` 在 source 变化时重订、`dispose`
取消。同步 emit 安全：source 在 `subscribe` 调用栈内立刻发的值会直接写入
snapshot（不走 `setState`，避免 element owner 未初始化时报错）。

辅助函数 `pixelAsyncSourceOf(value)` 用于把同步值包成立即 emit Success 的 source。

## 导航

### `PixelNavigator`

Flutter 风格的栈式导航 widget。`PixelNavigator` 保留 route stack，
`PixelNavigator.of(context)` 可在 route 子树里取得 `PixelNavigatorState`。

```kotlin
PixelNavigator(
    initialRoute = PixelRoute("home") { context ->
        Column(children = listOf(
            Text("HOME"),
            OutlinedButton(
                text = "DETAIL",
                onPressed = {
                    PixelNavigator.of(context).push(
                        PixelRoute("detail") { Text("DETAIL") },
                    )
                },
            ),
        ))
    },
    vsync = tickerProvider,
)
```

`PixelNavigatorState`：

```kotlin
state.push(route)
state.push(route) { result -> ... }
state.pop(): Boolean
state.pop(result): Boolean
state.maybePop(): Boolean
state.maybePop(result): Boolean
state.popToRoot()
state.popToRoot(animated = true)
state.replace(route)
state.replace(route, animated = true)
state.snapshot(): PixelNavigatorSnapshot
state.restore(snapshot, routeRegistry)
state.saveToBundle(outState)
state.restoreFromBundle(savedInstanceState, routeRegistry)
state.handleDeepLink(uri, resolver)
state.handleDeepLink(link, resolver, animated = true)
state.canPop
```

`PixelRoute(canPop = { ... })` 可拦截 `pop()` / `maybePop()`，用于未保存表单等确认场景。`PixelRoute(onEnter/onExit/onDispose)` 可观察 route 生命周期，dispose 会在离场转场完成后触发。
`state.snapshot()` 返回 `PixelNavigatorSnapshot`；`state.restore(snapshot, routeRegistry)` 可按 route name 栈恢复基础导航状态。

Lifecycle 时序：

- 创建 navigator：initial route `onEnter`
- `push`：旧 route `onExit` → 新 route `onEnter`；旧 route 仍在栈中，不 dispose
- `pop`：离场 route `onExit` → 返回 route `onEnter` → 动画 settle 后离场 route `onDispose`
- `replace`：旧 route `onExit` → 新 route `onEnter` → settle 后旧 route `onDispose`
- `popToRoot`：当前 route `onExit` → root `onEnter` → settle 后所有移除 route `onDispose`
- 非动画 replace/popToRoot：`onDispose` 在本次状态修改中立即执行
- `restore`：当前 route `onExit`，未被复用的旧 route 立即 dispose，恢复栈顶 `onEnter`

`onExit` 表示 route 失去前台，不代表对象已经释放。动画中又开始新导航时，上一轮挂起的
待 dispose route 会先释放，避免 transition 被打断后泄漏。

Route result：

```kotlin
navigator.push(editRoute) { result ->
    if (result == "saved") refresh()
}

// editRoute 内
navigator.pop("saved")
```

结果在离场动画 settle、route `onDispose` 之后交付。`canPop` guard 阻止返回时不会
触发结果回调；`replace` 保留当前栈位的回调，因此 replacement 最终 pop 时仍会把结果
交给最初的调用方。`popToRoot` 和 `restore` 会用 `null` 完成被移除 route 的等待回调。
同一个 `PixelRoute` 对象重复 push 时，每个栈位的回调相互独立。

结果回调只存在于当前进程内，不进入 `PixelNavigatorSnapshot` 或 Android `Bundle`；
配置恢复后的 route stack 不会恢复旧 lambda。

Deep link 使用纯 Kotlin `PixelDeepLink` / `PixelDeepLinkResolver`，core 不依赖
Android `Intent` 或 `android.net.Uri`。resolver 返回完整 route stack，返回 `null`
表示不匹配：

```kotlin
val handled = navigator.handleDeepLink(
    "pixel://shop/product?id=42",
    PixelDeepLinkResolver { link ->
        if (link.host == "shop" && link.pathSegments == listOf("product")) {
            listOf(
                homeRoute,
                productRoute(id = requireNotNull(link.queryParameter("id"))),
            )
        } else {
            null
        }
    },
)
```

`PixelDeepLink.parse()` 会解析并 percent-decode scheme、host、path segment、
重复 query 参数和 fragment；`queryParameter(name)` 返回第一个值。匹配成功后
Navigator 原子替换整个栈，默认以 `Replace` 转场进入新栈顶；`animated = false`
立即完成。旧栈的 route result 以 `null` 完成，未复用 route 在转场 settle 后 dispose。
resolver 返回空列表会抛出包含原始 URI 的可诊断异常；未匹配时返回 `false`，栈和
lifecycle 均不变化。宿主可自行从 `Intent.dataString` 调用该 API。

Android 配置变更可用同一 route name 栈写入 `Bundle`。`routeRegistry` 负责把 name
映射回当前进程里的 `PixelRoute` 对象；SDK 不序列化 route builder：

```kotlin
private val routeRegistry = mapOf(
    "home" to homeRoute,
    "detail" to detailRoute,
)

override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    navigatorState.saveToBundle(outState)
}

override fun onCreate(savedInstanceState: Bundle?) {
    // 创建 PixelNavigator 后，拿到 PixelNavigatorState：
    navigatorState.restoreFromBundle(savedInstanceState, routeRegistry)
}
```

需要自定义 key 时，可使用 `PixelNavigatorBundleKey` 或直接传入 `key` 参数；
也可以调用 `snapshot.saveToBundle(outState, key)` 与
`bundle.getPixelNavigatorSnapshot(key)` 自行管理 snapshot。

`PixelRouteScrollRestoration` 自动保存同一路由里的 List/Grid/CustomScrollView
位置。`restorationId` 在单个 route 内必须唯一；route 暂时被 push 覆盖后再 pop
回来时，新创建的 `PixelListState` 会在首次拿到真实 viewport/content 几何后恢复，
避免初始 0 尺寸把 offset 提前夹成 0：

```kotlin
PixelRouteScrollRestoration(
    restorationId = "feed",
    state = listState,
    controller = listController,
    policy = PixelListRestorationPolicy.AbsoluteOffset,
    child = ListView(
        items = rows,
        state = listState,
        controller = listController,
    ),
)
```

保存桶按 `PixelRoute` 对象身份隔离；route 被 pop/replace 并完成离场动画后会随
route 一起释放，不会成为进程级全局缓存。

Route transition：

```kotlin
PixelRouteTransition.None
PixelRouteTransition.Fade
PixelRouteTransition.SlideHorizontal
PixelRouteTransition.SlideVertical
```

`SlideHorizontal` / `SlideVertical` 使用整数 offset 转场；`Fade` 在 alpha blend
落地后走真实半透明合成。route lifecycle、pop guard 和基础 snapshot/restore 已接入。

自定义 route transition：

```kotlin
PixelRoute(
    name = "detail",
    builder = { Text("DETAIL") },
    transitionBuilder = PixelRouteTransitionBuilder {
        progress, operation, outgoing, incoming ->
        val direction = if (operation == PixelNavigatorOperation.Pop) -1 else 1
        Stack(children = listOf(
            Transform.translate(
                IntOffset((-progress * 8 * direction).toInt(), 0),
                outgoing,
            ),
            Transform.translate(
                IntOffset(((1f - progress) * 16 * direction).toInt(), 0),
                incoming,
            ),
        ))
    },
)
```

Navigator 负责 ticker、`progress` 0→1 和 settle/dispose；builder 只组合当前帧。
push/replace 使用 incoming route 的 builder，pop 使用 outgoing route 的 builder。
若 route 没有 builder，则回退到 `PixelNavigator.transitionBuilder`，最后才使用内建
`PixelRouteTransition`。

### `PixelHostView.dumpElementTree(): String`

### `PixelHostView.inspect(): PixelInspectorSnapshot`

一次性采样 host 调试快照，用于调试面板、log dump 或崩溃诊断：

```kotlin
val snapshot = hostView.inspect(includeAllocationSample = true)
snapshot.targetCounts.textInput
snapshot.allocationSample?.usedHeapBytes
snapshot.elementTree
snapshot.renderTree
snapshot.semanticsTree
```

`PixelInspectorSnapshot` 包含：

- `frameStats`
- `allocationSample: PixelInspectorAllocationSample?`
- `targetCounts: PixelInspectorTargetCounts`
- `targetSnapshots: List<PixelInspectorTargetSnapshot>`
- `elementTree` / `renderTree` / `semanticsTree`
- `hasPendingBuild`
- `focusedTextInput`
- `activePagerCount` / `activeListCount`
- `activeSlider` / `activeScrollbar` / `activeRefresh`

`PixelInspectorTargetCounts` 记录当前渲染结果导出的 click / pager / list /
scrollbar / refresh / textInput / slider / semantics 目标数量。

`PixelInspectorTargetSnapshot` 记录每个目标的 `kind`、`left/top/width/height`、
诊断 `detail`，以及可空的 `elementPath` / `renderPath`。正常 widget runtime
导出的目标会精确关联到产生它的 retained element 和 render object；手工提交的
`PixelRenderResult` 或没有 source 的测试目标保持 `null`，面板显示 `<unlinked>`。
路径包含 sibling index，可区分同类型相邻节点。该摘要不会暴露内部 controller、
state 或 render object 引用，可安全用于 debug panel、日志或崩溃报告。

在 `TARGETS` tab 选中目标后，面板会额外显示 `E ...` 和 `R ...` 两行路径；
它们与 bounds overlay 的 `selectedTarget` 使用同一快照对象，因此可以从画面命中区域
直接定位到对应 element/render 节点。

`includeAllocationSample` 默认关闭；打开后 `allocationSample` 会读取当前 JVM
heap 的 used / total / max 字节数。它用于调试趋势观察，不等同于严格的“本帧分配字节数”，
也不应放进每帧热路径。

## InheritedWidget

跨子树共享数据，并在数据变化时只重建依赖的子树：

```kotlin
class UserScope(
    val userName: String,
    override val child: Widget,
) : InheritedWidget(child = child) {
    override fun updateShouldNotify(old: InheritedWidget): Boolean =
        userName != (old as? UserScope)?.userName

    companion object {
        fun of(context: BuildContext): String =
            context.dependOnInheritedWidgetOfExactType<UserScope>()?.userName ?: "ANON"
    }
}

// 在树顶部注入：
UserScope(
    userName = "ALICE",
    child = MyApp(),
)

// 子节点读取：
Builder { context ->
    Text("HI ${UserScope.of(context)}")
}
```

SDK 内置的 `Directionality` / `MediaQuery` / `DefaultTextRasterizer` 都是 `InheritedWidget` 子类。

## 动画

> **import：** 动画 widget 在 `com.purride.pixelui.widgets.animated`，核心类型（Controller / Tween / Curves）在 `com.purride.pixelui.animation`。

pixel-engine 动画系统遵循**离散优先**原则：所有隐式动画 widget 默认使用 `Curves.Step(8)` 曲线，保持像素风格的格格感；若需要更平滑的过渡，可通过 `curve` 参数指定其他曲线。

### `TweenAnimationBuilder<T>`

通用隐式动画框架：当 `tween.end` 变化时自动从当前值补间到新值。

```kotlin
TweenAnimationBuilder(
    tween = IntTween(begin = 0, end = width),
    duration = 300.milliseconds,
    vsync = vsync,
    builder = { ctx, value ->
        Container(width = value, height = 16, borderColor = PixelColor.White)
    },
)
```

- `tween` — 任意 `Tween<T>`：`IntTween` / `EdgeInsetsTween` / `OffsetTween` / `PixelColorTween` / `PixelGradientTween`
- `builder` — `(BuildContext, T) -> Widget`，每帧以当前插值调用
- `curve` — 默认 `Curves.Step(8)`；可替换为 `Curves.Linear` / `Curves.EaseOut` 等
- `onEnd` — 动画完成时回调

### `AnimatedContainer`

属性级别隐式动画。多个属性可共享一个 controller，state 内部管理：

```kotlin
AnimatedContainer(

    vsync = vsync,
    width = if (expanded) 80 else 20,
    height = 16,
    borderColor = if (expanded) PixelColor.fromRgb(255, 200, 0) else PixelColor.White,
    padding = EdgeInsets.all(if (expanded) 4 else 2),
)
```

支持属性：`width` / `height` / `padding` / `margin` / `borderColor`。属性为 `null` 时跳过插值。

### `AnimatedOpacity`

在三档阈值之间过渡。`0.5` 档会通过 `Opacity` 走真实 alpha blend。

```kotlin

    child = myWidget,
```

量化规则：`opacity < 0.25 → 0`；`0.25..0.75 → 0.5`；`> 0.75 → 1`。

### `Opacity`

### `AnimatedBuilder`

性能取向的动画订阅 widget——把不变的子树通过 `child` 参数静态传入，builder
只负责构造"包住 child 的会变的部分"。

```kotlin

    animation = controller,
    child = Text("HELLO"),
) { _, child ->
    Padding(all = (controller.value * 8).toInt(), child = child!!)
}
```

与 `ListenableBuilder` 对比：

- `ListenableBuilder` 每次 listener 触发都让 builder 重建整棵子树。
- `AnimatedBuilder` 把 `child` 在外层只构造一次，按引用传给 builder；
  child 子树在 Element 层按 `===` reconcile，整体复用。

[`animation`] 类型放宽到任意 [`Listenable`]，与 `ListenableBuilder` 对齐——
名字沿用 Flutter `AnimatedBuilder` 习惯，配合 `PixelAnimationController`
（也是 `ChangeNotifier`）即可。

### `AnimatedSprite`

会抛 `IllegalArgumentException`。

```kotlin

    fps = 8,
    loop = true,
    playing = true,
    vsync = tickerProvider,
)
```

- `loop = true`：到末帧后回到首帧。
- `loop = false`：到末帧后停在末帧。
- `playing = false`：保持当前 frame，不推进 ticker。

### `PixelTickerProvider.createTicker(maxFps = …)`

像素引擎专属：把单个 ticker 限制在 N FPS，drop 中间帧。

```kotlin
val ticker = provider.createTicker(maxFps = 15) { elapsedNanos ->
    // 每秒最多 15 次（不强制等间距，但保证最低间隔）
}
```

- `maxFps == null`（默认）：每个 vsync 都派发。
- `maxFps > 0`：只有距上次派发 ≥ `1_000_000_000 / maxFps` 纳秒时才派发，
  中间帧丢弃。
- `elapsedNanos` 仍是 ticker 启动起累积的真实时间——`PixelAnimationController`
  使用低 FPS ticker 时，0→1 的步数 ≈ `duration × maxFps`，符合像素风
  离散感取向。
