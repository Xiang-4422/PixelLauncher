# pixel-engine 架构与技术实现

## 统一产物

pixel-engine 是单一 Android Library 和单一 Maven 坐标。内部仍按职责分层，但不再使用多个 Gradle 模块、兄弟 AAR 或传递的内部坐标。这样可以降低同步、依赖校验、发布和消费者排错成本。

统一产物不等于取消边界：package、Kotlin `internal`、稳定 API 标记、API/ABI baseline、isolated consumer 和产物预算共同约束实现。

## Retained tree

引擎的 UI 生命周期分为三层：

- Widget：不可变配置和子树描述。
- Element：挂载、更新、Inherited 依赖、State 和 owner 关系。
- RenderObject：约束布局、绘制、命中测试与 semantics。

更新时优先复用 Element 与 RenderObject，只把真实变化传播到布局或绘制阶段。自定义渲染通过 `com.purride.pixelui.advanced` 的公开 SPI 实现，不需要引用 internal 包。

## 帧与动画

生产 Host 使用 `ChoreographerFrameScheduler`，测试可注入 `ManualFrameScheduler`。动画对象必须支持取消和 dispose；Host detach 暂停帧推进，owner destroy 才执行终态释放。

## Android Host

`createPixelHostSetup` 统一创建 `PixelHostView`、文本输入桥和根容器，并连接：

- Lifecycle 与帧暂停/恢复。
- 触摸、键盘、焦点和 IME。
- WindowInsets、density 与 configuration。
- Accessibility semantics。
- Back dispatcher 与 overlay/navigation 消费顺序。

Activity 在 `onDestroy`、Fragment 在 `onDestroyView` 调用 `dispose()`。

## 主题与组件

主题由语义 token、motion token 和组件状态集合组成。标准组件读取主题并允许显式覆盖。组件实现不得依赖 Launcher 业务类型，产品视觉应由 `app` 注入。

## 路由与恢复

导航使用 typed destination、request、entry 和 outcome。Snapshot adapter 带版本，恢复必须先验证再提交，失败时保持旧状态。Overlay、子导航和宿主 Back 形成明确的消费链。

## 文本、资源与国际化

公开文本 offset 与 Android 保持 UTF-16 语义，内部编辑、selection、caret 和 hit test 对齐 Unicode grapheme。字体、bitmap、sprite 和 manifest 资源通过有界 cache 管理，资源 owner 负责释放。

## 测试与兼容

- JVM 测试覆盖布局、绘制、状态、路由和测试 DSL。
- instrumentation 覆盖真实 Android Host。
- Kotlin API、JVM ABI 和 Metalava baseline 保护稳定面。
- 隔离 Maven consumer 覆盖 R8、Java/Kotlin 调用、自定义 SPI 与旧二进制。
- 发布工具检查 AAR 内容、POM、metadata、依赖锁、SBOM 和签名。

## Compose 与性能

Compose wrapper 当前不属于 SDK，避免 Compose compiler 污染核心 ABI。性能 benchmark 与设备 soak 也已移出主工程；未来应在独立目标中基于明确设备和场景重新建立。
