# pixel-engine 高级基础组件计划

本文把可对开发者开放的高级基础组件固化为实施计划。目标不是复制 Material / Cupertino，
而是给 Android-only 像素 UI SDK 提供足够完整的底层 UI 组合能力。

## 1. 纳入原则

- 能跨业务复用，且不绑定 Launcher 产品模型。
- 状态由调用方持有，组件只负责像素布局、输入和回调。
- 优先复用现有 `Widget`、`PixelOverlay`、`MediaQuery`、controller、animation 和 testing 能力。
- 新 public API 必须同步 KDoc、API baseline、手册、demo 和测试。
- 一项组件能力完成后单独提交，不把多个组件堆成一个提交。

## 2. 第一批：低基础设施成本

这些组件只需要组合现有能力，优先实现。

| 组件 | SDK 价值 | 最小 API 边界 |
|---|---|---|
| `Visibility` | 受控显示 / 隐藏，减少业务层重复 `if` | `visible`、`child`、可选 `replacement` |
| `LoadStateView` | 统一 loading / empty / error / content | 接收状态枚举或 sealed state；不负责发请求 |
| `SelectionList` | 设置项、单选列表、枚举选择通用 | `items`、`selectedIndex`、`onSelected`、item label |
| `OptionList` | `SelectionList` 的轻量字符串版本 | `options`、`selectedIndex`、`onSelected` |
| `ValueAdjuster` | 像素屏上比 slider 更适合离散调值 | `valueText`、`onDecrease`、`onIncrease`、enabled |
| `Stepper` | 数字范围加减 | `value`、`range`、`step`、`onChanged` |
| `SectionList` | 分组列表基础能力 | sections + rows；复用 `ListView`，不做虚拟化新系统 |

## 3. 第二批：复用现有宿主能力

这些组件需要明确 Android host / overlay / insets 边界，但不需要重写框架。

| 组件 | SDK 价值 | 最小 API 边界 |
|---|---|---|
| `ImeAvoidingView` | 输入框页面避开 Android IME | 基于 `MediaQuery.viewInsets` 增加 padding |
| `KeyboardAvoidingView` | `ImeAvoidingView` 的开发者友好别名 | Android-only 文档说明 |
| `ModalBarrier` | dialog / menu / popover 的最小遮罩基础 | 拦截点击、可选 dismiss、颜色 |
| `ToastQueue` / `SnackbarQueue` | 多条通知顺序显示 | FIFO、Host active-time timeout、取消清理和一次性 action |
| `BottomSheet` | SafeArea/IME 内的贴底操作表面 | 与 Dialog 共用安全裁切和 modal 策略 |
| `SwipeRefreshScaffold` | 组合 refresh indicator 和列表内容 | 复用现有 refresh controller，不新增手势系统 |

## 4. 第三批：动画和焦点增强

这些组件要依赖现有 animation / focus，不新建复杂 DSL。

| 组件 | SDK 价值 | 最小 API 边界 |
|---|---|---|
| `AnimatedVisibility` | 出现 / 消失状态切换 | fade 或 size 二选一先落地；不做任意 transition DSL |
| `FocusTraversalGroup` | 键盘 / 手柄导航基础 | 只定义局部分组和顺序，复杂策略后置 |
| `ShortcutHint` | 展示快捷键 / 手柄提示 | 先做静态展示组件；快捷键注册模型后续补 |

## 5. 第四批：锚点浮层能力

这些组件已建立 root portal、统一 overlay stacking、Back、外点关闭和边缘避让底层支撑；
业务组合继续复用这些契约，不另建平行浮层系统。

| 组件 | SDK 价值 | 最小 API 边界 |
|---|---|---|
| `Popover` | 锚点浮层基础 | anchor rect / alignment / child / dismiss |
| `Menu` | 操作菜单和更多操作 | item label、enabled、onSelected，不做嵌套菜单 |
| `Dropdown` | 表单选择入口 | 复用 `Menu`，不单独实现浮层系统 |
| `Tooltip` | 焦点 / 长按说明 | 复用 `Popover`，不支持 hover-only 语义 |

## 6. 不进入核心 engine 的组件

以下组件暂不作为 `pixel-engine` 核心 SDK 基础组件：

- `DatePicker`
- `TimePicker`
- `CommandPalette`

原因：它们更像业务模式或产品级复杂组件。等 engine 的 `Menu`、`Popover`、`SelectionList`、
焦点和键盘能力稳定后，可以作为独立扩展或 demo 组合实现。

## 7. 实施顺序

1. 先实现第一批低成本组件，并更新 API 手册、demo、baseline 和测试。
2. 再实现 `ImeAvoidingView` / `KeyboardAvoidingView` / `ModalBarrier`，为浮层类组件打底。
3. 再实现 `AnimatedVisibility` / `FocusTraversalGroup` / `ShortcutHint`。
4. 最后实现 `Popover` / `Menu` / `Dropdown` / `Tooltip`。
5. 每完成一个组件或强相关组件组，运行 `tools/pixel-release-check.sh` 并单独提交。

## 8. 验收标准

- public / binary API baseline 只出现预期新增项。
- 每个组件至少有一个 `PixelTester` 单测。
- `app` 至少集成第一批和浮层类组件的真实用法，或由 SDK 文档提供可编译示例。
- `pixel-engine/docs/使用说明与API手册.md` 覆盖所有 public 组件。
- `tools/pixel-release-check.sh` 通过。
