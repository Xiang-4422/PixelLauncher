# pixel-engine 长期规划

本文描述 pixel-engine 的最终形态、长期边界和阶段任务。当前定位是 Android-first 的像素 UI SDK，不复刻 Flutter 全 API，也不引入 Material / Cupertino 组件库。

## 1. 最终形态

pixel-engine 最终应成为一个可独立发布、可长期维护的 Android 像素 UI 引擎：

- app 负责业务状态、权限、数据源和 Android Activity / Fragment 接线。
- pixel-engine 负责 widget tree、layout、render、input、focus、navigation、animation、testing 和 diagnostics。
- 视觉风格由像素组件和 `PixelTheme` 表达，不使用 Material / Cupertino 设计体系。
- 发布产物是 Maven artifact：`com.purride:pixel-engine:x.y.z`。
- SDK 用户可以写业务 UI、测试 UI、定位问题、升级版本，而不是依赖源码细节。

## 2. 长期边界

### 做

- Android-only host adapter。
- Flutter-like framework 基础能力：widget、state、inherited、focus、semantics、navigation、animation。
- 像素风组件和像素默认样式。
- SDK consumer smoke、API baseline、binary baseline、KDoc 门禁。
- 测试工具、诊断工具和错误边界。

### 不做

- 不做 Material / Cupertino 组件库。
- 不追 Flutter 全 API。
- 不做跨平台。
- 不做复杂设计系统生成器。
- 不为了“完整”添加组件；组件必须服务真实像素 UI 场景。

## 3. 阶段路线

### 阶段 1：0.x 基础 SDK 稳定

目标：内部使用不容易踩坑，SDK 用户出错时能定位问题。

- [ ] `PixelErrorBoundary`
  - [x] 捕获 build 层异常。
  - [x] 支持像素错误面板。
  - [x] 支持错误回调。
  - [ ] 捕获 render 层异常。
- [ ] SDK 可用的 `PixelTester`
  - `pumpWidget`
  - tap / drag / key / enterText
  - text / semantics 查询
  - pixel buffer / golden 断言
- [ ] 最小 `PixelOverlay`
  - `PixelOverlayHost`
  - `showToast`
  - `showDialog`
  - `showSnackbar`
- [ ] 继续完善 `PixelTheme`
  - 只扩展到不改变元素树的组件。
  - 后续控件重构时顺手接入，不为了 theme 强插 wrapper。
- [ ] Android host contract 梳理
  - back
  - IME
  - clipboard
  - haptic
  - saved state
  - lifecycle
  - window insets

### 阶段 2：Android 宿主能力成型

目标：pixel-engine 像 Android SDK，而不是单纯绘图库。

- [ ] Back handling
  - navigator pop
  - overlay dismiss
  - text input blur
  - app fallback
- [ ] Saved state
  - navigator stack
  - list / page scroll
  - text field state
  - route-local storage
- [ ] Android accessibility bridge
  - 复用现有 semantics tree。
  - 接 Android 无障碍节点。
- [ ] 输入法稳定化
  - selection / composition
  - next / done / search action
  - focus traversal
  - clipboard edit actions
- [ ] Activity / Fragment 接入文档
  - 最小 Activity
  - lifecycle 注意点
  - saved state 示例

### 阶段 3：像素组件体系

目标：形成自己的像素风组件，而不是 Material 替代品。

- [ ] `OutlinedButton`

- [ ] `ListTile`

- [ ] `Switch`

- [ ] `Toast`
- [ ] `Snackbar`
- [ ] `ProgressBar`

后续按真实需求补：

- [ ] `Menu`

- [ ] `EmptyState`
- [ ] `ErrorPanel`

### 阶段 4：渲染和性能长期打磨

目标：稳定跑在低分辨率像素屏、Launcher 场景和长时间运行场景。

- [ ] 明确 frame pipeline
  - build
  - layout
  - paint
  - submit
- [ ] 优化 buffer 复用和 allocation。
- [ ] 保留 perf smoke。
- [ ] 增加长期 soak test。
- [ ] 建立 perf baseline
  - list scroll
  - text input
  - animation
  - page transition
  - overlay
- [ ] 仅在真实瓶颈出现后引入 dirty region / partial repaint。

### 阶段 5：资源体系

目标：字体、sprite、bitmap 资源能被 SDK 用户稳定消费。

- [ ] resource manifest 文档稳定。
- [ ] 字体包加载和 fallback 策略稳定。
- [ ] sprite sheet schema 稳定。
- [ ] resource cache 行为明确
  - key
  - clear
  - snapshot
  - memory 边界
- [ ] 资源打包工具说明。

### 阶段 6：发布和兼容策略

目标：从内部 0.x 走到可长期维护的 1.0。

0.x：

- [ ] source / binary compatibility best-effort。
- [ ] breaking change 必须写入 changelog。
- [ ] public / binary API baseline 必须同步更新。
- [ ] release gate 必须全绿。

1.0 前必须完成：

- [ ] public API 分层干净。
- [ ] internal 类型不进入 baseline。
- [ ] SDK 文档覆盖主流程。
- [ ] consumer smoke 稳定。
- [ ] testing API 可用。
- [ ] Android host contract 稳定。
- [ ] 错误边界和诊断可用。

1.0 后：

- [ ] 遵循 SemVer。
- [ ] public API 不随意破坏。
- [ ] deprecate 至少保留一个 minor 周期。
- [ ] migration guide 必须跟 release 一起出。

## 4. 长期目录边界

- `pixelcore`
  - buffer、color、font、bitmap、sprite、resource、低层动画。
- `pixelui.foundation`
  - widget、state、inherited、focus、semantics、form、async。
- `pixelui.widgets`
  - 像素组件。
- `pixelui.state`
  - list / page / text / refresh controllers。
- `pixelui.host`
  - Android host bridge、frame loop、input bridge。
- `pixelui.testing`
  - SDK 测试工具。
- `pixelui.internal`
  - retained tree、render pipeline、Android helper、实现细节。

## 5. 当前推荐下一步

先做 `PixelErrorBoundary`。它是 SDK 安全垫，成本小，收益高于继续扩控件。完成后再做 `PixelTester` 发布化，最后做最小 `PixelOverlay`。
