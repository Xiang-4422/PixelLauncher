# pixel-engine 长期规划

本文描述 pixel-engine 的最终形态、长期边界和阶段任务。当前定位是 Android-first 的像素 UI SDK，不复刻 Flutter 全 API，也不引入 Material / Cupertino 组件库。

> M0-M8 的实现与行为验收已完成；M9 发布工程仍以 [`1.0-GOAL.md`](1.0-GOAL.md) 为唯一状态源。
> 本文保留历史阶段用于解释能力来源，正式发布剩余项以 [1.0 发布清单](1.0.0发布清单.md) 为准。

## 1. 最终形态

pixel-engine 最终应成为一个可独立发布、可长期维护的 Android 像素 UI 引擎：

- app 负责业务状态、权限、数据源和 Android Activity / Fragment 接线。
- pixel-engine 负责 widget tree、layout、render、input、focus、navigation、animation、testing 和 diagnostics。
- 视觉风格由像素组件和 `PixelTheme` 表达，不使用 Material / Cupertino 设计体系。
- 发布产物是 Maven artifact：`com.purride:pixel-engine:x.y.z`。
- SDK 用户可以写业务 UI、测试 UI、定位问题、升级版本，而不是依赖源码细节。

## 2. 长期边界

### 做

- Android-only host adapter。
- Flutter-like framework 基础能力：widget、state、inherited、focus、semantics、navigation、animation。
- 像素风组件和像素默认样式。
- SDK consumer smoke、API baseline、binary baseline、KDoc 门禁。
- 测试工具、诊断工具和错误边界。
- 面向开发者的高级基础组件，具体计划见 `pixel-engine/docs/高级基础组件计划.md`。

### 不做

- 不做 Material / Cupertino 组件库。
- 不追 Flutter 全 API。
- 不做跨平台。
- 不做复杂设计系统生成器。
- 不为了“完整”添加组件；组件必须服务真实像素 UI 场景。

### 阶段 4：渲染和性能长期打磨

目标：稳定跑在低分辨率像素屏、Launcher 场景和长时间运行场景。

当前已具备完整帧阶段诊断、Macro/Microbenchmark、Baseline Profile、API 37 模拟器 30 分钟长跑、
10,000 次生命周期压力和有界 heap 证据；模拟器结果仍不代表 60/120Hz 设备帧时间已经验收。
以下工作统一由 `1.0-GOAL.md` 的 M6 执行：

- [x] build/layout/paint/submit/Android draw 分阶段指标。
- [x] Macrobenchmark、Microbenchmark、Baseline Profile 和设备回归阈值工具。
- [x] 30–60 分钟 soak、10,000 次导航/Host 生命周期和有界 heap 证明。
- [x] 以 trace 证明后再决定逐像素提交、dirty region 或 partial repaint 优化。
- [ ] 在代表性 60/120Hz 设备上批准基线并通过 p95/p99/jank/回退阈值。

### 阶段 6：发布和兼容策略

目标：从内部 0.x 走到可长期维护的 1.0。

0.x：

- [x] source / binary compatibility best-effort。
- [x] breaking change 必须写入 changelog。
- [x] public / binary API baseline 必须同步更新。
- [x] release gate 必须全绿。

1.0 前必须完成：

- [ ] public API 分层干净。
- [ ] internal 类型不进入稳定 API 或兼容承诺。
- [ ] SDK 文档覆盖主流程并进入严格文档站门禁。
- [ ] consumer compatibility matrix 稳定。
- [ ] testing API 从最小 runtime artifact 分离且可用。
- [ ] Android host、生命周期、无障碍和状态恢复契约稳定。
- [ ] 错误边界、结构化错误报告和诊断可用。

具体实现和验收证据全部见 `pixel-engine/docs/1.0-GOAL.md`，不得根据本节条目名称直接勾选。

1.0 后：

- [ ] 遵循 SemVer。
- [ ] public API 不随意破坏。
- [ ] deprecate 至少保留一个 minor 周期。
- [ ] migration guide 必须跟 release 一起出。
  - [x] 规则固化在 `pixel-engine/docs/发布与兼容策略.md`。
  - [x] migration guide 模板固化在 `pixel-engine/docs/migrations/TEMPLATE.md`。

## 4. 长期目录边界

- `pixelcore`
  - buffer、color、font、bitmap、sprite、resource、低层动画。
- `pixelui.foundation`
  - widget、state、inherited、focus、semantics、form、async。
- `pixelui.widgets`
  - 像素组件。
- `pixelui.state`
  - list / page / text / refresh controllers。
- `pixelui.host`
  - Android host bridge、frame loop、input bridge。
- `pixelui.testing`
  - SDK 测试工具。
- `pixelui.internal`
  - retained tree、render pipeline、Android helper、实现细节。

下一步按 `pixel-engine/docs/1.0-GOAL.md` 从 M0 安全与真实基线开始，先完成依赖项再扩展组件。
