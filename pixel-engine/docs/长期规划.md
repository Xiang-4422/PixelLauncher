# pixel-engine 长期规划

本文描述 pixel-engine 的最终形态、长期边界和阶段任务。当前定位是 Android-first 的像素 UI SDK，不复刻 Flutter 全 API，也不引入 Material / Cupertino 组件库。

## 1. 最终形态

pixel-engine 最终应成为一个可独立发布、可长期维护的 Android 像素 UI 引擎：

- app 负责业务状态、权限、数据源和 Android Activity / Fragment 接线。
- pixel-engine 负责 widget tree、layout、render、input、focus、navigation、animation、testing 和 diagnostics。
- 视觉风格由像素组件和 `PixelTheme` 表达，不使用 Material / Cupertino 设计体系。
- 发布产物是 Maven artifact：`com.purride:pixel-engine:x.y.z`。
- SDK 用户可以写业务 UI、测试 UI、定位问题、升级版本，而不是依赖源码细节。

## 2. 长期边界

### 做

- Android-only host adapter。
- Flutter-like framework 基础能力：widget、state、inherited、focus、semantics、navigation、animation。
- 像素风组件和像素默认样式。
- SDK consumer smoke、API baseline、binary baseline、KDoc 门禁。
- 测试工具、诊断工具和错误边界。

### 不做

- 不做 Material / Cupertino 组件库。
- 不追 Flutter 全 API。
- 不做跨平台。
- 不做复杂设计系统生成器。
- 不为了“完整”添加组件；组件必须服务真实像素 UI 场景。

### 阶段 6：发布和兼容策略

目标：从内部 0.x 走到可长期维护的 1.0。

0.x：

- [ ] source / binary compatibility best-effort。
- [ ] breaking change 必须写入 changelog。
- [ ] public / binary API baseline 必须同步更新。
- [ ] release gate 必须全绿。

1.0 前必须完成：

- [ ] public API 分层干净。
- [ ] internal 类型不进入 baseline。
- [ ] SDK 文档覆盖主流程。
- [ ] consumer smoke 稳定。
- [ ] testing API 可用。
- [ ] Android host contract 稳定。
- [ ] 错误边界和诊断可用。

1.0 后：

- [ ] 遵循 SemVer。
- [ ] public API 不随意破坏。
- [ ] deprecate 至少保留一个 minor 周期。
- [ ] migration guide 必须跟 release 一起出。

## 4. 长期目录边界

- `pixelcore`
  - buffer、color、font、bitmap、sprite、resource、低层动画。
- `pixelui.foundation`
  - widget、state、inherited、focus、semantics、form、async。
- `pixelui.widgets`
  - 像素组件。
- `pixelui.state`
  - list / page / text / refresh controllers。
- `pixelui.host`
  - Android host bridge、frame loop、input bridge。
- `pixelui.testing`
  - SDK 测试工具。
- `pixelui.internal`
  - retained tree、render pipeline、Android helper、实现细节。
