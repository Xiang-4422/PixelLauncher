# 文本系统 v2 设计

## Summary

当前 `Text`、`RichText`、多行 `TextField`、ellipsis 已可用，但测量、断行和绘制语义还分散在不同 render object 中。v2 目标是建立 internal paragraph model，统一文本布局结果，再逐步扩展样式和输入体验。

## Public API

第一阶段不新增页面层 API，只重构 internal：

- `Text(...)`、`RichText(...)`、`TextField(...)` 调用保持源码兼容。
- `PixelTextStyle` 暂不扩字段，避免把 paragraph 重构和样式扩展混在一起。

第二阶段再兼容新增：

```kotlin
letterSpacing: Int = 0
lineHeight: Int? = null
fontScale: Int = 1
```

`fontScale` 只支持正整数，非整数缩放不进入本阶段。

## Internal Model

新增 internal paragraph 层：

- `PixelParagraphInput`：文本、spans、style、maxLines、overflow、softWrap、textAlign、direction。
- `PixelParagraphLine`：一行内的 glyph run、宽度、高度、baseline、ellipsis 状态。
- `PixelParagraphLayout`：完整布局结果，供 layout / paint / diagnostics 复用。
- `PixelParagraphLayouter`：统一断行、CJK/英文混排、显式换行、空行和 ellipsis。

`RenderText` 和 `RenderRichText` 都只负责把 widget 参数转换为 paragraph input，并消费 paragraph layout。

## Rendering Semantics

- 显式换行必须创建新 line，连续换行保留空行。
- `maxLines` 限制最终可见行数。
- `overflow = ELLIPSIS` 只在最后可见行追加 ellipsis。
- span 样式切换不能破坏字符级换行。
- `textAlign` 在 paragraph line 层统一处理。
- `TextField` placeholder 和实际文本使用同一 paragraph layout。

## Compatibility

- 默认 `letterSpacing = 0`、`lineHeight = null`、`fontScale = 1` 时输出应与当前 golden/snapshot 一致。
- 不做 selection handle、composition underline、复杂字体 fallback。
- 不改变宿主 `PixelTextInputRequest` 的现有单行/多行默认行为。

## Test Plan

- CJK/英文混排、显式换行、空行、窄宽度 ellipsis。
- `Text` 与 `RichText` 在相同文本下生成一致 line metrics。
- span 跨行、不同 tone/style 切换、`maxLines` + ellipsis。
- `TextField` placeholder、单行、多行输入复用 paragraph layout。
- 更新或新增 golden / element snapshot，覆盖 v2 paragraph 输出。
